# Конвейер: архитектура

Как идея превращается в результат. Один артефакт на этап, один источник
правды на сущность, стадия выводится из файлов, а не проставляется руками.

**Общая картина — в `docs/PLAY.md`**: что такое PLAY, кто за что отвечает,
восемь шагов от идеи до реакции игроков. Этот документ — тот же путь на
уровне файлов: какой артефакт на выходе каждого шага, какие ворота его
пропускают и что из этого уже построено.

Где два документа расходятся, прав `PLAY.md`. Известные расхождения названы
в конце, в разделе «Расхождения с PLAY.md».

Это целевая архитектура. Что из неё уже есть и в каком порядке двигаться —
в разделе «Миграция» в конце.

---

## Принципы

**Один артефакт на этап.** У каждого этапа ровно один выходной файл. Нет
файла — этап не пройден. Это и есть трекер: не нужна отдельная таблица со
статусами, потому что статус — это наличие файла.

**Стадия выводится, а не хранится.** Никто не пишет `status: built` руками.
Стадия вычисляется из того, какие артефакты существуют. Руками хранится
только то, что нельзя вывести: расписание (какая игра в какой день) и
вердикт (решение человека).

**Шапка для конвейера, проза для человека.** Каждый markdown-документ
начинается с YAML-шапки. Шапку читают скрипты, прозу — человек и AI.
Никакое поле не живёт в двух местах.

**Один слаг на игру, решается один раз.** Слаг придумывается на этапе IDEA
и дальше не меняется нигде: имя файла идеи, имя файла спеки, папка игры,
имя файла данных, имя файла результата, URL на хабе.

## Дерево

```
trends/YYYY-MM-DD-тема.md      наблюдения по рынку           ← пишет человек
ideas/active/NN-slug.md        идея + оценка + Gate 1        ← человек, оценка AI
ideas/rejected/NN-slug.md      не прошла Gate 1
specs/NN-slug.md               спека + Gate 2                ← AI, принимает человек
app/games/<slug>/              код игры                      ← AI по спеке
app/games/<slug>/review.md     Gate 4: человек играл         ← человек
app/games/<slug>/media/        обложка, баннер, кадр, ролик, тексты
data/<slug>.json               воронка из PostHog            ← скрипт
results/NN-slug.md             метрики + вердикт             ← AI, утверждает человек
results/PROMOTED.md            индекс победителей            ← генерируется

g/<slug>/                      опубликованная сборка         ← release.mjs
g/assets/                      общие хешированные бандлы

games.json                     реестр: день → слаг, статус, ссылки, даты
distribution/                  каналы, шаблоны, прогрев, генератор CSV
docs/templates/                шаблоны идеи, ручной проверки, медиа
docs/                          PLAY.md, архитектура, решения

specs/front-matter.mjs         чтение YAML-шапок — общее для всех скриптов
specs/validate.mjs             Gate 2 и сверка шапок с идеями
ideas/validate.mjs             Gate 1
pipeline.mjs                   доска: стадии и что ждёт человека
release.mjs                    публикация одной игры на хаб
build-games.mjs                генератор хаба
.github/workflows/ci.yml       Gate 3
```

`NN` — номер концепта, а не день. Концепт 23 может выйти в день 5. Связь
«день → слаг» живёт только в `games.json`.

## Этапы

Описаны в `docs/PLAY.md` — восемь шагов и четверо ворот, кто за что отвечает.
Здесь не повторяются: два описания одного конвейера разойдутся, вопрос
времени.

Что относится к файлам и чего в `PLAY.md` нет:

| Шаг | Артефакт | Проверка |
|---|---|---|
| Тренды | `trends/YYYY-MM-DD-тема.md` | — |
| Идея | `ideas/active/NN-slug.md` | `node ideas/validate.mjs` |
| Gate 1 | раздел «Оценка» + `gate1` в шапке | там же: порог и `approved` вопреки цифрам |
| Спека | `specs/NN-slug.md` | `node specs/validate.mjs` |
| Gate 2 | `review` в шапке спеки | там же |
| Сборка | `app/games/<slug>/` | `npm run check` |
| Gate 3 | зелёный прогон CI | `.github/workflows/ci.yml` |
| Gate 4 | `app/games/<slug>/review.md` | `release.mjs` не публикует без `approved` |
| Медиа | `app/games/<slug>/media/` | — |
| Релиз | `g/<slug>/` + `links.play` | `node release.mjs <slug>` |
| Дистрибуция | `distribution/publer-posts.csv` | `node distribution/build-posts.mjs` |
| Цифры | `data/<slug>.json` | — |
| Вердикт | `results/NN-slug.md` | — |

Шаблоны: `docs/templates/idea.md`, `specs/_TEMPLATE.md`,
`docs/templates/review.md`, `docs/templates/media.md`. Форматы `data/` и
`results/` — в README этих папок.

## Стадия выводится

Никакого поля `status`, которое надо не забыть поменять. Стадия — это функция
от файлов:

| Стадия | Признак |
|---|---|
| `идея` | есть `ideas/active/NN-slug.md` |
| `отклонена` | файл в `ideas/rejected/` |
| `спека` | есть `specs/NN-slug.md`; `review` говорит, принята ли |
| `собрана` | есть `app/games/<slug>/game.config.ts` |
| `принята` | в `app/games/<slug>/review.md` стоит `approved` |
| `опубликована` | в `games.json` заполнен `links.play` |
| `цифры` | есть `data/<slug>.json` |
| `вердикт` | есть `results/NN-slug.md` с непустым `verdict` |

```sh
node pipeline.mjs            # доска целиком
node pipeline.mjs --waiting  # только то, что ждёт решения человека
node pipeline.mjs --json     # то же машиночитаемо
```

```
PLAY · 2026-09-20 · старт 2026-10-01, через 11 дн.

  день  слаг             стадия
    1  box-arrives      спека
    2  two-moves-later  спека
   ...
  вне расписания
  #36  arrow-flip       идея           25/30

Ждёт тебя: 1
  • arrow-flip (#36) — gate 1 — твоё решение
```

Это и заменяет гугл-трекер: колонки «собрана / протестирована / опубликована»
перестают быть чек-боксами, которые надо ставить руками. Поставить их и
забыть невозможно, потому что ставить нечего.

Главная колонка — **«Ждёт тебя»**. Три из четырёх ворот — решение человека, и
ровно они теряются первыми. `--waiting` отвечает на единственный вопрос,
который задают утром: за что браться.

## Восемь команд

Каждая — один переход, файл на входе, файл на выходе.

| Команда | Вход | Выход | Кто |
|---|---|---|---|
| `/idea` | разговор | `ideas/NN-slug.md` | человек + AI |
| `/spec` | идея | `specs/NN-slug.md` | AI |
| `/build` | спека | `app/games/<slug>/` | AI |
| `/verify` | код | зелёный прогон | CI |
| `/release` | зелёная сборка | сайт + `games.json` | скрипт |
| `/distribute` | реестр + тексты | CSV | скрипт |
| `/pull-data` | опубликованная игра | `data/<slug>.json` | скрипт |
| `/result` | данные + критерий | `results/NN-slug.md` | AI + человек |

Четыре средних — `build`, `verify`, `release`, `distribute` — должны быть
полностью автоматическими. `idea` требует человека по существу. `result`
требует его согласия с вердиктом.
