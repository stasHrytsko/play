# PLAY — правила работы в этом репозитории

Конвейер целиком описан в `docs/PLAY.md`. Это канонический документ: где
что-то расходится с ним, прав он.

---

## Правило №1 — доска не отстаёт от репозитория

**Любое изменение, которое двигает что-то по конвейеру, попадает на доску в
том же коммите.** Не следующим, не «потом соберём» — в том же.

```sh
node pipeline.mjs --write    # перед каждым коммитом, который что-то сдвинул
```

Что считается движением:

- заведена, оценена, одобрена или отклонена идея; файл переехал между
  `ideas/active/` и `ideas/rejected/`;
- появилась или принята спека (`review` в шапке);
- собрана игра, появился или изменился `app/games/<slug>/review.md`;
- игра опубликована — заполнен `links.play` в `games.json`;
- переставлено расписание день → слаг;
- снята выгрузка в `data/`, вынесен вердикт в `results/`;
- добавлено наблюдение в `trends/`.

**Почему это правило, а не пожелание.** Доска, которая показывает вчерашнее
состояние и выглядит при этом свежей, — худший способ сломаться: ей верят и
по ней принимают решения. Пустая доска честнее отставшей.

**Как это не держится на памяти.** Три слоя, и ни один не про дисциплину:

1. Стадии нигде не хранятся — они считаются из того, какие файлы есть. Нет
   поля `status`, которое можно забыть переставить; можно забыть только
   пересчитать снимок.
2. `git config core.hooksPath .githooks` — один раз на машине. Дальше
   pre-commit сам пересчитывает `dashboard/status.json` и добавляет его в
   коммит.
3. `node pipeline.mjs --check` в CI. Если снимок отстал — сборка красная.

Сверяется только то, что зависит от файлов. Дата и обратный отсчёт до старта
меняются сами, и сверять их значило бы ронять CI каждую ночь.

---

## Правило №2 — один источник правды на сущность

Ни одно значение не живёт в двух местах. Если оно нужно где-то ещё — его
читают, а не копируют.

| Сущность | Где живёт |
|---|---|
| Замысел, kill-критерий, оценка | шапка `ideas/active/NN-slug.md` |
| Название, питч, правила игры | `specs/NN-slug.md` (шапка наследует идею) |
| День выхода, ссылки, даты | `games.json` |
| Приёмка спеки | `review` в шапке спеки |
| Приёмка игры | `app/games/<slug>/review.md` |
| Тексты и медиа игры | `app/games/<slug>/media/` |
| Правила и шаблоны постов | `distribution/` |
| Цифры | `data/<slug>.json` |
| Вердикт | `results/NN-slug.md` |

Расхождение шапки спеки с шапкой идеи роняет `specs/validate.mjs`.

---

## Правило №3 — ворота не пропускаются

Четверо ворот, три из них — решение человека, и ровно они теряются первыми.
Поэтому каждое записано файлом, а не памятью:

| Ворота | Где записано | Кто держит |
|---|---|---|
| Gate 1 — идея | `gate1` + `score` в шапке идеи | `ideas/validate.mjs` |
| Gate 2 — спека | `review` в шапке спеки | `specs/validate.mjs` |
| Gate 3 — CI | зелёный прогон | `.github/workflows/ci.yml` |
| Gate 4 — человек играл | `app/games/<slug>/review.md` | `release.mjs` не публикует без `approved` |

AI ставит баллы и предлагает вердикты. **Решения — человека.** Скрипты не
решают за него: они ловят решение, противоречащее собственным цифрам.

---

## Проверки перед коммитом

```sh
node pipeline.mjs --write     # обновить доску
node specs/validate.mjs       # спеки и сверка с идеями
node ideas/validate.mjs       # Gate 1
node test-hub.mjs             # поведение хаба
node build-games.mjs          # перерисовать страницы из games.json
```

Всё это же гоняет CI. Ошибка роняет сборку, предупреждение — нет.
