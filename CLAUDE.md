# PLAY — правила работы в этом репозитории

Конвейер целиком — `docs/PLAY.md`. Это канонический документ: где что-то
расходится с ним, прав он.

---

## Правило №1 — доска не отстаёт от репозитория

**Доска всегда показывает текущее состояние.** Держится это не на дисциплине,
а на том, что забывать нечего:

1. **Стадии нигде не хранятся.** Нет поля `status`, которое надо переставить
   руками. Стадия — функция от того, какие файлы существуют: есть идея, что
   стоит в `review` спеки, есть ли `game.config.ts`, сколько уровней в паке,
   подписан ли `review.md`, заполнен ли `links.play`, снята ли выгрузка, есть
   ли решение Gate 2. Двигая конвейер, ты уже обновил доску.
2. **Снимок коммитится, а забыть его не даёт CI.** `dashboard/status.json`
   лежит в репозитории — страница тогда работает на чистой статике, при любой
   настройке хостинга. `node pipeline.mjs --write` обновляет,
   `node pipeline.mjs --check` в CI роняет пуш, если забыл.
3. **Всё, что зависит от даты, страница считает сама, в браузере.** «Идёт
   12/30 дн.», «месяц вышел», «снять цифры» меняются без коммита, поэтому в
   снимок не запекаются. Окно отсчитывается **от даты публикации конкретной
   игры**, а не от общей даты старта.

**Почему это правило.** Доска, показывающая вчерашнее состояние и выглядящая
свежей, — худший способ сломаться: ей верят. **Пустая доска честнее
отставшей.**

**При изменениях.** Новый артефакт или стадия обязаны появиться в
`pipeline.mjs` — иначе доска молча врёт о полноте. Это единственное место,
где правило требует внимания.

```sh
node pipeline.mjs              # вживую, в терминале
node pipeline.mjs --waiting    # только то, что ждёт решения
node pipeline.mjs --write && (cd dashboard && python3 -m http.server 8077)
```

## Правило №2 — один источник правды на сущность

Ни одно значение не живёт в двух местах. Нужно где-то ещё — читают, а не
копируют.

| Сущность | Где живёт |
|---|---|
| Замысел, kill-критерий, оценка | шапка `ideas/active/NN-slug.md` |
| Название, питч, правила игры | `specs/NN-slug.md` (шапка наследует идею) |
| Макет экрана | `specs/screens/NN-slug.png`, §7.1 спеки |
| День выхода, ссылки, даты, адрес лаборатории | `games.json` |
| Приёмка спеки | `review` в шапке спеки |
| Проверка среза | `review` в шапке `app/games/<slug>/review.md` |
| Тексты и медиа игры | `app/games/<slug>/media/` |
| Правила и шаблоны постов | `distribution/` |
| Цифры | `data/<slug>.json` |
| Правило Gate 1 и Gate 2 | `ideas/gate1.md` и `results/gate2.md` — каждое рядом со своим решением |
| Результат Gate 2 | `gate2` в шапке `results/NN-slug.md` |

Расхождение шапки спеки с шапкой идеи роняет `specs/validate.mjs`.

### Дерево

```
trends/YYYY-MM-DD-тема.md      наблюдения по рынку           ← человек
ideas/gate1.md                 правило Gate 1 — оценка идеи
ideas/_TEMPLATE.md             шаблон идеи
ideas/active/NN-slug.md        идея + оценка + Gate 1        ← человек, оценка AI
ideas/rejected/NN-slug.md      не прошла Gate 1
specs/_TEMPLATE.md             нормативный шаблон спеки
specs/NN-slug.md               спека, приёмка человеком      ← AI пишет
specs/screens/NN-slug.png      макет экрана                  ← человек
app/                           фабрика: общий шелл и игры
app/games/_REVIEW.md           шаблон проверки среза
app/games/_MEDIA.md            шаблон медиа игры
app/games/<slug>/              код одной игры                ← AI по спеке
app/games/<slug>/review.md     проверка среза автором        ← человек
app/games/<slug>/media/        обложка, баннер, кадр, ролик, тексты
data/<slug>.json               воронка из PostHog            ← скрипт
results/gate2.md               правило Gate 2 — прототип на игроках
results/NN-slug.md             Gate 2: наблюдения и решение  ← AI считает, подписывает человек

games.json                     реестр: день → слаг, статус, ссылки, даты
g/<slug>/                      опубликованная сборка         ← release.mjs
app/public/                    robots.txt и заглушка лаборатории
distribution/                  каналы, шаблоны, прогрев (заморожено)
dashboard/                     доска страницей
docs/PLAY.md                   конвейер целиком — канон
docs/decisions.md              журнал решений проекта

specs/front-matter.mjs         чтение YAML-шапок — общее для скриптов
specs/validate.mjs             спеки и сверка шапок с идеями
ideas/validate.mjs             Gate 1
pipeline.mjs                   доска: стадии и что ждёт человека
release.mjs                    публикация одной игры на хаб
build-games.mjs                генератор хаба
test-hub.mjs                   поведение хаба
.github/workflows/ci.yml       CI
```

`NN` — номер концепта, а не день выхода. Связь «день → слаг» живёт только в
`games.json`.

## Правило №3 — ворота не пропускаются

**Двое ворот на концепт,** и оба решают, жить ли ему:

| Ворота | Правило | Где записано | Кто держит |
|---|---|---|---|
| Gate 1 — идея → прототип | `ideas/gate1.md` | `gate1` + `score` в шапке идеи | `ideas/validate.mjs` |
| Gate 2 — прототип → производство | `results/gate2.md` | `gate2` в шапке `results/NN-slug.md` | человек; доли считает AI |

Между ними три проверки, которые воротами не называются: человек принимает
спеку (`review` в её шапке), он же смотрит срез три минуты (`review` в
`app/games/<slug>/review.md`, без него `release.mjs` не публикует), и CI
гоняет тесты. Они решают «доделывать ли», а не «жить ли концепту».

Публикация отдельной подписи не требует: запуск `release.mjs` и есть решение
публиковать. Лишние ворота стоят круг ожидания на каждой из тридцати игр.

AI ставит баллы и предлагает вердикты. **Решения — человека.** Скрипты ловят
решение, противоречащее собственным цифрам.

Каждое ожидающее решение доска показывает с адресом: какой файл открыть, что
прочитать, куда записать ответ. Пункт без адреса откладывается, потому что
начинается с вопроса «а где это».

**Добавляя стадию или ворота, пропиши в `pipeline.mjs` и действие** — `open`,
`read`, `write`, при необходимости `run`. И **пропиши ветку «поля просто
нет»**: по пустой клетке нельзя отличить «сделано» от «не дошли руки».

**Очередь, а не свалка.** Приёмка нужна всем тридцати спекам, но игры делаются
по одной: в «ждёт тебя» попадает только ближайшая по расписанию. Список, в
который не смотрят, не лучше пустого.

## Правило №4 — машинерия после второго случая

Новое поле, ворота, раздел или скрипт заводятся, когда **дважды** сломалось
без них. Не после первого раза и тем более не заранее.

Причина записана в `docs/decisions.md` за 2026-09-21: правило про «убить»
написали умозрительно, и первый же настоящий kill его сломал — концепт
убивали там, где записать решение было негде. Дистрибуция сгенерировала 533
строки постов для игр, которых нет. Шесть тысяч строк прозы про конвейер при
нуле опубликованных игр.

Практически это значит: пока не вышли три игры, конвейер не меняется. Если
что-то мешает — записать в `docs/decisions.md` наблюдением, дождаться
второго такого же и только тогда чинить.

## Проверки перед коммитом

```sh
node pipeline.mjs --write            # снимок доски
node build-games.mjs                 # страницы хаба из games.json
node specs/validate.mjs              # спеки и сверка с идеями
node ideas/validate.mjs              # Gate 1
node test-hub.mjs                    # поведение хаба
```

Первые два — генераторы, их выход закоммичен, и CI проверяет совпадение с
источниками. Остальные — проверки: ошибка роняет сборку, предупреждение нет.

`node distribution/build-posts.mjs` заморожен до первой публикации, его выход
не коммитится.

**Сгенерированное руками не правят.** `index.html` и страницы игр,
`dashboard/status.json` — выход генераторов. Править надо источник:
`games.json`, шапку спеки, `posts.json`, `media/copy.md` игры.
