# dashboard/

Доска конвейера на экран. Отдельный статический проект — деплоится на Vercel
из этой папки, независимо от хаба.

```
dashboard/
  index.html     страница, без зависимостей и без сборки
  status.json    данные ← пишет pipeline.mjs
  vercel.json    статика, без build-команды
  favicon.svg
```

## Обновить

**Правило №1** (`CLAUDE.md`): доска всегда показывает текущее состояние.

```sh
node pipeline.mjs --write   # пересчитать status.json
node pipeline.mjs --check   # упасть, если он отстал (стоит в CI)
```

Забыть не даст CI: `--check` гоняется на каждом пуше и ничего не требует
включать руками. Сверяется только то, что зависит от файлов.

Отдельно от этого **всё, что зависит от даты, страница считает в браузере**:
«идёт 12/30 дн.», «месяц вышел», «снять цифры». Это меняется без коммита,
поэтому в снимок не запекается, и вкладка, висящая на экране неделю, не врёт
и без нового деплоя. Порог приезжает в данных из `pipeline.mjs`, чтобы
оставаться записанным в одном месте.

Окно отсчитывается **от даты публикации конкретной игры**. Общей даты старта
на доске нет: у каждого прототипа свои тридцать дней.

## Локально

```sh
cd dashboard && python3 -m http.server 8077
```

Файлом (`file://`) не откроется: страница читает `status.json` через `fetch`.

## Деплой на Vercel

Новый проект из того же репозитория. Сборки нет — папка отдаётся как есть:

| Настройка | Значение |
|---|---|
| Root Directory | `dashboard` |
| Framework Preset | Other |
| Build Command | пусто |
| Output Directory | пусто |
| Install Command | пусто |

`status.json` лежит в репозитории и приезжает с коммитом, поэтому страница
работает на чистой статике и не зависит ни от одной настройки сборки. Это
было выбрано сознательно: сборочная команда, читающая файлы выше Root
Directory, зависит от отдельного переключателя Vercel, и её поломка выглядит
как пустая страница, а не как красный деплой.

Проект хаба при этом не трогается.

**Закрой доступ.** Settings → Deployment Protection → Vercel Authentication
или пароль. Доска показывает внутреннюю кухню: какие идеи отклонены, что на
доработке, какие игры выйдут в какие дни.

Отдельно: корень репозитория отдаётся хабом `play.hrytsko.com` как есть,
поэтому `play.hrytsko.com/dashboard/` тоже откроется и покажет то же самое.
Убирается правилом на 404 для `/dashboard/*` в `vercel.json` проекта хаба.
Репозиторий публичный, так что секретом это в любом случае не было.

## Что на странице

Тёмная тема одна, светлой нет: доска рассчитана висеть на экране.

**Ждёт тебя** — единственная крупная цифра и список. Три из четырёх ворот —
твоё решение, и ровно они теряются первыми. Остальное на странице отвечает на
вопрос «как дела», этот блок — на вопрос «за что браться».

Каждый пункт несёт **ссылку на файл** (в GitHub, адрес берётся из git remote,
а не вписан руками), **что прочитать** и **куда записать решение** — поле в
шапке, раздел внизу файла или команда. Без этого «ждёт решения» — не задача, а
напоминание: непонятно, с чего начать, и пункт откладывается.

У пунктов, которые ждут не человека, стоит ярлык: `AI`, `скрипт`,
`ты запускаешь`. Поэтому подпись под цифрой — «ждёт действия», а не «ждёт
твоего решения»: часть работы не твоя.

**Всего** — плитки со счётчиками.

**Дошли хотя бы до стадии** — воронка. Накопленный счёт, а не доля от целого:
иначе ранние стадии выглядели бы достижением. Порядковая рампа в одной
тональности, проверена валидатором в светлой и тёмной моде.

**Таблицы** — тридцать прототипов по порядку выхода и концепты без
назначенного места. Колонка «Вышла» — дата публикации, «Состояние» — сколько
из тридцати дней прошло, цифры воронки или вердикт.

Стадии нигде не хранятся — считаются из того, какие файлы есть. Поэтому доску
нельзя забыть обновить: обновлять в ней нечего, только пересчитать.
