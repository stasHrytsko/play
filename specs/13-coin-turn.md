# 1. Паспорт концепта

- Название: Монета за поворот
- **Правило одной фразой:** Клади фигуры на поле; каждый поворот стоит монету, а монет на весь уровень только десять.
- Глагол: укладка
- Давление: дефицит ресурса
- Твист: Par — поворот фигуры является платным действием
- **Целевая эмоция:** скупость — «повернуть сейчас или сохранить монету на фигуру, без которой потом не обойтись?»
- **Уровни:** генерируется
- **Солвер:** не нужен
- Оценка: 25/30 — чит 4, мот 5, давл 3, payoff 3, произв 5, рынок 5

Дополнительно:
- Семейство: Block
- Отличие от аналога: Tetris — вращение обычно бесплатно, здесь каждое вращение расходует конечный ресурс.
- TREND: да
- Kill-критерий: если монеты стабильно заканчиваются в первой трети уровня и после этого решений про ресурс больше нет, концепт хоронится.

# 2. Цель и условия

Правила уровня — текст для кнопки `?`:

На поле по одной приходят фигуры. Перетащи текущую фигуру на свободное место. Если её неудобно класть, можешь повернуть на 90° — каждый поворот стоит 1 монету. На уровень даётся 10 монет, и они не восстанавливаются. Полностью заполненные строки и колонки очищаются. Размести все фигуры из очереди, не заперев поле.

- Условие ПОБЕДЫ: последняя фигура фиксированной очереди успешно размещена на поле и все обязательные очистки после неё разрешены.
- Условие ПОРАЖЕНИЯ: текущая фигура не имеет ни одного легального размещения в своей текущей ориентации, а либо `coins === 0`, либо среди ориентаций, достижимых за оставшиеся монеты, тоже нет ни одного легального размещения.
- Дополнительного лимита ходов нет.
- Runtime RNG отсутствует. Стартовое поле, последовательность фигур и стартовая ориентация каждой фигуры заранее зафиксированы уровнем.

# 3. Правила

1. На старте движок загружает поле, фиксированную очередь фигур и `coins = 10`.
2. Активной становится первая фигура очереди в своей заданной стартовой ориентации.
3. Игрок может нажать кнопку поворота текущей фигуры.
4. Если `coins > 0`, один тап по повороту вращает текущую фигуру ровно на 90° по часовой стрелке и уменьшает `coins` на `1`.
5. Если `coins === 0`, тап по повороту ничего не меняет.
6. Один и тот же объект можно повернуть несколько раз; каждый поворот отдельно стоит 1 монету.
7. Игрок может перетащить текущую фигуру на клетки поля.
8. Фигура размещается только если все её клетки находятся внутри поля и не пересекаются с уже занятыми клетками.
9. Невалидный drop возвращает фигуру в зону ожидания и не меняет поле.
10. Невалидный drop не тратит монету и не продвигает очередь.
11. Валидный drop фиксирует фигуру на поле в её текущей ориентации.
12. После фиксации одновременно очищаются все полностью заполненные строки и колонки.
13. Очистка строк и колонок не возвращает монеты.
14. После разрешения очисток активной становится следующая фигура очереди в её собственной заданной стартовой ориентации.
15. Повороты предыдущей фигуры не влияют на стартовую ориентацию следующей.
16. Игрок не может пропустить фигуру, поменять порядок очереди или вернуть уже размещённую фигуру.
17. После появления каждой новой фигуры движок проверяет, существует ли хотя бы одно легальное размещение с учётом доступных поворотов и оставшихся монет.
18. Если такого размещения нет, фиксируется поражение по п.2.
19. Если очередь закончилась после успешного размещения последней фигуры, фиксируется победа по п.2.

# 4. Состояние уровня

```ts
type Rotation = 0 | 90 | 180 | 270;

type PieceState = {
  id: string;
  shapeId: string;
  rotation: Rotation;
};

type GameState = {
  board: (string | null)[][];
  queue: PieceState[];
  current: PieceState | null;
  coins: number;
  placedCount: number;
  status: 'playing' | 'won' | 'failed';
};
```

Геометрия `shapeId` хранится в общей библиотеке фигур. Стартовые ориентации очереди являются частью неизменяемых данных уровня.

# 5. Ввод

Два типа игровых жестов:

```ts
{ type: 'rotate' } |
{ type: 'drag'; targetId: string; dropCell: { x: number; y: number } }
```

- `rotate` — один платный поворот текущей фигуры на 90°.
- `drag` — попытка разместить текущую фигуру с якорной клеткой `dropCell`.

# 6. Контент уровня

Пример `levels.json`:

```json
{
  "id": 1,
  "grid": { "w": 8, "h": 8 },
  "coins": 10,
  "prefill": [],
  "pieces": [
    { "id": "p1", "shape": "bar3", "rotation": 0 },
    { "id": "p2", "shape": "l3", "rotation": 90 },
    { "id": "p3", "shape": "bar2", "rotation": 0 }
  ]
}
```

Правила контента:

- `coins = 10` на всех пяти экспериментальных уровнях.
- Очередь фигур и стартовая ориентация каждой фигуры фиксированы.
- Runtime RNG нет.
- Используется ограниченная библиотека простых polyomino-фигур.
- Генератор строит уровень из заранее известной проходимой последовательности размещений и затем детерминированно проверяет её.
- Полноценный solver не нужен: генератор знает хотя бы один валидный маршрут и бюджет поворотов этого маршрута.
- Уровень считается невалидным, если оптимальная стратегия требует потратить почти все монеты в первой трети очереди и дальше ресурс перестаёт участвовать в решениях.

Кривая по пяти уровням:

1. **Понять цену поворота.** Короткая очередь из простых фигур. Одна фигура заметно удобнее после одного поворота, но пройти можно и без него. Игрок видит: удобство стоит монету.
2. **Понять ограниченность.** Очередь длиннее. Есть 2–3 соблазнительных поворота, но тратить все подряд невыгодно. В конце остаётся фигура, для которой один поворот существенно облегчает размещение.
3. **Первый настоящий выбор.** Минимум две ситуации, где текущую фигуру можно уложить бесплатно в менее удобное место или потратить монету и сохранить хорошую геометрию поля.
4. **Давление.** Плотнее стартовое поле, больше асимметричных фигур. Неразборчивые ранние повороты оставляют слишком мало монет для поздних обязательных перестроек.
5. **Проверка концепта.** Очередь достаточно длинная, чтобы монеты оставались значимым ресурсом до последней трети. Минимум три решения должны реально зависеть от вопроса «потратить монету сейчас или сохранить на потом».

# 7. Визуал

- Поле: квадратная сетка с чёткими ячейками.
- Текущая фигура показывается под полем крупно и отдельно от уже размещённых блоков.
- Рядом с фигурой — одна понятная кнопка поворота с ценой `1`.
- Монеты показываются как постоянный HUD: `Монеты: 7/10`.
- При доступном повороте кнопка активна; при `0` монет — визуально выключена.
- Выбрано: при drag фигура приподнимается, на поле показывается ghost-placement.
- Выполнено: фигура снапается в сетку.
- Поворот: короткая анимация 90°, одновременно одна монета исчезает из счётчика.
- Очистка: заполненная строка или колонка быстро схлопывается.
- Payoff-момент: игрок тратит монету, фигура поворачивается и сразу становится очевидно, что теперь она идеально входит в подготовленное место.
- Ошибка: если текущую фигуру больше невозможно разместить ни в одной достижимой ориентации, неподходящие клетки кратко подсвечиваются и появляется fail.
- HUD: `Осталось фигур: N`, `Монеты: N/10`.

# 8. Онбординг

1. Перетащи текущую фигуру на свободное место.
2. Полная строка или колонка очищается.
3. Нужен другой угол — нажми поворот.
4. Каждый поворот стоит 1 монету.
5. На весь уровень только 10 монет.
6. Размести всю очередь, не потратив повороты впустую.

Кнопка `?` показывает только правило из п.2.

# 9. Явно ВНЕ рамок

- Без меты, постоянной валюты, коллекций, заданий, ежедневных бонусов, рекламы, IAP.
- Монеты существуют только внутри текущего уровня и всегда стартуют с `10`.
- Без runtime RNG.
- Одно давление: дефицит монет на вращения.
- Один твист: Par — вращение является платным действием.
- Без hold-слота, undo, перестановки очереди, покупки монет, бонусных монет и бесплатных поворотов.
- Без изменений баланса/уровней после публикации, кроме датированного критического бага.

# 10. Метрики и события

Шелл сам логирует общие события эксперимента.

Механика вызывает:

- `first_action` — первый `rotate` или первый валидный `drag`, в зависимости от того, что игрок сделал раньше.
- `level_start` — вход на уровень с номером уровня.
- `level_win` — когда последняя фигура очереди успешно размещена.
- `level_fail` — когда текущую фигуру нельзя разместить ни в одной ориентации, достижимой за оставшиеся монеты; `reason: 'no_legal_placement'`.
- `retry` — повтор того же уровня после fail.
- `level_5_complete` отдельно не эмитится.

Kill-критерий концепта: если монеты в большинстве тестовых прохождений заканчиваются в первой трети уровня и после этого игрок просто доигрывает без решений про ресурс, концепт хоронится.

Онлайн-резерв: читаемость, доходимость до 5 уровня, возврат D1. Если критерий не сработал — концепт не чинится.
