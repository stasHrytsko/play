# 1. Паспорт концепта

Поля паспорта — в шапке раздела 0.

**Почему kill-критерий именно такой.** Идея в том, что слияние открывает плитку под собой и может запустить цепочку, которую игрок не выполнял руками. Если автоматический каскад случается реже раза за уровень, обещание не сбывается: остаётся обычный match плиток со слоями, а перекрытие работает как помеха, а не как заряд. Провал по критерию означает, что каскад не срабатывает как идея: это свойство того, как номиналы разложены по слоям, а не количества плиток.

# 2. Цель и условия

Правила уровня — текст для кнопки `?`:

На столе лежат плитки в несколько слоёв. Нажимать можно только на те, которые ничем не накрыты сверху. Выбери две открытые плитки одинакового номинала — они сольются в плитку следующего номинала. Снятые верхние плитки открывают нижние. Если после слияния новая плитка совпала ровно с одной другой открытой плиткой, начинается автоматический каскад. Разбери весь стол.

- Условие ПОБЕДЫ: на столе не осталось ни одной плитки.
- Условие ПОРАЖЕНИЯ: плитки ещё остаются, но среди всех открытых плиток нет ни одной пары одинакового номинала.
- Runtime RNG отсутствует. Все плитки, их номиналы, позиции, слои и связи перекрытия заданы уровнем заранее.

# 3. Правила

1. На старте движок загружает полный набор плиток и связи перекрытия между ними.
2. Каждая плитка имеет `value`, позицию, слой и список плиток, которые лежат прямо над ней.
3. Плитка считается **открытой**, если ни одна активная плитка не перекрывает её сверху.
4. Закрытая плитка видна частично или полностью в зависимости от раскладки, но не принимает игровой ввод.
5. Игрок тапает по открытой плитке.
6. Если ничего не выбрано, эта плитка становится `selected`.
7. Тап по той же выбранной плитке снимает выбор и не считается ходом.
8. Тап по закрытой плитке ничего не делает и не считается ходом.
9. Если выбрана плитка `A`, а игрок тапает по другой открытой плитке `B` с другим номиналом, выбор переносится на `B`; ход не засчитывается.
10. Если выбрана плитка `A`, а игрок тапает по открытой плитке `B` с тем же номиналом, выполняется merge.
11. При merge плитка `A` удаляется со стола.
12. Плитка `B` остаётся на своей позиции и получает следующий номинал: `value = next(value)`.
13. Один ручной merge считается одним ходом независимо от длины последующего автоматического каскада.
14. После удаления `A` и обновления `B` движок пересчитывает, какие нижние плитки стали открытыми.
15. Затем движок проверяет автоматический каскад для результирующей плитки `B`.
16. Если среди открытых плиток есть **ровно одна** другая плитка `C` с тем же номиналом, `C` автоматически вливается в `B`.
17. При автоматическом merge `C` удаляется, `B` остаётся на месте и снова получает следующий номинал.
18. Автоматический merge не считается отдельным ходом.
19. После каждого автоматического merge движок снова пересчитывает открытые плитки и повторяет проверку каскада.
20. Если подходящих открытых плиток для `B` нет, каскад останавливается.
21. Если подходящих открытых плиток для `B` две или больше, каскад останавливается, чтобы движок не выбирал за игрока.
22. После остановки каскада выбор очищается: `selected = null`.
23. Игрок не может перемещать плитки, менять слой, отменять merge или вручную вмешиваться во время каскада.
24. После полного разрешения хода движок проверяет победу по п.2.
25. Если победы нет, движок проверяет наличие хотя бы одной пары одинаковых открытых плиток.
26. Если такой пары нет, фиксируется поражение по п.2.

# 4. Состояние уровня

```ts
type TileId = string;
type TileValue = number;

type TileState = {
  id: TileId;
  value: TileValue;
  x: number;
  y: number;
  z: number;
  active: boolean;
  coveredBy: TileId[];
};

type GameState = {
  tiles: TileState[];
  selected: TileId | null;
  moves: number;
  cascadeDepth: number;
  status: 'playing' | 'won' | 'failed';
};
```

`coveredBy` хранит явные связи перекрытия из данных уровня. Плитка открыта, если все плитки из `coveredBy` имеют `active === false`.

# 5. Ввод

Один тип игрового ввода — тап по плитке:

```ts
{
  type: 'tap';
  targetId: string;
}
```

Первый тап выбирает открытую плитку. Второй тап либо переносит выбор, либо запускает merge.

# 6. Контент уровня

Пример `levels.json`:

```json
{
  "id": 1,
  "tiles": [
    { "id": "a", "value": 1, "x": 1, "y": 1, "z": 2, "coveredBy": [] },
    { "id": "b", "value": 1, "x": 3, "y": 1, "z": 2, "coveredBy": [] },
    { "id": "c", "value": 2, "x": 1, "y": 2, "z": 1, "coveredBy": ["a"] },
    { "id": "d", "value": 2, "x": 3, "y": 2, "z": 1, "coveredBy": ["b"] }
  ]
}
```

Правила контента:

- Позиции и перекрытия полностью фиксированы до публикации.
- Один верхний тайл может перекрывать одну или несколько нижних плиток.
- Номиналы задаются небольшим целочисленным рядом: `1 → 2 → 3 → 4 → ...`.
- Генератор строит раскладку из заранее решаемой последовательности merge-действий.
- Solver обязан подтвердить существование полного разбора стола.
- Solver также проверяет, что уровень не решается единственным жадным правилом «всегда сливай любую доступную пару».
- Runtime RNG отсутствует.

Кривая по пяти уровням:

1. **Обучение доступности.** Два простых верхних слоя. Очевидная пара открывает ещё одну очевидную пару. Один короткий каскад.
2. **Обучение merge.** 3 номинала, несколько перекрытий. Игрок видит, что результат merge может совпасть с только что открывшейся плиткой и продолжить каскад.
3. **Первый настоящий выбор.** Одновременно доступны минимум две пары. Одна сразу даёт короткий merge, другая открывает плитку, нужную для цепочки глубже.
4. **Давление.** Больше слоёв и перекрёстных перекрытий. Неправильная ранняя пара не проигрывает сразу, но может оставить открытыми номиналы без партнёров.
5. **Проверка концепта.** Минимум три момента, где порядок выбора пар влияет на то, какие нижние плитки откроются. Минимум два каскада, один из них глубиной не менее `2` автоматических merge.

# 7. Визуал

- Стол: компактная композиция плиток в несколько визуально читаемых слоёв.
- Плитки: одинаковая базовая форма; номинал крупно читается в центре; игровые цвета берутся из `tokens.css`.
- Глубина: нижние плитки видны по краям и смещению, чтобы сразу было понятно, что они накрыты.
- Закрытая плитка слегка приглушена и не реагирует на тап.
- Выбранная плитка приподнимается и получает короткий акцентный outline.
- При ручном merge первая плитка быстро летит во вторую; вторая делает короткий pulse и меняет номинал.
- Открывшиеся нижние плитки сразу переходят из приглушённого состояния в активное.
- Главный payoff — каскад: новая плитка последовательно втягивает единственные подходящие открытые плитки, каждый раз повышая номинал и открывая следующий слой.
- Каскад должен читаться без текста: `merge → слой открылся → ещё merge → ещё слой`.
- Ошибка выбора другого номинала не штрафуется: selection просто переносится.
- Fail: все доступные плитки остаются подсвеченными как активные, но ни одна пара не совпадает; затем появляется экран поражения.
- HUD: `Осталось: N`, `Слой: X`, во время каскада кратко `Цепочка ×N`.

# 8. Онбординг

1. Нажимать можно только на плитки, которые ничем не накрыты.
2. Выбери две открытые плитки одинакового номинала.
3. Они сольются в плитку следующего номинала.
4. Снятые плитки открывают то, что лежало под ними.
5. Если новый номинал совпадёт с одной открытой плиткой, merge продолжится автоматически.
6. Разбери весь стол.

Кнопка `?` показывает только правило из п.2.

# 9. Явно ВНЕ рамок

- Без меты, валют, коллекций, заданий, ежедневных бонусов, рекламы, IAP.
- Без runtime RNG.
- Одно давление: блокировка доступа нижними/верхними слоями.
- Один твист: автоматический каскад.
- Без таймера, лимита ходов, бустеров, undo, shuffle и ручного перемещения плиток.
- Без специальных плиток, wildcard, замков и дополнительных типов merge.
- Движок никогда не выбирает между несколькими возможными партнёрами для каскада: при `>1` варианте каскад останавливается.
- Без изменений баланса/уровней после публикации, кроме датированного критического бага.

# 10. Метрики и события

Аналитикой владеет общий shell. Механика **не вызывает PostHog напрямую** —
она сообщает о происходящем через контракт `MechanicHost`.

- Shell сам логирует `game_open`, `help_open`, `level_start`, `level_win`,
  `level_5_complete`, `rating_submit`, `comment_submit`.
- Hub отдельно логирует `hub_impression`, `hub_click`, `teaser_click`.
- D1/D7 и повторные сессии PostHog считает сам по persisted distinct_id и
  `game_open` — отдельные события для них не нужны.
- `retry` шлёт shell после fail-попапа; `level_5_complete` отдельно не
  эмитится, он выводится из `level_win` пятого уровня.

Ниже описано, **когда** наступает каждое событие. Механика при этом вызывает
только `onFirstAction()`, `onFail('<код>')` и `onComplete()` — остальное
отправляет shell.

- `first_action` — первый валидный тап по открытой плитке.
- `level_start` — при входе на каждый уровень с номером уровня.
- `level_win` — когда после полного разрешения merge/каскада не осталось активных плиток.
- `level_fail` — когда плитки остаются, но нет ни одной пары одинаковых открытых плиток; `reason: 'no_open_pair'`.
- `retry` — повтор того же уровня после fail.
- `level_5_complete` отдельно не эмитится.

Внутренние диагностические поля механики:

- `cascade_depth` — число автоматических merge после ручного merge.
- `open_pairs_after_move` — число доступных пар после полного разрешения хода.

Kill-критерий концепта: если автоматический каскад глубиной `>=1` происходит реже одного раза за уровень в среднем по тестовой выборке, концепт хоронится, а не усиливается дополнительными механиками.

Онлайн-резерв: читаемость, доходимость до 5 уровня, возврат D1. Если критерий не сработал — концепт не чинится.

# 11. Крайние случаи

- **Повторный тап по той же плитке** — тап по уже выбранной снимает выбор и ходом не считается (п.7). Тап по другой открытой плитке с иным номиналом переносит выбор, тоже без хода (п.9).
- **Тап мимо всего** — по закрытой плитке или пустому месту — ничего не меняется, ход не засчитывается (п.8).
- **Действие невозможно** — если среди открытых плиток нет ни одной пары с одинаковым номиналом, фиксируется поражение (п.25–26). Вмешаться в каскад игрок не может (п.23), поэтому «нечего делать» проверяется только после полного разрешения хода.
- **Ходов не осталось, победа не выполнена** — неприменимо: лимита ходов нет, конец уровня определяется отсутствием пар.
- **Два объекта в одной позиции** — перекрытие плиток — это сама механика, а не коллизия: плитка лежит над другой и держит её закрытой (п.2–3). Двух плиток в одной точке одного слоя не бывает: при merge `A` удаляется, а `B` остаётся на своём месте (п.11–12).

# 12. Профиль реализации

Относится к фабрике, а не к игровой идее: сменится фабрика — перепишется
только этот раздел.

**Контракт.** Механика реализует `MechanicHost` из `src/shell-contract.ts` и
вызывает `onFirstAction()`, `onComplete()`, `onFail(reason)`, `onExit()`.
PostHog напрямую не трогает — см. раздел 10.

**`game.config.ts`.** `id` совпадает со `slug` из шапки, `title` — с
`title_ru`, `tagline` — короткая строка под названием, `levelCount: 5`,
`version` и `onboarding.version` поднимаются при изменении контента и правил
соответственно. Токены аналитики и ключ обратной связи копируются из
`games/tap-targets/game.config.ts`.

**`data-testid`.** Обязателен на каждом интерактивном элементе — e2e ищет
строго по ним. Существующая конвенция: `game-surface` — контейнер механики,
`mechanic-hud` — HUD с атрибутом `data-remaining`.

**Анимация.** Payoff строится из эффектов `render-kit`: `punch`,
`invalidShake`, `successFlash`, `fadeCollapse`, `cameraShake`, `moveTo`.
Если нужного нет — сказать здесь, а не изобретать свой во время сборки.
