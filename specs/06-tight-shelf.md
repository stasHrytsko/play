# 1. Паспорт концепта

- Название: Тесная полка
- **Правило одной фразой:** Клади товары на полки: три одинаковых исчезают, а заполненные полки ведут к проигрышу.
- Глагол: сортировка
- Давление: дефицит места
- Твист: нет
- **Целевая эмоция:** теснота — постоянное ощущение, что свободного места почти не осталось
- **Уровни:** генерируется
- **Солвер:** нужен
- Оценка: 27/30 — чит 5, мот 4, давл 5, payoff 5, произв 3, рынок 5

Дополнительно:
- Семейство: Sort
- Отличие от аналога: Goods Sort — узкое место не поиск тройки, а ограниченная ёмкость полок.
- TREND: да
- Kill-критерий: если оптимально почти всегда класть товар на самую пустую полку, концепт хоронится.

# 2. Цель и условия

## Правила уровня — текст для кнопки «?»

Перед тобой несколько полок и куча товаров. Каждый товар можно положить на любую полку, где есть свободное место.

Каждая полка вмещает 5 товаров.

Если на одной полке собираются 3 одинаковых товара, эта тройка сразу исчезает и освобождает места.

Полок меньше, чем типов товаров, поэтому часть вещей приходится временно класть не туда, где уже собирается тройка.

## Условие ПОБЕДЫ

В куче не осталось товаров, и все товары, уже лежащие на полках, разрешились по правилам уровня.

## Условие ПОРАЖЕНИЯ

Игрок пытается разместить следующий товар, но все полки заполнены до лимита `5/5` и ни на одной полке нет свободного места.

Других условий поражения нет.

Runtime RNG отсутствует. Порядок товаров, их типы и стартовое состояние полок заранее зафиксированы в данных уровня.

# 3. Правила

1. На старте уровня движок загружает фиксированную очередь товаров и состояние полок.
2. Для базового эксперимента используется 3 полки по 5 мест каждая.
3. На экране всегда показан текущий товар, который нужно разместить.
4. Игрок тапает по одной из полок, выбирая, куда положить текущий товар.
5. Если на выбранной полке есть свободное место, товар занимает первый свободный слот этой полки.
6. Если выбранная полка заполнена `5/5`, тап ничего не меняет и не считается ходом.
7. После валидного размещения движок проверяет количество товаров каждого типа на этой полке.
8. Если на полке стало ровно 3 или больше товаров одного типа, одна тройка этого типа немедленно удаляется.
9. Удаление тройки освобождает 3 места на этой же полке.
10. За один ход может разрешиться только одна тройка — та, которая образовалась вследствие последнего размещения.
11. Удаление тройки не считается отдельным ходом.
12. После разрешения результата текущий товар удаляется из очереди, и открывается следующий.
13. Игрок не может перемещать уже размещённые товары между полками.
14. Игрок не может пропустить текущий товар.
15. Игрок не может менять порядок очереди.
16. Если очередь пуста, движок проверяет условие победы из п.2.
17. Если очередь не пуста и все полки заполнены `5/5`, фиксируется поражение по п.2.

# 4. Состояние уровня

```ts
type ItemType = string;

type ShelfState = {
  id: string;
  items: ItemType[];
  capacity: 5;
};

type GameState = {
  queue: ItemType[];
  current: ItemType | null;
  shelves: ShelfState[];
  moves: number;
  status: 'playing' | 'won' | 'failed';
};
```

# 5. Ввод

```ts
{
  type: 'tap';
  targetId: string;
}
```

`targetId` — id полки.

Один игровой жест — тап по полке, на которую игрок хочет положить текущий товар.

Тап по заполненной полке не считается игровым ходом.

# 6. Контент уровня

## Формат уровня в `levels.json`

```json
{
  "id": 1,
  "shelfCount": 3,
  "shelfCapacity": 5,
  "itemTypes": ["a", "b", "c", "d"],
  "queue": ["a", "a", "b", "c", "a", "d", "b", "b", "c"]
}
```

Стартовые полки по умолчанию пустые. При необходимости уровень может задавать фиксированный `prefill`.

```json
{
  "prefill": [
    ["a"],
    ["b", "c"],
    []
  ]
}
```

Генерация выполняется до публикации. Runtime RNG отсутствует.

Солвер обязан проверять, что:

1. У уровня существует хотя бы один путь до победы.
2. Победа требует не только правила «клади на самую пустую полку».
3. Хотя бы в уровнях 3–5 есть состояния, где выбор менее пустой полки является частью решения.

## Кривая по пяти уровням

### Уровень 1 — понять тройку

- 3 полки.
- 3 типа товаров.
- 9–12 товаров.
- Очередь несколько раз почти сама собирает очевидные тройки.
- Полки редко заполнены больше чем на 3/5.

Цель: игрок понимает связь `3 одинаковых на одной полке → исчезают`.

### Уровень 2 — понять временное хранение

- 3 полки.
- 4 типа товаров.
- 15–18 товаров.
- Один тип приходится временно положить на полку, где пока нет пары.
- Хотя бы одна полка доходит до 4/5.

Цель: показать, что не каждый товар сразу ведёт к тройке.

### Уровень 3 — первый настоящий выбор

- 3 полки.
- 5 типов товаров.
- 20–24 товара.
- Есть минимум три состояния, где один товар можно разумно положить на две разные полки.
- Выбор самой пустой полки хотя бы один раз создаёт худшее будущее состояние.

### Уровень 4 — давление

- 3 полки.
- 6 типов товаров.
- 24–30 товаров.
- Полки регулярно достигают 4/5.
- Нужно сознательно держать свободный слот под будущую тройку.
- Неудачные размещения могут привести к полной блокировке спустя несколько ходов.

### Уровень 5 — проверка концепта

- 3 полки.
- 7 типов товаров.
- 30–36 товаров.
- Все три полки несколько раз оказываются почти заполнены.
- Минимум три решения должны зависеть от будущей последовательности товаров, а не только от текущей заполненности.
- Жадная стратегия «всегда класть на самую пустую полку» не должна проходить уровень.

# 7. Визуал

## Поле

В центре экрана — 3 горизонтальные полки.

Каждая полка визуально разделена на 5 фиксированных мест.

Над полками — текущий товар. Рядом можно показать preview следующих 2 товаров, если он зафиксирован в уровне и одинаков для всех игроков.

Форма товара — простой объект-карточка или коробка с крупным символом типа. Цвета берутся только из `tokens.css`.

## Состояние «выбрано»

При тапе выбранная полка коротко подсвечивается, а товар перелетает в первый свободный слот.

## Выполнено

Если тройка не собралась, товар просто остаётся на месте.

## Payoff

Если образовалась тройка:

1. три одинаковых товара слегка приподнимаются;
2. быстро стягиваются друг к другу;
3. исчезают;
4. свободные слоты схлопываются визуально обратно в пустые места.

Весь payoff должен считываться примерно за одну секунду.

## Ошибка

Тап по полной полке вызывает короткий shake полки. Ход не тратится.

При поражении все три полки визуально показываются как заполненные, затем появляется fail.

## HUD

Помимо `Осталось: N`:

- заполненность каждой полки: `3/5`, `4/5`, `2/5`;
- текущий товар;
- preview следующих товаров, если он включён в конкретный уровень.

# 8. Онбординг

1. Положи текущий товар на любую полку.
2. На каждой полке только 5 мест.
3. Три одинаковых товара на одной полке исчезают.
4. Освобождённые места можно использовать снова.
5. Уже положенные товары нельзя переносить.
6. Не дай всем полкам заполниться.

Кнопка `?` показывает только краткое правило из п.2.

# 9. Явно ВНЕ рамок

- Без меты, валют, коллекций, заданий, ежедневных бонусов, рекламы, IAP.
- Без runtime RNG.
- Одно давление: дефицит места.
- Твист отсутствует.
- Без перемещения уже размещённых товаров.
- Без обмена товаров между полками.
- Без undo.
- Без бустеров.
- Без скрытых типов товаров.
- Без изменения вместимости полок во время уровня.
- Без второй механики очистки кроме `3 одинаковых на одной полке`.
- Без изменений баланса/уровней после публикации, кроме датированного критического бага.

# 10. Метрики и события

Шелл самостоятельно логирует общие события эксперимента.

Механика вызывает:

- `first_action` — первый валидный тап по полке, после которого текущий товар реально размещён.
- `level_start` — при входе на каждый уровень с номером уровня.
- `level_win` — когда выполнено условие победы из п.2.
- `level_fail` — когда очередь не пуста, а все полки заполнены `5/5`; `reason: 'all_shelves_full'`.
- `retry` — повтор того же уровня после `level_fail`.
- `level_5_complete` отдельно не эмитится.

Kill-критерий концепта: если стратегия «всегда класть на самую пустую полку» решает уровни или ключевые состояния без реального планирования, концепт хоронится.

Онлайн-резерв: читаемость, доходимость до 5 уровня, возврат D1. Если критерий не сработал — концепт не чинится.
