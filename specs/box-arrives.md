# 1. Паспорт концепта

- Название: Ящик приезжает
- **Правило одной фразой:** Приёмные ящики меняются по расписанию — откручивай винты под доступные цвета.
- Глагол: извлечение
- Давление: навязанная очередь
- Твист: нет
- **Целевая эмоция:** ритм и удовлетворение от того, что поймал нужный цвет в правильное окно
- **Уровни:** генерируется
- **Солвер:** не нужен
- Оценка: 27/30
  - Читаемость: 4/5
  - Мотивация: 5/5
  - Давление: 4/5
  - Payoff: 4/5
  - Производимость: 5/5
  - Рынок: 5/5

Дополнительно:
- Семейство: Screw
- Отличие от аналога: Screw Jam — цвет нужно не просто найти, а поймать в доступное окно.
- TREND: да
- Kill-критерий: если предпросмотр очереди ящиков не меняет порядок откручивания, концепт хоронится.

# 2. Цель и условия

## Правила уровня — текст для кнопки «?»

Откручивай винты.

Внизу стоят два активных приёмных ящика. Каждые 3 хода левый ящик уезжает, правый сдвигается влево, а следующий ящик из очереди приезжает справа.

Цвета следующих ящиков видны заранее.

Если цвет винта совпадает с одним из активных ящиков, винт сразу отправляется туда. Если нужного цвета сейчас нет, винт попадает в карман.

В кармане 3 места. Когда подходящий ящик приезжает, соответствующие винты автоматически уходят из кармана.

## Условие ПОБЕДЫ

На поле не осталось ни одного винта.

## Условие ПОРАЖЕНИЯ

Игрок откручивает винт цвета, которого нет среди двух активных ящиков, когда все 3 места кармана уже заняты.

Попытка положить четвёртый винт в карман немедленно завершает уровень поражением.

Других условий поражения нет.

Runtime RNG отсутствует. Порядок ящиков, расположение винтов и их цвета полностью зафиксированы в данных уровня.

# 3. Правила

1. На старте уровня движок загружает набор винтов, очередь ящиков и выставляет первые два ящика как активные.
2. Под активными ящиками показывается очередь следующих 3 ящиков.
3. Счётчик до смены ящика устанавливается в `3`.
4. Карман пуст.
5. Игрок может нажать на любой винт, который ещё находится на поле.
6. Тап по уже удалённому винту ничего не делает и не считается ходом.
7. Валидный тап по винту всегда откручивает его с поля.
8. Если цвет винта совпадает хотя бы с одним активным ящиком, винт сразу отправляется в этот ящик.
9. Такой винт не занимает место в кармане.
10. Если цвет винта не совпадает ни с одним активным ящиком и в кармане есть свободное место, винт помещается в первый свободный слот кармана.
11. Если цвет винта не совпадает ни с одним активным ящиком и все 3 слота кармана заняты, фиксируется `level_fail`.
12. Каждый успешно открученный винт считается одним ходом.
13. После каждого успешного хода счётчик смены ящика уменьшается на `1`.
14. Когда счётчик достигает `0`, выполняется смена ящиков.
15. При смене левый активный ящик уезжает за пределы экрана.
16. Правый активный ящик перемещается на левую позицию.
17. Первый ящик из очереди становится новым правым активным ящиком.
18. Очередь сдвигается на одну позицию.
19. Счётчик смены снова устанавливается в `3`.
20. Сразу после появления нового ящика движок проверяет карман.
21. Все винты из кармана, цвет которых совпадает с одним из двух активных ящиков, автоматически отправляются в соответствующий ящик.
22. Автоматическое освобождение кармана не считается ходом.
23. Если сразу несколько винтов подходят под приехавший ящик, они покидают карман последовательно с коротким визуальным интервалом.
24. Активные ящики не имеют ограничения вместимости.
25. В двух активных позициях одновременно не может находиться два ящика одного цвета.
26. Игрок не может менять очередь ящиков.
27. Игрок не может пропустить ход.
28. Игрок не может вручную перемещать винты из кармана.
29. Игрок не может взаимодействовать с ящиками.
30. Если после разрешения действия на поле не осталось винтов, фиксируется победа по условию из п.2.

# 4. Состояние уровня

```ts
type ColorId = string;

type PocketItem = {
  screwId: string;
  color: ColorId;
};

type GameState = {
  levelId: number;
  remainingScrews: string[];
  removedScrews: string[];
  pocket: PocketItem[];
  activeBoxes: [ColorId, ColorId];
  boxQueue: ColorId[];
  moves: number;
  movesUntilShift: 1 | 2 | 3;
  status: 'playing' | 'won' | 'failed';
  firstActionTracked: boolean;
};
```

Движок также имеет неизменяемые данные уровня с цветом и координатами каждого винта.

# 5. Ввод

В механике используется один игровой жест — тап по винту.

```ts
{
  type: 'tap';
  targetId: string;
}
```

`targetId` всегда относится к винту.

Тапы по HUD, очереди, карману или ящикам не передаются в игровой движок как игровые действия.

# 6. Контент уровня

## Формат уровня в `levels.json`

```json
{
  "id": 1,
  "shiftEvery": 3,
  "pocketSize": 3,
  "queuePreview": 3,
  "screws": [
    { "id": "s1", "color": "c1", "x": 0.24, "y": 0.31 },
    { "id": "s2", "color": "c3", "x": 0.53, "y": 0.22 }
  ],
  "boxes": ["c1", "c2", "c3", "c1", "c4", "c2"]
}
```

Первые два элемента `boxes` — стартовые активные ящики. Остальные элементы — фиксированная очередь приезда.

`shiftEvery`, `pocketSize` и `queuePreview` одинаковы для всех пяти экспериментальных уровней:

```ts
shiftEvery = 3
pocketSize = 3
queuePreview = 3
```

Сложность растёт только за счёт распределения цветов винтов и порядка ящиков.

## Генерация

Генерация выполняется до публикации. Runtime RNG отсутствует.

Генератор:

1. Создаёт фиксированную очередь ящиков.
2. Формирует набор цветов винтов относительно этой очереди.
3. Гарантирует существование маршрута без переполнения кармана.
4. Расставляет винты по допустимым координатам.
5. Сохраняет результат в `levels.json`.
6. После сохранения уровень больше не меняется.

Полноценный solver не нужен. Генератор строит уровень из заранее допустимой последовательности действий и после генерации только прогоняет её детерминированной проверкой.

## Кривая пяти уровней

### Уровень 1 — понять соответствие цветов

- 3 цвета
- 10 винтов
- Большинство винтов совпадает с текущими активными ящиками.
- Очередь показывает первое очевидное появление третьего цвета.
- Карман нужен максимум один раз.
- Игрок должен увидеть связь: `цвет винта → активный ящик`.

### Уровень 2 — понять расписание

- 3 цвета
- 13 винтов
- Несколько винтов текущего недоступного цвета специально лежат рядом с доступными.
- Один и тот же цвет возвращается позже в очереди.
- Карман можно заполнить на 2/3 без риска.

### Уровень 3 — первый настоящий выбор

- 4 цвета
- 16 винтов
- В нескольких состояниях одновременно есть минимум 3 разумных кандидата на тап.
- Один цвет отсутствует сейчас, но находится первым в preview.
- Другой отсутствующий цвет появится значительно позже.
- Неправильный порядок способен довести карман до `3/3`.

### Уровень 4 — давление

- 4 цвета
- 20 винтов
- Несколько отрезков требуют временно использовать карман.
- Очередь регулярно меняет лучший следующий ход.
- Есть состояния с карманом `2/3`, где неправильный следующий цвет приводит к поражению позже.

### Уровень 5 — проверка концепта

- 5 цветов
- 24 винта
- Все пять цветов реально участвуют в выборе.
- Карман периодически достигает `3/3`.
- Следующий приезд часто освобождает один или несколько слотов.
- Уровень содержит минимум три ситуации, где знание следующих ящиков должно менять порядок откручивания.

Если preview можно игнорировать и всё равно естественно пройти уровень, уровень считается невалидным ещё до публикации.

# 7. Визуал

## Поле

Основная игровая зона — одна крупная плита.

Винты:
- круглая головка;
- внутренний шлиц;
- достаточно крупная tap-area;
- визуально одинаковый размер;
- различаются игровым token-цветом.

Никаких падающих досок, физики пластин или дополнительных Screw Jam-механик нет.

## Активные ящики

Два крупных контейнера стоят в нижней части игрового поля.

Левый — следующий на выезд. Правый — приехавший позже.

Над левым ящиком показывается индикатор `уедет через 3`, после каждого хода: `3 → 2 → 1`.

Очередь будущих ящиков располагается рядом и визуально заметно меньше активных. Показываются следующие 3 цвета.

## Карман

Три фиксированных круглых слота: `○ ○ ○`.

Каждый неподходящий винт перелетает со своего места в свободный слот. Карман всегда виден.

HUD показывает `Карман 2/3`.

## Состояние «выбрано»

После тапа винт слегка приподнимается, делает короткий оборот и выходит из отверстия.

## Успешное совпадение

Если подходящий ящик активен, винт после выкручивания летит напрямую в соответствующий ящик.

## Винт ушёл в карман

Винт после выкручивания летит в свободный слот кармана. При заполнении третьего слота карман делает короткий акцент состояния `3/3`.

## Приезд ящика — основной payoff-момент

Каждые три хода:

1. левый ящик выезжает;
2. правый плавно сдвигается влево;
3. новый ящик въезжает справа;
4. очередь сдвигается;
5. подходящие винты автоматически вылетают из кармана в новый ящик;
6. освободившиеся места кармана явно подсвечиваются анимацией освобождения.

Весь момент должен читаться примерно за одну секунду.

Игрок должен визуально почувствовать: «Я это предвидел».

## Ошибка

При попытке положить четвёртый винт винт доходит до кармана, карман коротко дёргается, четвёртому винту физически некуда встать, затем сразу показывается поражение.

## HUD

Помимо `Осталось: N`:
- `Смена через: 3 / 2 / 1`
- `Карман: 0/3`
- preview следующих 3 ящиков

# 8. Онбординг

1. `Нажми на винт, чтобы открутить его.`
2. `Подходящий цвет сразу отправится в один из этих ящиков.`
3. `Неподходящий винт попадёт в карман.`
4. `В кармане только 3 места.`
5. `Каждые 3 хода приезжает новый ящик.`
6. `Смотри вперёд: следующие ящики уже видны.`

После этого управление полностью передаётся игроку.

Кнопка `?` открывает только краткое правило из п.2 и не повторяет пошаговый онбординг.

# 9. Явно ВНЕ рамок

- Без меты, валют, коллекций, заданий, ежедневных бонусов, рекламы, IAP.
- Без runtime RNG.
- Без бустеров.
- Без undo.
- Без ручной перестановки винтов.
- Без взаимодействия с ящиками.
- Без изменения порядка очереди.
- Без пропуска хода.
- Без вместимости ящиков.
- Без физики падающих пластин.
- Без скрытых винтов.
- Без дополнительных типов винтов.
- Максимум одно давление: навязанная очередь.
- Максимум один твист; здесь твиста нет.
- После публикации баланс, очередь, количество винтов и уровни не меняются.
- Допустима только датированная правка критического бага.

# 10. Метрики и события

Shell самостоятельно логирует `game_open`, `hub_impression`, `hub_click`, `teaser_click`, `help_open`, `more_yes`, `session_2`, `return_d1`, `return_d7` и общие поля `game_id`, `anonymous_user_id`, `session_id`, `timestamp`, `source`, `version`.

Механика вызывает `track()` в следующих точках.

## `first_action`

Первый валидный тап по винту, который ещё находится на поле.

```ts
track('first_action')
```

Тап по пустому месту, HUD или уже удалённому винту не считается `first_action`.

## `level_start`

При каждом входе на уровень:

```ts
track('level_start', { level: 3 })
```

## `level_win`

Когда после разрешения последнего валидного тапа `remainingScrews.length === 0`:

```ts
track('level_win', {
  level: 3,
  moves: 16
})
```

## `level_fail`

Когда игрок пытается отправить неподходящий винт в уже заполненный карман:

```ts
track('level_fail', {
  level: 4,
  moves: 12,
  reason: 'pocket_overflow'
})
```

## `retry`

При повторном запуске того же уровня после `level_fail`:

```ts
track('retry', { level: 4 })
```

## `level_5_complete`

Отдельно не эмитится. Автоматически определяется shell как `level_win` пятого уровня.

## Проверяемая гипотеза

Игрок смотрит на очередь будущих ящиков и на её основе меняет порядок откручивания винтов.

Если preview существует визуально, но фактически не влияет на решения игрока, механика не прошла эксперимент.

Концепт не лечится дополнительными бустерами, усложнением Screw-механики, уменьшением кармана или ускорением смены ящиков. Он хоронится.

## Онлайн-ворота

Если прямую проверку влияния preview до публикации провести невозможно, используются общие ворота эксперимента: читаемость, доходимость до 5 уровня, возврат D1.

Если критерий эксперимента не выполнен — концепт хоронится, а не перебалансируется.
