# 2. Цель и условия

Правила уровня — текст для кнопки `?`:

Сгибай фигуру только по отмеченным линиям. При сгибе выбранная тонкая часть перекидывается на другую сторону линии и накрывает новые клетки. Всё, что уже участвовало в сгибе, становится толстым и больше не может сгибаться. Накрой все отмеченные клетки.

- Условие ПОБЕДЫ: все клетки из `targets` покрыты фигурой после завершения очередного сгиба.
- Условие ПОРАЖЕНИЯ: победа ещё не достигнута и не осталось ни одной допустимой линии сгиба.
- Отдельного глобального лимита ходов нет.
- Runtime RNG отсутствует. Форма, цели и доступные линии сгиба заранее заданы уровнем.

# 3. Правила

1. На старте движок загружает клеточную сетку, исходную фигуру, целевые клетки и набор допустимых линий сгиба.
2. Каждая занятая клетка фигуры имеет толщину `1` или `2`.
3. На старте все клетки фигуры имеют толщину `1`.
4. Игрок может выбрать только линию сгиба, заданную в уровне.
5. Для каждой линии заранее задана сторона, которая может быть перекинута через неё, либо обе стороны как два отдельных допустимых действия.
6. Сгиб разрешён только если все клетки перемещаемой части имеют толщину `1`.
7. Сгиб разрешён только если зеркальные позиции всех перемещаемых клеток находятся внутри поля.
8. Клетки перемещаемой части отражаются относительно линии сгиба в заранее определённые клетки назначения.
9. После сгиба исходные позиции перемещённой части освобождаются.
10. Клетка назначения становится занятой фигурой.
11. Если в клетке назначения уже была тонкая часть фигуры толщины `1`, итоговая толщина клетки становится `2`.
12. Если клетка назначения была пустой, перемещённая клетка всё равно считается участвовавшей в сгибе и получает толщину `2`.
13. Клетка толщины `2` больше никогда не может входить в перемещаемую часть последующего сгиба.
14. Клетка толщины `2` может оставаться на неподвижной стороне будущего сгиба и не мешает ему, если сама не должна перемещаться.
15. Недопустимый выбор линии ничего не меняет.
16. После каждого валидного сгиба движок пересчитывает покрытие целевых клеток.
17. Если все `targets` покрыты, фиксируется `level_win`.
18. Если победа не достигнута и ни одна линия больше не допускает сгиба, фиксируется `level_fail`.
19. Порядок сгибов полностью определяется действиями игрока; случайных изменений состояния нет.

# 4. Состояние уровня

```ts
type Thickness = 1 | 2;

type Cell = {
  x: number;
  y: number;
  thickness: Thickness;
};

type FoldLine = {
  id: string;
  axis: 'horizontal' | 'vertical';
  index: number;
  side: 'negative' | 'positive';
  cells: string[];
};

type GameState = {
  occupied: Record<string, Thickness>;
  targets: string[];
  folds: FoldLine[];
  usedFolds: string[];
  moves: number;
  status: 'playing' | 'won' | 'failed';
};
```

`cells` у `FoldLine` содержит клетки исходной фигуры, которые эта операция пытается перекинуть. Геометрия отражения вычисляется движком из `axis`, `index` и `side`.

Пример `levels.json`:

```json
{
  "id": 1,
  "grid": { "w": 6, "h": 6 },
  "shape": [
    { "x": 1, "y": 3 },
    { "x": 2, "y": 3 },
    { "x": 3, "y": 3 },
    { "x": 3, "y": 2 }
  ],
  "targets": [
    { "x": 3, "y": 1 },
    { "x": 4, "y": 3 }
  ],
  "folds": [
    {
      "id": "f1",
      "axis": "vertical",
      "index": 3,
      "side": "negative",
      "cells": ["1,3", "2,3"]
    },
    {
      "id": "f2",
      "axis": "horizontal",
      "index": 2,
      "side": "positive",
      "cells": ["3,3"]
    }
  ]
}
```

Правила контента:

- На одном уровне обычно 2–5 допустимых линий сгиба.
- Генератор обязан подтвердить solver-ом минимум одно решение.
- Solver должен учитывать необратимую толщину после каждого сгиба.
- Уровень не принимается, если все допустимые первые ходы ведут к победе одинаково легко.
- Уровень не принимается, если порядок сгибов не влияет на решаемость.
- Runtime RNG отсутствует.

Кривая по пяти уровням:

1. **Обучение.** Одна линия сгиба, одна целевая клетка. Игрок видит, как часть перекидывается и становится толстой.
2. **Первый порядок.** Две линии, обе выглядят допустимыми, но только один порядок позволяет накрыть обе цели.
3. **Первый настоящий выбор.** Три линии. Один ранний сгиб создаёт толстую область и блокирует полезный следующий сгиб.
4. **Давление.** Четыре линии, несколько целей по разные стороны фигуры. Нужно заранее понимать, какую тонкую часть сохранить для последнего сгиба.
5. **Проверка концепта.** 4–5 линий, минимум три осмысленных развилки, где локально выгодный сгиб закрывает будущую возможность. Решение не должно сводиться к ближайшей линии.

# 7. Визуал

- Поле: простая клеточная сетка.
- Фигура: единая плоская форма, собранная из занятых клеток.
- Цели: отдельные маркеры клеток под фигурой или рядом с ней.
- Допустимые линии сгиба: короткие пунктирные линии с понятным направлением перекидывания.
- Тонкая часть: обычная плоская заливка.
- Толстая часть: визуально двойной слой / усиленный контур / небольшая высота, чтобы сразу читалось «больше не гнётся».
- Выбор линии: подсветка будущего отражения до подтверждения.
- Выполнено: короткая анимация переворота выбранной части через линию.
- Payoff: после правильного последнего сгиба цели быстро подсвечиваются как закрытые.
- Ошибка: если игрок выбирает недопустимую линию, толстые клетки коротко подсвечиваются как причина блокировки; состояние не меняется.
- HUD: количество оставшихся незакрытых целей. Глобальный лимит ходов не показывается, потому что его нет.

# 8. Онбординг

1. Нажми на отмеченную линию — часть фигуры перекинется через неё.
2. Нужно накрыть все отмеченные клетки.
3. После сгиба участвовавшая часть становится толстой.
4. Толстую часть больше нельзя сгибать.
5. Поэтому порядок сгибов важен.
6. Кнопка `?` повторяет правило уровня, но не показывает решение.

# 9. Явно ВНЕ рамок

- Нет меты, валют, коллекций, квестов, daily-бонусов, рекламы и IAP.
- Нет runtime RNG.
- Только одно давление: необратимая толщина уже сложенной части.
- Твист отсутствует.
- Нет отдельного общего лимита сгибов как основной механики.
- Нет свободного рисования линии сгиба — только заранее заданные линии уровня.
- Нет вращения фигуры целиком.
- Нет масштабирования, растягивания или произвольной деформации.
- Нет undo, бустеров и дополнительных инструментов.
- Толщина имеет только два состояния: `1` и `2`.
- После публикации баланс и геометрия уровня не меняются, кроме датированного critical bug fix.

# 10. Метрики и события

Аналитикой владеет общий shell. Механика **не вызывает PostHog напрямую** —
она сообщает о происходящем через контракт `MechanicHost`.

- Shell сам логирует `game_open`, `help_open`, `level_start`, `level_win`,
  `level_5_complete`, `rating_submit`, `comment_submit`.
- Hub отдельно логирует `hub_impression`, `hub_click`, `teaser_click`.
- D1/D7 и повторные сессии PostHog считает сам по persisted distinct_id и
  `game_open` — отдельные события для них не нужны.
- `retry` шлёт shell после fail-попапа; `level_5_complete` отдельно не
  эмитится, он выводится из `level_win` пятого уровня.

Ниже описано, **когда** наступает каждое событие. Механика при этом вызывает
только `onFirstAction()`, `onFail('<код>')` и `onComplete()` — остальное
отправляет shell.

- `first_action` — первый валидный сгиб;
- `level_start`;
- `level_win`;
- `level_fail` с `reason = no_valid_folds`;
- `retry`.

`level_5_complete` отдельно не эмитится — определяется по `level_win` пятого уровня.

Дополнительные поля для fold-событий:
- `fold_id`
- `moves`
- `targets_remaining`
- `thin_cells_remaining`
- `thick_cells_count`

Онлайн-гейты как резерв:
- читается ли правило «толстое больше не гнётся» без объяснения после первого уровня;
- доходит ли игрок до L5;
- D1.

Если kill-критерий выполняется или концепт проваливает гейт, концепт закрывается, а не чинится изменением уже опубликованных уровней.

# 12. Профиль реализации

Относится к фабрике, а не к игровой идее: сменится фабрика — перепишется
только этот раздел.

**Контракт.** Механика реализует `MechanicHost` из `src/shell-contract.ts` и
вызывает `onFirstAction()`, `onComplete()`, `onFail(reason)`, `onExit()`.
PostHog напрямую не трогает — см. раздел 10.

**`game.config.ts`.** `id` совпадает со `slug` из шапки, `title` — с
`title_ru`, `tagline` — короткая строка под названием, `levelCount: 5`,
`version` и `onboarding.version` поднимаются при изменении контента и правил
соответственно. Токены аналитики и ключ обратной связи копируются из
`games/tap-targets/game.config.ts`.

**`data-testid`.** Обязателен на каждом интерактивном элементе — e2e ищет
строго по ним. Существующая конвенция: `game-surface` — контейнер механики,
`mechanic-hud` — HUD с атрибутом `data-remaining`.

**Анимация.** Payoff строится из эффектов `render-kit`: `punch`,
`invalidShake`, `successFlash`, `fadeCollapse`, `cameraShake`, `moveTo`.
Если нужного нет — сказать здесь, а не изобретать свой во время сборки.
_Какие именно эффекты нужны этой игре — не записано._
