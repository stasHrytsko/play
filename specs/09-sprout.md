# 2. Цель и условия

Правила уровня — текст для кнопки `?`:

Веди отросток по соседним клеткам. Каждый шаг тратит 1 ход. Клетки ветки дают очки, но они не засчитываются, пока ветка не дойдёт до воды. Источник воды закрепляет ветку, сохраняет собранные очки и даёт указанный бонус шагов. Если шаги закончатся раньше воды, вся незакреплённая ветка осыплется, а её клетки станут мёртвыми. Набери нужное количество очков.

- Условие ПОБЕДЫ: `bankedScore >= targetScore` после закрепления ветки у источника воды.
- Условие ПОРАЖЕНИЯ: `bankedScore < targetScore` и из последней закреплённой точки не существует пути к ни одному неиспользованному источнику воды через доступные клетки длиной не больше сохранённого запаса шагов.
- Само осыпание ветки не является поражением: игрок возвращается в последнюю закреплённую точку и может попробовать другой маршрут.
- Runtime RNG отсутствует. Карта, ценность клеток, стартовый запас, источники воды и их бонусы заранее зафиксированы уровнем.

Техническая фиксация для прототипа: каждая закреплённая точка сохраняет текущий запас шагов. После неудачной ветки игрок возвращается в неё с тем же запасом, который был сохранён в момент закрепления. Это позволяет продолжить игру после осыпания, а цена ошибки остаётся в мёртвых клетках.

# 3. Правила

1. На старте уровня движок загружает сетку, корень, источники воды, ценность клеток, `targetScore` и стартовый запас шагов.
2. Корень считается первой закреплённой точкой.
3. В начале `bankedScore = 0`, активная незакреплённая ветка пуста.
4. Игрок делает свайп вверх, вниз, влево или вправо.
5. Валидный свайп переносит кончик ветки ровно на одну соседнюю клетку в выбранном направлении.
6. Нельзя выйти за границы поля.
7. Нельзя войти в мёртвую клетку.
8. Нельзя повторно войти в клетку текущей незакреплённой ветки.
9. Нельзя войти в уже закреплённую клетку, кроме текущей закреплённой точки, из которой начинается новая ветка.
10. Невалидный свайп ничего не меняет и не тратит шаг.
11. Каждый валидный шаг уменьшает `stepsRemaining` на `1`.
12. Обычная клетка, по которой прошла активная ветка, добавляет своё `value` в `pendingScore`.
13. `pendingScore` не входит в общий счёт, пока ветка не закреплена у воды.
14. Если кончик ветки входит в неиспользованный источник воды, источник считается достигнутым.
15. При достижении воды все клетки текущей ветки становятся закреплёнными.
16. `pendingScore` добавляется в `bankedScore`, затем `pendingScore` сбрасывается в `0`.
17. Достигнутый источник воды помечается использованным и больше не может использоваться как новая цель.
18. После закрепления к текущему запасу добавляется фиксированный `bonusSteps` этого источника.
19. Новый итоговый запас шагов сохраняется в этой воде как `anchorSteps`.
20. Эта вода становится новой закреплённой точкой, от которой растёт следующая ветка.
21. Если после закрепления выполнено условие победы из п.2, фиксируется `level_win`.
22. Если после валидного шага `stepsRemaining` стал `0`, а текущая клетка не является водой, незакреплённая ветка осыпается.
23. При осыпании все клетки текущей ветки становятся мёртвыми.
24. Очки этой ветки теряются: `pendingScore = 0`.
25. Кончик роста возвращается в последнюю закреплённую точку.
26. `stepsRemaining` восстанавливается до сохранённого `anchorSteps` этой точки.
27. Мёртвые клетки остаются мёртвыми до конца попытки и больше не доступны.
28. После осыпания движок проверяет наличие хотя бы одного достижимого неиспользованного источника воды.
29. Источник считается достижимым, если существует путь от текущей закреплённой точки через доступные клетки длиной `<= anchorSteps`.
30. Если такого пути нет и победа ещё не достигнута, фиксируется `level_fail` по условию из п.2.
31. Использованные источники, мёртвые клетки и закреплённые ветки не меняются случайным образом и полностью определяются действиями игрока.

# 6. Контент уровня

Пример `levels.json`:

```json
{
  "id": 1,
  "grid": { "w": 7, "h": 9 },
  "root": { "x": 3, "y": 8 },
  "initialSteps": 6,
  "targetScore": 10,
  "cells": [
    { "x": 3, "y": 7, "value": 1 },
    { "x": 3, "y": 6, "value": 1 },
    { "x": 2, "y": 6, "value": 3 }
  ],
  "waters": [
    { "id": "w1", "x": 3, "y": 4, "bonusSteps": 3 },
    { "id": "w2", "x": 1, "y": 2, "bonusSteps": 4 }
  ],
  "blocked": []
}
```

Правила контента:

- `value` обычной клетки: `1–3`.
- Значение воды в счёт не входит.
- `bonusSteps` показывается прямо на источнике как `+N`.
- Все клетки и воды заданы заранее.
- Генератор обязан прогнать solver и подтвердить хотя бы один выигрышный маршрут.
- Solver также проверяет kill-критерий: лучший маршрут не должен сводиться к последовательному выбору ближайшей воды по кратчайшему пути.
- Runtime RNG отсутствует.

Кривая по пяти уровням:

1. **Обучение движению.** Один источник воды, запас явно достаточен. На прямом пути есть несколько клеток ценности `1`. Игрок учится: шаг тратит ресурс, вода закрепляет ветку.
2. **Обучение ставке.** Два пути к одной воде: короткий бедный и немного более длинный с клетками `2–3`. Оба безопасны, но длинный выгоднее.
3. **Первый настоящий выбор.** Два источника воды. Ближайший легко достижим, но даёт маленький бонус; более дальний маршрут позволяет набрать больше очков и улучшает позицию для следующего участка.
4. **Давление.** Минимум три воды и несколько богатых боковых клеток. Один соблазнительный крюк приводит к осыпанию, если взять его слишком рано. После осыпания мёртвые клетки реально меняют доступные маршруты.
5. **Проверка концепта.** Минимум четыре воды. Есть не меньше трёх решений вида «безопасно закрепиться сейчас или рискнуть ради ценности». Оптимальный маршрут хотя бы один раз проходит не к ближайшей воде.

# 7. Визуал

- Поле: прямоугольная клеточная сетка.
- Корень: крупная закреплённая форма в нижней части поля.
- Активная ветка: тонкий непрерывный отросток между центрами клеток; активные клетки визуально светятся.
- Закреплённая ветка: становится плотной и неподвижной.
- Мёртвая ветка: осыпается короткой анимацией; клетки остаются визуально сухими/пустыми и недоступными.
- Источник воды: отдельная форма с крупным `+N`, где `N` — бонус шагов.
- Ценные клетки: форма/маркер ценности `1`, `2` или `3`; игровые цвета берутся только из `tokens.css`.
- Выбрано: отдельного selected-state нет — направление задаётся свайпом.
- Выполнено: новый сегмент ветки быстро вырастает в соседнюю клетку.
- Главный payoff: при достижении воды вся активная ветка одним импульсом закрепляется, `pendingScore` перелетает в общий счёт, а запас шагов увеличивается.
- Ошибка: при последнем шаге без воды активная ветка дрожит и рассыпается назад до закреплённой точки; должно быть понятно за секунду, что потеряна именно незакреплённая часть.
- HUD: `Очки: X / target`, `Шаги: N`, `В ветке: +pendingScore`.

# 8. Онбординг

1. Проведи пальцем — ветка растёт на одну клетку.
2. Каждый шаг тратит 1 из запаса.
3. Очки на ветке пока не сохранены.
4. Дойди до воды, чтобы закрепить ветку и забрать очки.
5. Вода даёт указанный бонус шагов.
6. Если шаги закончатся раньше воды, незакреплённая ветка осыплется.

Кнопка `?` показывает только краткое правило из п.2 и не повторяет пошаговое обучение.

# 10. Метрики и события

Аналитикой владеет общий shell. Механика **не вызывает PostHog напрямую** —
она сообщает о происходящем через контракт `MechanicHost`.

- Shell сам логирует `game_open`, `help_open`, `level_start`, `level_win`,
  `level_5_complete`, `rating_submit`, `comment_submit`.
- Hub отдельно логирует `hub_impression`, `hub_click`, `teaser_click`.
- D1/D7 и повторные сессии PostHog считает сам по persisted distinct_id и
  `game_open` — отдельные события для них не нужны.
- `retry` шлёт shell после fail-попапа; `level_5_complete` отдельно не
  эмитится, он выводится из `level_win` пятого уровня.

Ниже описано, **когда** наступает каждое событие. Механика при этом вызывает
только `onFirstAction()`, `onFail('<код>')` и `onComplete()` — остальное
отправляет shell.

- `first_action` — первый валидный свайп, который выращивает ветку на соседнюю клетку.
- `level_start` — при входе на уровень с номером уровня.
- `level_win` — когда после закрепления у воды `bankedScore >= targetScore`.
- `level_fail` — когда победа не достигнута и из текущей закреплённой точки нет ни одного достижимого неиспользованного источника воды; `reason: 'no_reachable_water'`.
- `retry` — повторная попытка того же уровня после `level_fail`.
- `level_5_complete` отдельно не эмитится.

Kill-критерий концепта: если solver показывает, что стратегия «всегда идти к ближайшей воде кратчайшим путём» оптимальна или эквивалентна оптимальной на всех пяти уровнях, концепт хоронится.

Онлайн-резерв: читаемость, доходимость до 5 уровня, возврат D1. Если критерий эксперимента не сработал — концепт не чинится.

# 12. Профиль реализации

Относится к фабрике, а не к игровой идее: сменится фабрика — перепишется
только этот раздел.

**Контракт.** Механика реализует `MechanicHost` из `src/shell-contract.ts` и
вызывает `onFirstAction()`, `onComplete()`, `onFail(reason)`, `onExit()`.
PostHog напрямую не трогает — см. раздел 10.

**`game.config.ts`.** `id` совпадает со `slug` из шапки, `title` — с
`title_ru`, `tagline` — короткая строка под названием, `levelCount: 5`,
`version` и `onboarding.version` поднимаются при изменении контента и правил
соответственно. Токены аналитики и ключ обратной связи копируются из
`games/tap-targets/game.config.ts`.

**`data-testid`.** Обязателен на каждом интерактивном элементе — e2e ищет
строго по ним. Существующая конвенция: `game-surface` — контейнер механики,
`mechanic-hud` — HUD с атрибутом `data-remaining`.

**Анимация.** Payoff строится из эффектов `render-kit`: `punch`,
`invalidShake`, `successFlash`, `fadeCollapse`, `cameraShake`, `moveTo`.
Если нужного нет — сказать здесь, а не изобретать свой во время сборки.
_Какие именно эффекты нужны этой игре — не записано._
