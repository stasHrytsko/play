# 2. Цель и условия

Правила уровня — текст для кнопки `?`:

На каждом блоке есть стрелка. Блок можно сдвинуть только на одну клетку в сторону стрелки. После успешного сдвига стрелка именно этого блока поворачивается на 90° по часовой стрелке. Если блок делает шаг за границу через выход, он покидает поле. Выведи все блоки так, чтобы не запереть оставшиеся.

- Условие ПОБЕДЫ: на поле не осталось ни одного блока.
- Условие ПОРАЖЕНИЯ: на поле ещё есть блоки, но ни один из них не может сделать легальный сдвиг в направлении своей текущей стрелки.
- Runtime RNG отсутствует. Стартовые позиции блоков, стартовые направления и выходы заранее зафиксированы в данных уровня.

# 3. Правила

1. На старте уровня движок загружает сетку, блоки, их стартовые направления и клетки-выходы.
2. Каждый блок занимает ровно одну клетку.
3. У каждого блока есть текущее направление: `up`, `right`, `down` или `left`.
4. Для каждого блока интерфейс показывает его текущую стрелку и маленький preview следующего направления после успешного хода.
5. Игрок свайпает выбранный блок в сторону его текущей стрелки.
6. Свайп в любую другую сторону ничего не делает и не считается ходом.
7. Валидный сдвиг перемещает блок ровно на одну соседнюю клетку по направлению стрелки.
8. Сдвиг внутрь поля разрешён только если целевая клетка свободна.
9. Если целевая клетка занята другим блоком, сдвиг не происходит и не считается ходом.
10. Если следующий шаг ведёт за границу поля не через выход, сдвиг не происходит и не считается ходом.
11. Если следующий шаг ведёт за границу через выход, блок покидает поле.
12. После любого успешного сдвига внутри поля стрелка только что сдвинутого блока поворачивается на 90° по часовой стрелке.
13. Если блок покинул поле через выход, его направление больше не обновляется, потому что блок удалён.
14. Стрелки остальных блоков не меняются.
15. Один успешный сдвиг одного блока считается одним ходом.
16. После каждого успешного хода движок проверяет победу по п.2.
17. Если блоки остались, движок проверяет существование хотя бы одного легального сдвига среди всех блоков.
18. Если легальных сдвигов нет, фиксируется поражение по п.2.
19. Блоки нельзя толкать, обменивать местами, вращать вручную или перемещать более чем на одну клетку за ход.
20. Игрок не может пропустить ход.

# 4. Состояние уровня

```ts
type Dir = 'up' | 'right' | 'down' | 'left';

type BlockState = {
  id: string;
  x: number;
  y: number;
  dir: Dir;
};

type GameState = {
  blocks: BlockState[];
  moves: number;
  status: 'playing' | 'won' | 'failed';
};
```

Выходы и размеры поля относятся к неизменяемым данным уровня и между ходами не меняются.

# 5. Ввод

```ts
{
  type: 'swipe';
  targetId: string;
  dir: 'up' | 'right' | 'down' | 'left';
}
```

Один тип ввода — свайп блока.

`targetId` указывает на конкретный блок. Движок отдельно проверяет, совпадает ли `dir` свайпа с текущим направлением этого блока.

# 6. Контент уровня

Пример параметров одного уровня в `levels.json`:

```json
{
  "id": 1,
  "grid": { "w": 6, "h": 6 },
  "exits": [
    { "x": 5, "y": 2, "dir": "right" },
    { "x": 2, "y": 0, "dir": "up" }
  ],
  "blocks": [
    { "id": "b1", "x": 3, "y": 2, "dir": "right" },
    { "id": "b2", "x": 2, "y": 2, "dir": "up" },
    { "id": "b3", "x": 3, "y": 3, "dir": "left" }
  ]
}
```

Следующее направление не хранится отдельно: оно всегда вычисляется детерминированно как поворот текущего направления на 90° по часовой стрелке.

Генератор:

1. Создаёт фиксированное поле и набор выходов.
2. Расставляет блоки и стартовые направления.
3. Солвер проверяет, что существует хотя бы один путь к победе.
4. Солвер также оценивает долю альтернативных порядков, которые приводят к победе.
5. Уровни, где порядок почти не имеет значения, отбрасываются.
6. Валидные уровни сохраняются в `levels.json`.
7. Runtime RNG отсутствует.

Кривая по пяти уровням:

1. **Уровень 1 — понять поворот.** 3 блока, 2 выхода. Первый блок можно вывести двумя движениями; после первого движения игрок явно видит смену стрелки.
2. **Уровень 2 — понять, что стрелки независимы.** 4 блока. Нужно двигать два блока по очереди; поворот одного никак не влияет на остальные.
3. **Уровень 3 — первый настоящий выбор.** 5 блоков. Два блока имеют легальные ходы, но ранний ход одним из них меняет направление так, что позже перекрывает маршрут другого.
4. **Уровень 4 — давление.** 6 блоков, 3 выхода. Минимум два состояния, где локально безопасный сдвиг создаёт будущий тупик после поворота стрелки.
5. **Уровень 5 — проверка концепта.** 7 блоков, 3 выхода. Минимум три решения должны зависеть от связки `текущее направление → следующее направление` конкретного блока. Случайный или почти любой порядок не должен проходить уровень.

# 7. Визуал

- Поле: квадратная парковочная сетка с крупными блоками по одной клетке.
- Каждый блок имеет крупную основную стрелку текущего направления.
- Рядом с основной стрелкой показывается маленькая вторичная стрелка следующего направления именно этого блока.
- Никакого глобального индикатора поворота нет.
- Выбрано: при начале свайпа блок слегка приподнимается, допустимая соседняя клетка получает ghost-позицию.
- Выполнено: блок снапается на соседнюю клетку, затем его основная стрелка коротко поворачивается на четверть оборота; preview одновременно обновляется.
- Выход: блок, сделавший шаг через выход, быстро выезжает за границу поля и исчезает.
- Ошибка: при заблокированном направлении блок делает короткий толчок в сторону препятствия и возвращается на место; ход не тратится.
- Payoff-момент: успешный сдвиг + мгновенный поворот стрелки должны читаться глазами меньше чем за секунду.
- HUD: `Осталось: N`. Дополнительного счётчика ходов нет.

# 8. Онбординг

1. Каждый блок едет только по своей большой стрелке.
2. Свайпни блок в сторону стрелки — он сдвинется на одну клетку.
3. После хода его стрелка повернётся на четверть вправо.
4. Маленькая стрелка показывает, куда блок сможет ехать следующим ходом.
5. Через выход блок покидает поле.
6. Выведи все блоки, не заперев их.

Кнопка `?` показывает только краткое правило из п.2 и не повторяет обучение.

# 10. Метрики и события

Аналитикой владеет общий shell. Механика **не вызывает PostHog напрямую** —
она сообщает о происходящем через контракт `MechanicHost`.

- Shell сам логирует `game_open`, `help_open`, `level_start`, `level_win`,
  `level_5_complete`, `rating_submit`, `comment_submit`.
- Hub отдельно логирует `hub_impression`, `hub_click`, `teaser_click`.
- D1/D7 и повторные сессии PostHog считает сам по persisted distinct_id и
  `game_open` — отдельные события для них не нужны.
- `retry` шлёт shell после fail-попапа; `level_5_complete` отдельно не
  эмитится, он выводится из `level_win` пятого уровня.

Ниже описано, **когда** наступает каждое событие. Механика при этом вызывает
только `onFirstAction()`, `onFail('<код>')` и `onComplete()` — остальное
отправляет shell.

- `first_action` — первый успешный свайп блока в направлении его текущей стрелки.
- `level_start` — при входе на каждый уровень, с номером уровня.
- `level_win` — когда после разрешения хода на поле не осталось блоков.
- `level_fail` — когда блоки остаются, но ни у одного нет легального сдвига; `reason: 'no_legal_move'`.
- `retry` — повтор того же уровня после `level_fail`.
- `level_5_complete` отдельно не эмитится.

Kill-критерий концепта: если любой порядок сдвигов выводит все блоки более чем в 80% сгенерированных уровней, концепт хоронится.

Онлайн-резерв: читаемость, доходимость до 5 уровня, возврат D1. Если критерий не сработал — концепт не чинится.

# 12. Профиль реализации

Относится к фабрике, а не к игровой идее: сменится фабрика — перепишется
только этот раздел.

**Контракт.** Механика реализует `MechanicHost` из `src/shell-contract.ts` и
вызывает `onFirstAction()`, `onComplete()`, `onFail(reason)`, `onExit()`.
PostHog напрямую не трогает — см. раздел 10.

**`game.config.ts`.** `id` совпадает со `slug` из шапки, `title` — с
`title_ru`, `tagline` — короткая строка под названием, `levelCount: 5`,
`version` и `onboarding.version` поднимаются при изменении контента и правил
соответственно. Токены аналитики и ключ обратной связи копируются из
`games/tap-targets/game.config.ts`.

**`data-testid`.** Обязателен на каждом интерактивном элементе — e2e ищет
строго по ним. Существующая конвенция: `game-surface` — контейнер механики,
`mechanic-hud` — HUD с атрибутом `data-remaining`.

**Анимация.** Payoff строится из эффектов `render-kit`: `punch`,
`invalidShake`, `successFlash`, `fadeCollapse`, `cameraShake`, `moveTo`.
Если нужного нет — сказать здесь, а не изобретать свой во время сборки.
