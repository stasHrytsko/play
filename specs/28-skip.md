# 1. Паспорт концепта

Дополнительно:
- Отличие от обычной сортировки: игрок управляет не только местом предмета, но и его временем появления — один раз может отложить конкретный предмет в конец фиксированной очереди.
- Runtime RNG: нет.

**Почему kill-критерий именно такой.** Идея — единственный пропуск: один предмет можно отложить в конец очереди, и всё решение в том, когда потратить эту единственную отсрочку. Если жадное «клади сразу, если можешь» выигрывает большинство уровней, пропуск не нужен ни разу — остаётся обычная сортировка по цветам. Провал по критерию означает, что твист не создаёт решения: это свойство порядка очереди относительно числа активных ящиков, а не их вместимости.

# 2. Цель и условия

Правила уровня — текст для кнопки `?`:

Перед тобой фиксированная очередь цветных предметов и несколько активных ящиков. Пустой ящик принимает любой цвет; после первого предмета он закрепляется за этим цветом и принимает только такой же. Когда ящик заполнен, он уезжает и на его месте появляется новый пустой. Текущий предмет можно либо положить в подходящий ящик, либо один раз отправить в конец очереди. Повторно пропустить тот же предмет нельзя. Разбери всю очередь и закрой все ящики.

- Условие ПОБЕДЫ: очередь пуста, все предметы размещены, все заполненные ящики закрыты и на поле не осталось частично заполненных ящиков.
- Условие ПОРАЖЕНИЯ: текущий предмет нельзя положить ни в один активный ящик, и этот предмет уже был пропущен раньше.
- Дополнительного лимита ходов или общего лимита пропусков нет.
- Каждый предмет можно пропустить максимум один раз.
- Порядок исходной очереди полностью задан уровнем.
- Runtime RNG отсутствует.

# 3. Правила

1. На старте уровень создаёт фиксированную очередь предметов и фиксированное число активных ящиков.
2. Каждый предмет имеет `color` и флаг `skippedOnce`.
3. Каждый активный ящик имеет одинаковую вместимость `boxCapacity`.
4. Пустой ящик не закреплён за цветом.
5. Когда игрок кладёт предмет в пустой ящик, ящик закрепляется за цветом этого предмета.
6. Непустой ящик принимает только предметы своего цвета.
7. Один предмет занимает ровно одно место в ящике.
8. Игрок работает только с первым предметом очереди.
9. Для текущего предмета доступны два типа действий: `place` или `skip`.
10. `place` валиден, если выбранный ящик пустой либо уже закреплён за цветом текущего предмета и в нём есть свободное место.
11. При валидном `place` текущий предмет удаляется из начала очереди и добавляется в выбранный ящик.
12. Если после `place` ящик достиг `boxCapacity`, он считается завершённым, все его предметы уходят с поля, а ящик мгновенно заменяется новым пустым ящиком.
13. Новый пустой ящик не меняет порядок оставшейся очереди.
14. `place` в ящик другого цвета или в заполненный ящик невалиден и ничего не меняет.
15. `skip` валиден только если у текущего предмета `skippedOnce = false`.
16. При валидном `skip` текущий предмет удаляется из начала очереди, получает `skippedOnce = true` и добавляется в самый конец очереди.
17. `skip` не меняет состояние ящиков.
18. Предмет с `skippedOnce = true` нельзя пропустить повторно.
19. После каждого валидного действия новым текущим предметом становится первый предмет обновлённой очереди.
20. Если очередь пуста, движок проверяет состояние ящиков.
21. Если очередь пуста и все активные ящики пустые, фиксируется `level_win`.
22. Уровни обязаны быть сконструированы так, чтобы суммарное число предметов каждого цвета делилось на `boxCapacity`; финальные незакрываемые остатки не допускаются контентом.
23. Если текущий предмет нельзя положить ни в один активный ящик и он уже был пропущен, фиксируется `level_fail` с причиной `blocked_return`.
24. Если текущий предмет нельзя положить, но он ещё не был пропущен, единственное валидное действие — `skip`.
25. Никаких автоматических перестановок очереди, кроме явного `skip`, нет.
26. Все последствия действий полностью детерминированы.

# 5. Ввод

Два типа игрового ввода:

```ts
{ type: 'place'; itemId: string; boxId: string }
```

```ts
{ type: 'skip'; itemId: string }
```

Renderer отправляет `itemId` только для текущего первого предмета. Engine повторно валидирует, что предмет действительно первый в очереди и действие разрешено.

# 6. Контент уровня

Пример `levels.json`:

```json
{
  "id": 1,
  "boxCount": 3,
  "boxCapacity": 3,
  "queue": [
    { "id": "a", "color": "red" },
    { "id": "b", "color": "blue" },
    { "id": "c", "color": "yellow" },
    { "id": "d", "color": "red" },
    { "id": "e", "color": "green" },
    { "id": "f", "color": "red" },
    { "id": "g", "color": "blue" },
    { "id": "h", "color": "blue" },
    { "id": "i", "color": "green" },
    { "id": "j", "color": "green" },
    { "id": "k", "color": "yellow" },
    { "id": "l", "color": "yellow" }
  ]
}
```

Правила генерации:

- Очередь всегда фиксирована до старта уровня.
- Количество предметов каждого цвета кратно `boxCapacity`.
- Генератор обязан прогнать solver и подтвердить хотя бы одно решение.
- Solver учитывает выбор ящика для каждого `place` и возможность одного `skip` для каждого конкретного предмета.
- Уровень не принимается, если `skip` не требуется ни в одном оптимальном решении.
- Уровень не принимается, если единственный правильный ход определяется без просмотра хотя бы 2–3 следующих предметов очереди на уровнях 3–5.
- Уровень не принимается, если стратегия «всегда класть сразу, если есть валидный ящик» проходит уровень независимо от выбора пустого ящика.
- Никакого runtime RNG.

Кривая по пяти уровням:

1. **Обучение пропуску.** 2 ящика, вместимость 2, 2 цвета. Один предмет нужно один раз отправить назад, чтобы закрыть первый ящик.
2. **Первые занятые цвета.** 3 ящика, вместимость 3, 3–4 цвета. Игрок видит, что открывать новый цвет в последнем пустом ящике опасно.
3. **Первый настоящий выбор.** 3 ящика, 4 цвета. Текущий предмет можно разместить, но правильное решение — пропустить его, потому что ближайшие два предмета выгоднее закроют уже начатый ящик.
4. **Давление.** 3 ящика, 4–5 цветов. Не меньше двух предметов возвращаются после `skip`; неправильное использование пустого ящика приводит к `blocked_return` через несколько ходов.
5. **Проверка концепта.** 3–4 ящика, 5 цветов. Есть несколько валидных размещений и минимум две осмысленные точки решения «взять сейчас или отложить»; solver подтверждает, что жадное размещение проигрывает хотя бы на одной ветке.

# 7. Визуал

- Верх/центр: горизонтальная или слегка изогнутая лента очереди; полностью видны текущий предмет и несколько следующих, остальные могут быть показаны компактнее.
- Текущий предмет визуально крупнее и отделён от очереди.
- Активные ящики расположены ниже; у каждого явно видны заполненные и свободные места.
- Пустой ящик нейтральный. После первого предмета получает визуальную маркировку цвета из `tokens.css`.
- Цвет предмета дублируется простой формой/иконкой, чтобы механика не зависела только от различения цветов.
- Валидный `place`: предмет быстро перелетает в ящик; при заполнении ящик закрывается с коротким `snap`, уезжает и заменяется пустым.
- `skip`: предмет уезжает по ленте вправо и появляется в хвосте; на нём появляется маленькая метка «уже пропущен».
- Невалидный ящик даёт короткий отказ без изменения состояния.
- Fail `blocked_return`: вернувшийся предмет подсвечивается, а все ящики показывают, почему не принимают его.
- HUD: количество предметов в очереди; отдельного счётчика общего лимита пропусков нет.

# 8. Онбординг

1. Бери только первый предмет очереди.
2. Положи его в пустой ящик или в ящик того же цвета.
3. Заполненный ящик уезжает и освобождает новый пустой.
4. Неудобный предмет можно один раз отправить в конец очереди.
5. Когда он вернётся, пропустить его ещё раз нельзя.
6. Разбери всю очередь и не забей все ящики несовместимыми цветами.

`?` повторяет только эти правила и не показывает решение текущего уровня.

# 9. Явно ВНЕ рамок

- Без меты, валют, коллекций, заданий, ежедневных бонусов, рекламы и IAP.
- Без runtime RNG.
- Давление ровно одно: ограниченное число активных ящиков.
- Твист ровно один: одноразовый перенос конкретного предмета в конец очереди.
- Без изменений баланса/уровней после публикации, кроме датированного критического бага.
- Нет общего лимита ходов.
- Нет таймера.
- Нет общего запаса пропусков поверх правила «один раз на предмет».
- Нет ручной перестановки предметов внутри очереди.
- Нельзя брать предмет не с начала очереди.
- Нет wildcard-предметов, универсальных ящиков, бомб, shuffle и undo.
- Нет предметов разного размера в первом прототипе: каждый предмет занимает один слот.

# 10. Метрики и события

Аналитикой владеет общий shell. Механика **не вызывает PostHog напрямую** —
она сообщает о происходящем через контракт `MechanicHost`.

- Shell сам логирует `game_open`, `help_open`, `level_start`, `level_win`,
  `level_5_complete`, `rating_submit`, `comment_submit`.
- Hub отдельно логирует `hub_impression`, `hub_click`, `teaser_click`.
- D1/D7 и повторные сессии PostHog считает сам по persisted distinct_id и
  `game_open` — отдельные события для них не нужны.
- `retry` шлёт shell после fail-попапа; `level_5_complete` отдельно не
  эмитится, он выводится из `level_win` пятого уровня.

Ниже описано, **когда** наступает каждое событие. Механика при этом вызывает
только `onFirstAction()`, `onFail('<код>')` и `onComplete()` — остальное
отправляет shell.

- `first_action` — первый валидный `place` или `skip` текущего предмета;
- `level_start` — при входе на каждый уровень;
- `level_win` — когда очередь пуста и все ящики закрыты/пусты;
- `level_fail` — при `blocked_return`;
- `retry` — при повторе после fail.

Диагностический payload для действий:

- `item_color`;
- `queue_position_before`;
- `action: 'place' | 'skip'`;
- `box_id` для `place`;
- `boxes_open_colors`;
- `queue_remaining`;
- `skips_used`.

`level_5_complete` отдельно не эмитится: фиксируется автоматически через `level_win` пятого уровня.

Онлайн-гейты как резерв:

- **Readability:** игрок понимает, что `skip` отправляет предмет именно в конец и доступен этому предмету только один раз.
- **Reach L5:** достаточная доля игроков доходит до пятого уровня.
- **D1:** возврат на следующий день.

Если kill-критерий срабатывает или гейты провалены — концепт хоронится, не чинится дополнительными системами.

# 11. Крайние случаи

- **Повторное то же действие** — повторный `skip` того же предмета невозможен: после первого у него `skippedOnce = true` (п.16, 18). Повторный `place` в тот же ящик — обычное действие, пока в нём есть место и цвет совпадает (п.10).
- **Действие мимо всего** — `place` в ящик другого цвета или в заполненный невалиден и ничего не меняет (п.14).
- **Действие невозможно** — если текущий предмет некуда положить и он уже был пропущен, фиксируется `level_fail` с причиной `blocked_return` (п.23). Если ещё не был — единственным валидным действием остаётся `skip` (п.24), то есть без выхода игрок не остаётся.
- **Ходов не осталось, победа не выполнена** — неприменимо: лимита ходов нет, уровень ограничен очередью. Пустая очередь при пустых ящиках — победа (п.21), а незакрываемых остатков контент не допускает (п.22).
- **Два объекта в одной позиции** — неприменимо: один предмет занимает ровно одно место в ящике (п.7).

# 12. Профиль реализации

Относится к фабрике, а не к игровой идее: сменится фабрика — перепишется
только этот раздел.

**Контракт.** Механика реализует `MechanicHost` из `src/shell-contract.ts` и
вызывает `onFirstAction()`, `onComplete()`, `onFail(reason)`, `onExit()`.
PostHog напрямую не трогает — см. раздел 10.

**`game.config.ts`.** `id` совпадает со `slug` из шапки, `title` — с
`title_ru`, `tagline` — короткая строка под названием, `levelCount: 5`,
`version` и `onboarding.version` поднимаются при изменении контента и правил
соответственно. Токены аналитики и ключ обратной связи копируются из
`games/tap-targets/game.config.ts`.

**`data-testid`.** Обязателен на каждом интерактивном элементе — e2e ищет
строго по ним. Существующая конвенция: `game-surface` — контейнер механики,
`mechanic-hud` — HUD с атрибутом `data-remaining`.

**Анимация.** Payoff строится из эффектов `render-kit`: `punch`,
`invalidShake`, `successFlash`, `fadeCollapse`, `cameraShake`, `moveTo`.
Если нужного нет — сказать здесь, а не изобретать свой во время сборки.
_Какие именно эффекты нужны этой игре — не записано._
