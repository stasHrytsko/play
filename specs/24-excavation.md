# 1. Паспорт концепта

- Название: Раскоп
- **Правило одной фразой:** Открывай плиты по подсказкам о соседних ловушках, собирай золото и решай, когда остановиться: 5 — пройдено, 7 — хороший результат, 9 — идеальный.
- Глагол: проба
- Давление: скрытая информация
- Твист: ставка
- **Целевая эмоция:** жадность — «я уже могу выйти, но вдруг смогу забрать ещё?»
- **Уровни:** генерируется
- **Солвер:** нужен
- Оценка: 21/30 — чит 4, мот 3, давл 4, payoff 5, произв 2, рынок 3

Дополнительно:
- Семейство: Reveal
- Отличие от аналога: Сапёр — риск после достижения минимальной цели становится добровольным; игрок сам решает, выйти или продолжить ради лучшего результата.
- TREND: нет
- Kill-критерий: если игрок, использующий числовые подсказки и логический вывод, выигрывает случайного игрока меньше чем на 20%, концепт хоронится.

# 2. Цель и условия

Правила уровня — текст для кнопки `?`:

Открывай плиты. Число на безопасной плите показывает, сколько ловушек находится в восьми соседних клетках. Под некоторыми безопасными плитами лежит золото. Каждая найденная золотая плита даёт `+1` золото и тоже показывает число соседних ловушек. Ловушка завершает попытку и сжигает всё золото этой попытки. Когда собрал 5 золота, можешь выйти и пройти уровень. Можешь продолжить: 7 золота — хороший результат, 9 — идеальный.

- Условие ПОБЕДЫ: игрок нажимает `Выйти`, имея `gold >= 5`, либо собирает `gold = 9`, после чего уровень завершается автоматически как идеальный результат.
- Результат уровня:
  - `5–6` золота при выходе → `passed`.
  - `7–8` золота при выходе → `good`.
  - `9` золота → `perfect`.
- Условие ПОРАЖЕНИЯ: игрок открывает клетку с ловушкой до завершения уровня. Накопленное золото этой попытки обнуляется, фиксируется `level_fail`.
- До `gold >= 5` кнопка `Выйти` недоступна.
- После `gold >= 5` игрок в любой момент может выйти без дополнительного риска.
- Hidden info полностью определяется уровнем до старта: позиции ловушек, золота и безопасных пустых клеток не меняются в runtime.
- Runtime RNG отсутствует.

# 3. Правила

1. На старте движок загружает сетку и заранее зафиксированное содержимое каждой закрытой клетки: `empty`, `gold` или `trap`.
2. Каждая клетка также получает заранее вычисленное число `adjacentTraps` от `0` до `8` — количество ловушек среди восьми соседей.
3. Все клетки стартуют закрытыми.
4. Игрок может тапнуть только закрытую клетку.
5. Тап по уже открытой клетке ничего не делает.
6. Если открытая клетка имеет тип `trap`, попытка немедленно заканчивается поражением.
7. При поражении `gold` текущей попытки становится `0`.
8. Если открытая клетка имеет тип `empty`, она становится открытой и показывает `adjacentTraps`.
9. Если открытая клетка имеет тип `gold`, она становится открытой, добавляет `+1` к `gold` и показывает `adjacentTraps`.
10. Золото нельзя собрать повторно: одна золотая клетка даёт `+1` только при первом открытии.
11. Автоматического flood-open для нулевых клеток нет: один тап всегда открывает ровно одну клетку. Это сохраняет правило «одна проба = одно решение».
12. До `gold < 5` кнопка `Выйти` заблокирована.
13. Когда `gold` впервые становится `5`, кнопка `Выйти` становится активной и остаётся активной до конца попытки.
14. При `gold = 5` или `6` игрок может выйти с результатом `passed`.
15. При `gold = 7` или `8` игрок может выйти с результатом `good`.
16. При `gold = 9` уровень немедленно завершается с результатом `perfect`; дополнительного подтверждения не требуется.
17. Если игрок после достижения 5 продолжает открывать клетки и попадает в ловушку, попытка считается проигранной целиком, даже если минимальная квота уже была достигнута.
18. Все числа на открытых безопасных клетках всегда правдивы и относятся к неизменяемой раскладке ловушек текущего уровня.
19. Никаких случайных перестановок содержимого после первого тапа нет.
20. Уровень должен быть сгенерирован так, чтобы существовал хотя бы один логически обоснованный путь до 5 золота без обязательного угадывания.
21. Для результатов 7 и 9 допускается возрастающий риск, но solver обязан оценить, насколько дальнейшее продвижение остаётся выводимым из видимых подсказок.

# 4. Состояние уровня

```ts
type CellKind = 'empty' | 'gold' | 'trap';
type CellStatus = 'closed' | 'open';

type CellState = {
  id: string;
  x: number;
  y: number;
  kind: CellKind;
  status: CellStatus;
  adjacentTraps: number;
};

type ResultGrade = 'none' | 'passed' | 'good' | 'perfect';

type GameState = {
  cells: CellState[];
  gold: number;
  exitUnlocked: boolean;
  openedCount: number;
  resultGrade: ResultGrade;
  status: 'playing' | 'won' | 'failed';
};
```

# 5. Ввод

Игровой ввод состоит из двух действий:

```ts
{ type: 'reveal'; cellId: string }
```

```ts
{ type: 'exit' }
```

- `reveal` открывает ровно одну закрытую клетку.
- `exit` валиден только при `gold >= 5`.
- Никаких свайпов, флагов и вторичных режимов ввода в прототипе нет.

# 6. Контент уровня

Пример `levels.json`:

```json
{
  "id": 1,
  "grid": { "w": 6, "h": 6 },
  "passGold": 5,
  "goodGold": 7,
  "perfectGold": 9,
  "cells": [
    { "x": 0, "y": 0, "kind": "empty" },
    { "x": 1, "y": 0, "kind": "gold" },
    { "x": 2, "y": 0, "kind": "trap" }
  ]
}
```

Правила контента:
- Пороги результата фиксированы для прототипа: `5 / 7 / 9`.
- Каждая золотая клетка даёт ровно `1` золото.
- В каждом уровне должно быть минимум `9` золотых клеток.
- Все ловушки и золотые клетки заданы до старта.
- Генератор обязан прогнать solver и подтвердить, что 5 золота можно получить без обязательного угадывания.
- Solver отдельно оценивает пути к 7 и 9 и измеряет, создаётся ли реальное решение «выйти сейчас или рискнуть дальше».
- Уровень отклоняется, если лучший ход слишком часто не отличим от случайного выбора.
- Runtime RNG отсутствует.

Кривая по пяти уровням:

1. **Обучение числам.** Небольшое поле. Мало ловушек. До первых 5 золотых клеток существует почти линейная цепочка выводов. После 5 сразу показывается активная кнопка `Выйти`.
2. **Обучение ставке.** После 5 остаётся короткий безопасно выводимый путь до 7 и заметно более рискованный путь к 9.
3. **Первый настоящий выбор.** Несколько закрытых зон с разной плотностью ловушек. До 5 можно дойти логикой, после 5 минимум два направления имеют разный риск и потенциальную награду.
4. **Давление.** Больше неоднозначных границ. До 7 всё ещё существует сильный логический маршрут, но попытка дойти до 9 требует последовательности точных выводов и хотя бы одного решения между несколькими потенциально выгодными зонами.
5. **Проверка концепта.** Игрок гарантированно может пройти на 5 при хорошем чтении поля, но 7 и особенно 9 должны создавать реальную добровольную ставку. Solver подтверждает, что логический игрок заметно превосходит случайного и что решение продолжать после 5 не всегда одинаково выгодно.

# 7. Визуал

- Поле: прямоугольная сетка каменных плит в комнате гробницы.
- Закрытая клетка: цельная плита без информации о содержимом.
- Открытая пустая клетка: углубление/камень с крупным числом `0–8`.
- Открытая золотая клетка: золотой объект + то же числовое значение соседних ловушек.
- Ловушка: резкий короткий reveal с понятным символом опасности и немедленным fail-state.
- Числа должны читаться без зависимости только от цвета.
- После нахождения золота счётчик быстро увеличивается `4 → 5`, и при достижении 5 кнопка `Выйти` визуально активируется.
- HUD: `Золото X / 9` и шкала с отметками `5 Пройдено`, `7 Хорошо`, `9 Идеально`.
- После 5 над кнопкой выхода коротко появляется подсказка: `Можно выйти`.
- После 7 меняется только статус результата; никаких мета-наград не показывается.
- При 9 — короткий сильный payoff и автоматическое завершение уровня.

# 8. Онбординг

1. Тапни плиту, чтобы открыть её.
2. Число показывает, сколько ловушек находится рядом по восьми соседним клеткам.
3. Золото безопасно: оно даёт `+1` и тоже показывает число ловушек рядом.
4. Собери 5 золота — после этого уже можно выйти и пройти уровень.
5. Продолжишь до 7 — получишь хороший результат; до 9 — идеальный.
6. Откроешь ловушку — потеряешь всё золото этой попытки.

`?` повторяет правила, но не подсказывает конкретный безопасный ход.

# 9. Явно ВНЕ рамок

- Нет мета-прогрессии, валют, коллекций, квестов, daily bonus, рекламы и IAP.
- Золото существует только внутри текущего уровня и не переносится между уровнями.
- Нет runtime RNG.
- Содержимое всех плит фиксируется до старта уровня.
- Давление одно: скрытая информация.
- Твист один: добровольная ставка после достижения минимальной цели.
- Нет флагов, мин, обезвреживания, инструментов, жизней, щитов и бустеров.
- Нет таймера реального времени и общего лимита ходов.
- Нет автоматического раскрытия пустых областей.
- Пороговые результаты `5 / 7 / 9` — часть одной попытки, а не отдельная мета-система звёзд.
- После публикации баланс и раскладка уровня не меняются, кроме датированного критического бага.

# 10. Метрики и события

Shell логирует стандартные события:
- `game_open`
- `hub_impression`
- `hub_click`
- `teaser_click`
- `help_open`
- `more_yes`
- `session_2`
- `return_d1`
- `return_d7`

Общие поля: `game_id`, `level_id`, `session_id`, `attempt_id`, `timestamp`.

Механика вызывает:
- `first_action` — первый `reveal`.
- `level_start`.
- `reveal` — `cell_id`, `cell_kind`, `adjacent_traps`, `gold_before`, `gold_after`.
- `exit_unlocked` — при первом достижении `gold = 5`.
- `exit_pressed` — `gold`, `result_grade`.
- `level_win` — `gold`, `result_grade`, `opened_count`.
- `level_fail` — `reason: trap`, `gold_before_fail`, `opened_count`.
- `retry`.
- `level_5_complete` автоматически считается через победу уровня 5, отдельно не эмитится.

Резервные online-gates:
- Игроки понимают значение чисел без дополнительного объяснения после первого уровня.
- Большинство игроков способны достигнуть 5 золота не случайным перебором.
- Доля игроков, которые после 5 добровольно продолжают хотя бы один раз, достаточна для проверки твиста.
- Логический игрок превосходит случайного минимум на 20% по вероятности успешного результата на сопоставимых уровнях.

Если критерий не проходит — концепт хоронится, а не чинится бесконечным балансом.
