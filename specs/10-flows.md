# 1. Паспорт концепта

Поля паспорта — в шапке раздела 0.

**Почему kill-критерий именно такой.** Идея в том, что каждый поворот оплачивается шагом воды: возиться нельзя, путь приходится строить впереди потока теми ходами, что есть. Если правильный поворот очевиден почти всегда, выбора нет — остаётся исполнение, «тапни по очевидной трубе», а вода лишь задаёт темп. Провал по критерию означает, что растущая угроза не порождает решений: это свойство самой конструкции уровней, потому что очевидная раскладка остаётся очевидной при любом размере сетки.

# 2. Цель и условия

Правила уровня — текст для кнопки `?`:

На поле лежат сегменты труб. Нажимай на сегмент, чтобы повернуть его на 90° по часовой стрелке. После каждого успешного поворота вода продвигается ровно на одну клетку по текущему соединению труб. Сегмент, в который уже пришла вода, больше нельзя поворачивать. Доведи воду от источника до слива. Если вода упирается в стену, край поля или неподходящее соединение — проигрыш.

- Условие ПОБЕДЫ: вода после очередного продвижения входит в клетку слива через соединённый с ним вход.
- Условие ПОРАЖЕНИЯ: после действия игрока вода должна продвинуться, но из текущей заполненной клетки нет валидного соединённого выхода в соседнюю клетку, либо соседняя труба не имеет входа с противоположной стороны.
- Других условий поражения нет.
- Runtime RNG отсутствует. Типы сегментов, их стартовые ориентации, источник и слив заранее зафиксированы уровнем.

# 3. Правила

1. На старте уровня движок загружает клеточную сетку, источник, слив и фиксированный набор сегментов труб с их стартовыми ориентациями.
2. Вода начинает в клетке источника.
3. Клетка источника сразу считается заполненной водой и больше не может поворачиваться.
4. Игрок может тапнуть по любому незаполненному сегменту трубы.
5. Валидный тап поворачивает выбранный сегмент ровно на 90° по часовой стрелке.
6. Тап по уже заполненному водой сегменту ничего не меняет и не считается ходом.
7. Тап по источнику или сливу ничего не меняет и не считается ходом.
8. После каждого валидного поворота увеличивается счётчик `moves` на 1.
9. Сразу после поворота вода обязана продвинуться ровно на одну соседнюю клетку.
10. Направление движения воды определяется единственным открытым выходом из текущей заполненной клетки, который продолжает путь вперёд.
11. Если из текущей клетки нет открытого выхода, фиксируется поражение по п.2.
12. Если открытый выход ведёт за границу поля, фиксируется поражение по п.2.
13. Если выход ведёт в соседний сегмент, но у него нет входа с противоположной стороны, фиксируется поражение по п.2.
14. Если соединение корректно, вода входит в соседний сегмент.
15. Сегмент, в который вошла вода, помечается заполненным и больше не может вращаться.
16. Если вода входит в клетку слива через его разрешённый вход, фиксируется победа по п.2.
17. Если вода вошла в обычный сегмент, управление возвращается игроку.
18. Вода не двигается сама по себе между действиями игрока.
19. Игрок не может пропустить ход.
20. Игрок не может вращать сегмент против часовой стрелки одним действием.
21. Чтобы изменить ориентацию на 180° или 270°, игрок должен сделать несколько отдельных тапов; каждый такой тап отдельно продвигает воду на одну клетку.
22. Заполненные водой сегменты остаются зафиксированными до конца попытки.
23. Все результаты полностью детерминированы текущим состоянием уровня и действием игрока.

Источник и слив хранятся в неизменяемом описании уровня.

# 5. Ввод

Один тип игрового ввода — тап по сегменту:

```ts
{
  type: 'tap';
  targetId: string;
}
```

Один валидный тап = один поворот на 90° по часовой стрелке = одно продвижение воды на одну клетку.

# 6. Контент уровня

Пример `levels.json`:

```json
{
  "id": 1,
  "grid": { "w": 6, "h": 7 },
  "source": { "x": 0, "y": 3, "out": "right" },
  "drain": { "x": 5, "y": 1, "in": "left" },
  "pipes": [
    { "id": "p1", "x": 1, "y": 3, "kind": "straight", "rotation": 90 },
    { "id": "p2", "x": 2, "y": 3, "kind": "corner", "rotation": 0 },
    { "id": "p3", "x": 2, "y": 2, "kind": "straight", "rotation": 0 }
  ]
}
```

Правила контента:

- Уровень полностью фиксирован до публикации.
- Runtime RNG отсутствует.
- Генератор создаёт поле, затем solver подтверждает хотя бы один выигрышный порядок поворотов.
- Solver обязан учитывать, что каждый отдельный поворот немедленно двигает воду на одну клетку.
- Генератор отбраковывает уровни, где более 90% состояний имеют единственный очевидный полезный тап.
- Уровень должен содержать хотя бы один момент, где игроку выгодно поворачивать сегмент не прямо перед водой, а дальше по маршруту.

Кривая по пяти уровням:

1. **Обучение.** Короткий путь из 5–6 сегментов. Почти все трубы уже правильно ориентированы. Игрок один-два раза поворачивает ближайший сегмент и видит цикл `тап → вода продвинулась`.
2. **Обучение опережению.** Путь длиннее. Есть два подряд неправильно ориентированных сегмента, поэтому один из них нужно подготовить заранее, пока вода ещё далеко.
3. **Первый настоящий выбор.** Появляется развилка с двумя возможными направлениями. Один маршрут короче, но требует нескольких поворотов подряд; другой длиннее, зато легче подготовить заранее.
4. **Давление.** Больше поворотов возле текущего фронта воды. Несколько сегментов можно исправить только до того, как вода займёт соседнюю клетку и закроет к ним доступ по времени.
5. **Проверка концепта.** Поле содержит минимум три ситуации, где игрок должен решить, крутить ближайший сегмент или заранее подготовить более дальний. Победа требует планирования на несколько ходов вперёд.

# 7. Визуал

- Поле: клеточная сетка с отдельными геометрическими сегментами труб.
- Цвета сегментов, воды, фона и состояний берутся из `tokens.css`.
- Источник: отдельная форма с направлением выхода.
- Слив: отдельная форма с направлением входа.
- Незаполненная труба: статичный сегмент с хорошо читаемыми отверстиями.
- Заполненная труба: визуально содержит воду и выглядит зафиксированной.
- Выбрано: при тапе сегмент быстро поворачивается на 90°.
- Выполнено: сразу после поворота вода одним коротким импульсом переходит в следующую клетку.
- Ошибка: если соединение не совпало, вода доходит до края текущего сегмента и коротко ударяется в закрытый конец; затем показывается fail.
- Главный payoff: последовательность `поворот → вода прошла дальше` должна читаться глазами меньше чем за секунду.
- HUD: `До слива: N клеток`, `Ходы: N`.
- Дополнительно на поле явно видно направление, куда вода пойдёт следующим шагом из текущего сегмента.

# 8. Онбординг

1. Нажми на трубу, чтобы повернуть её на 90°.
2. После каждого твоего поворота вода идёт на одну клетку вперёд.
3. Трубу с водой больше нельзя поворачивать.
4. Подготовь путь заранее, пока вода не дошла до него.
5. Если соединение не совпадёт, вода упрётся в тупик и ты проиграешь.
6. Доведи воду до слива.

Кнопка `?` показывает только правило из п.2.

# 10. Метрики и события

Аналитикой владеет общий shell. Механика **не вызывает PostHog напрямую** —
она сообщает о происходящем через контракт `MechanicHost`.

- Shell сам логирует `game_open`, `help_open`, `level_start`, `level_win`,
  `level_5_complete`, `rating_submit`, `comment_submit`.
- Hub отдельно логирует `hub_impression`, `hub_click`, `teaser_click`.
- D1/D7 и повторные сессии PostHog считает сам по persisted distinct_id и
  `game_open` — отдельные события для них не нужны.
- `retry` шлёт shell после fail-попапа; `level_5_complete` отдельно не
  эмитится, он выводится из `level_win` пятого уровня.

Ниже описано, **когда** наступает каждое событие. Механика при этом вызывает
только `onFirstAction()`, `onFail('<код>')` и `onComplete()` — остальное
отправляет shell.

- `first_action` — первый валидный тап по незаполненному сегменту трубы.
- `level_start` — при входе на каждый уровень, с номером уровня.
- `level_win` — когда вода входит в слив через корректное соединение.
- `level_fail` — когда после хода вода не может перейти в следующую клетку; `reason: 'dead_end'`.
- `retry` — повтор того же уровня после `level_fail`.
- `level_5_complete` отдельно не эмитится.

Kill-критерий концепта: если в более чем 90% ходов лучший поворот очевиден и игрок почти всегда просто чинит ближайшую к воде трубу, концепт хоронится.

Онлайн-резерв: читаемость, доходимость до 5 уровня, возврат D1. Если критерий не сработал — концепт не чинится.

# 11. Крайние случаи

- **Повторный тап по тому же сегменту** — обычный ход: ещё 90° и ещё одно продвижение воды (п.5, 9). Это и есть цена поворота на 180° — два хода и две клетки воды (п.21).
- **Тап мимо всего** — по пустому месту или HUD — не ход, вода не двигается (п.18).
- **Действие невозможно** — тап по заполненному сегменту, источнику или сливу ничего не меняет и ходом не считается (п.6–7). Если незаполненных сегментов не осталось вовсе, а вода ещё не в сливе, ход сделать нечем и вода без хода не пойдёт — такая позиция фиксируется как поражение немедленно, иначе уровень завис бы без исхода.
- **Ходов не осталось, победа не выполнена** — неприменимо: лимита ходов нет. Поражение наступает по разрыву пути — нет выхода, выход за границу или несостыковка (п.11–13).
- **Два объекта в одной позиции** — неприменимо: клетка содержит ровно один сегмент, сегменты не перемещаются.

# 12. Профиль реализации

Относится к фабрике, а не к игровой идее: сменится фабрика — перепишется
только этот раздел.

**Контракт.** Механика реализует `MechanicHost` из `src/shell-contract.ts` и
вызывает `onFirstAction()`, `onComplete()`, `onFail(reason)`, `onExit()`.
PostHog напрямую не трогает — см. раздел 10.

**`game.config.ts`.** `id` совпадает со `slug` из шапки, `title` — с
`title_ru`, `tagline` — короткая строка под названием, `levelCount: 5`,
`version` и `onboarding.version` поднимаются при изменении контента и правил
соответственно. Токены аналитики и ключ обратной связи копируются из
`games/tap-targets/game.config.ts`.

**`data-testid`.** Обязателен на каждом интерактивном элементе — e2e ищет
строго по ним. Существующая конвенция: `game-surface` — контейнер механики,
`mechanic-hud` — HUD с атрибутом `data-remaining`.

**Анимация.** Payoff строится из эффектов `render-kit`: `punch`,
`invalidShake`, `successFlash`, `fadeCollapse`, `cameraShake`, `moveTo`.
Если нужного нет — сказать здесь, а не изобретать свой во время сборки.
_Какие именно эффекты нужны этой игре — не записано._
