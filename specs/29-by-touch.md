# 1. Паспорт концепта

- Название: Наощупь
- **Правило одной фразой:** По цифрам на краях угадывай расположение ценных клеток, размещай фигуры раунда и забирай очки вовремя — если внутри раунда фигуры перестанут помещаться, незабранное сгорит.
- Глагол: размещение
- Давление: скрытая информация
- Твист: ставка
- **Целевая эмоция:** «кажется, я вычислил где ценное — рискну ещё одним раундом».
- **Уровни:** генерируется
- **Солвер:** нужен
- Оценка: сильный кандидат — необычное сочетание дедукции, block placement и push-your-luck; главный риск концепта — ощущение угадайки, если подсказок недостаточно.

Дополнительно:
- Семейство: Block puzzle / deduction.
- Отличие от аналога: фигуры не просто заполняют поле — они одновременно являются способом проверить гипотезу о скрытых ценных клетках.
- Kill-критерий: если solver показывает, что рациональная стратегия по видимым подсказкам обыгрывает случайное размещение менее чем на 20%, концепт хоронится как угадайка.

# 2. Цель и условия

Правила уровня — текст для кнопки `?`:

На поле 8×8 спрятаны ценные клетки. Числа слева и сверху показывают, сколько ценных клеток находится в каждой строке и колонке. В каждом раунде ты получаешь три фигуры и должен разместить все три. Клетки под фигурой открываются: ценная клетка даёт 1 очко, пустая просто занимает место. После завершения раунда можно забрать результат, если достигнута квота, или начать следующий раунд. Если внутри начатого раунда одну из оставшихся фигур уже нельзя поставить, попытка проиграна и незабранные очки сгорают.

- Условие ПОБЕДЫ: между раундами игрок нажимает `Забрать`, имея `score >= targetScore`.
- Условие ПОРАЖЕНИЯ: внутри уже начатого раунда для всех оставшихся фигур не существует последовательности валидных размещений, позволяющей завершить раунд; практическое событие fail срабатывает, когда текущий набор оставшихся фигур не имеет ни одного валидного размещения для следующего действия и раунд ещё не завершён.
- После начала раунда cash-out недоступен, пока все три фигуры этого раунда не размещены.
- Runtime RNG отсутствует.
- Карта ценностей и наборы фигур каждого раунда полностью заданы уровнем заранее.
- Скрытая информация касается только содержимого клеток; строковые и колонковые числа являются точными видимыми уликами и позволяют сужать расположение ценностей.

# 3. Правила

1. На старте движок загружает фиксированную сетку 8×8.
2. Каждая клетка заранее имеет скрытое содержимое `treasure` или `empty`.
3. В начале видны все числа строк и колонок.
4. Число строки равно общему количеству `treasure` в этой строке; число колонки — общему количеству `treasure` в этой колонке.
5. Уже открытые ценные клетки учитываются в исходном числе, но UI дополнительно показывает, сколько ценностей в этой строке/колонке ещё не найдено.
6. Уровень содержит фиксированную последовательность раундов.
7. Каждый раунд состоит ровно из трёх фигур.
8. Все три фигуры текущего раунда видимы одновременно до первого размещения этого раунда.
9. Игрок может размещать три фигуры текущего раунда в любом порядке.
10. Фигуру нельзя вращать.
11. Валидное размещение требует, чтобы все клетки фигуры находились внутри поля.
12. Валидное размещение требует, чтобы ни одна клетка фигуры не пересекалась с уже занятой клеткой.
13. Невалидный drag ничего не меняет и не считается действием.
14. После валидного размещения клетки фигуры становятся занятыми до конца попытки.
15. Для каждой только что занятой клетки движок открывает её скрытое содержимое.
16. За каждую впервые открытую `treasure` клетку `score` увеличивается на 1.
17. Открытая `empty` клетка очков не даёт.
18. Открытая клетка больше не является скрытой, но остаётся занятой фигурой.
19. После открытия клеток обновляются счётчики «осталось ценного» у затронутых строк и колонок.
20. Размещение одной фигуры не удаляет заполненные строки и не очищает поле.
21. После размещения фигура удаляется из списка текущего раунда.
22. Пока в текущем раунде остаются фигуры, кнопка `Забрать` заблокирована.
23. После каждого размещения движок проверяет, существует ли хотя бы одно валидное размещение для каждой из оставшихся фигур с учётом возможного порядка их размещения.
24. Если завершить текущий раунд уже невозможно, фиксируется `level_fail` с причиной `no_space`.
25. Когда размещены все три фигуры, раунд завершается и включается checkpoint.
26. На checkpoint, если `score < targetScore`, игрок обязан начать следующий раунд.
27. На checkpoint, если `score >= targetScore`, игрок может нажать `Забрать` и завершить уровень победой.
28. Вместо cash-out игрок может начать следующий заранее заданный раунд и продолжить увеличивать score.
29. После старта следующего раунда cash-out снова блокируется до размещения всех трёх фигур.
30. Если закончились все заданные раунды и `score >= targetScore`, уровень автоматически предлагает `Забрать`; если `score < targetScore`, фиксируется `level_fail` с причиной `quota_not_met`.
31. Все последствия каждого действия детерминированы текущим состоянием и данными уровня.

# 4. Состояние уровня

```ts
type Cell = {
  x: number;
  y: number;
  content: 'treasure' | 'empty';
  revealed: boolean;
  occupied: boolean;
};

type Shape = {
  id: string;
  cells: Array<{ x: number; y: number }>;
};

type Round = {
  id: string;
  shapes: Shape[]; // ровно 3
};

type GameState = {
  grid: Cell[][];
  rowTotals: number[];
  colTotals: number[];
  rowRemaining: number[];
  colRemaining: number[];
  rounds: Round[];
  roundIndex: number;
  remainingShapeIds: string[];
  score: number;
  targetScore: number;
  status: 'playing' | 'checkpoint' | 'won' | 'failed';
};
```

# 5. Ввод

Два типа игрового ввода:

```ts
{
  type: 'place_shape';
  shapeId: string;
  anchorX: number;
  anchorY: number;
}
|
{
  type: 'cash_out';
}
```

`place_shape` считается валидным только после повторной проверки engine на границы и пересечения.

`cash_out` валиден только в состоянии `checkpoint` и при `score >= targetScore`.

# 6. Контент уровня

Пример `levels.json`:

```json
{
  "id": 1,
  "grid": { "w": 8, "h": 8 },
  "targetScore": 5,
  "treasures": [
    [1,0], [3,0], [5,1], [2,2], [6,2],
    [0,4], [4,4], [7,5], [3,6], [6,7]
  ],
  "rounds": [
    {
      "id": "r1",
      "shapes": [
        { "id": "a", "cells": [[0,0],[1,0]] },
        { "id": "b", "cells": [[0,0],[0,1]] },
        { "id": "c", "cells": [[0,0]] }
      ]
    },
    {
      "id": "r2",
      "shapes": [
        { "id": "d", "cells": [[0,0],[1,0],[0,1]] },
        { "id": "e", "cells": [[0,0],[1,0],[2,0]] },
        { "id": "f", "cells": [[0,0],[0,1]] }
      ]
    }
  ]
}
```

Правила генерации:

- Поле всегда 8×8 в прототипе.
- Карта сокровищ генерируется до начала уровня и сохраняется как фиксированный content.
- Числа строк и колонок вычисляются из этой карты и никогда не врут.
- Наборы фигур и порядок раундов фиксируются в уровне.
- Генератор обязан прогнать solver и подтвердить существование хотя бы одного пути к `targetScore` с успешным cash-out.
- Уровень не принимается, если случайное валидное размещение достигает target почти так же часто, как solver.
- Уровень не принимается, если подсказки строк/колонок не сужают множество возможных карт после первых открытий.
- Уровень не принимается, если единственная стратегия — всегда ставить фигуру в строку/колонку с максимальным числом.
- Runtime RNG отсутствует.

Кривая по пяти уровням:

1. **Обучение подсказкам.** Низкая плотность сокровищ, простые фигуры из 1–2 клеток, target достигается за 1–2 раунда.
2. **Пересечение строк и колонок.** Игроку впервые выгодно сопоставлять сразу два числа, а не ориентироваться на одну строку.
3. **Первый настоящий выбор.** Несколько равноценных зон по одной подсказке, но пересечение двух подсказок выделяет более вероятное место; фигуры уже занимают пространство ощутимо.
4. **Давление.** Крупнее фигуры, меньше свободных зон, после target появляется реальный выбор cash-out или ещё один раунд ради большего score.
5. **Проверка концепта.** Несколько логических гипотез, минимум две развилки размещения; greedy по самым большим числам не должен стабильно побеждать.

# 7. Визуал

- Поле: квадратная сетка 8×8.
- Нераскрытая свободная клетка: нейтральная закрытая поверхность с лёгким знаком `?`.
- Занятая клетка: форма поставленного блока поверх сетки.
- При открытии `treasure`: короткий яркий reveal/popup, читаемый примерно за 1 секунду.
- При открытии `empty`: спокойный нейтральный reveal без штрафной анимации.
- Числа строк слева, числа колонок сверху.
- Рядом с исходным числом можно показывать уменьшенный индикатор `осталось`, чтобы игрок не считал найденные сокровища в уме.
- Три текущие фигуры находятся под полем и доступны для drag.
- Валидный preview размещения подсвечивает занимаемые клетки; невалидный — короткий отказ.
- Checkpoint после третьей фигуры должен явно отделяться короткой паузой: `Счёт: N / Цель: M` и две кнопки `Забрать` / `Ещё раунд`.
- HUD: текущий `score`, `targetScore`, номер раунда.

# 8. Онбординг

1. Под полем спрятаны ценные клетки.
2. Числа показывают, сколько ценного находится в каждой строке и колонке.
3. Поставь фигуру — клетки под ней откроются.
4. Ценная клетка даёт очко; пустая просто занимает место.
5. В раунде нужно поставить все три фигуры.
6. После раунда забери результат или рискни следующим.

`?` показывает только правила, без решения текущей карты.

# 9. Явно ВНЕ рамок

- Без меты, валют, коллекций, заданий, ежедневных бонусов, рекламы и IAP.
- Без runtime RNG.
- Давление ровно одно: скрытая информация.
- Твист ровно один: добровольный cash-out между раундами.
- Без изменений баланса/уровней после публикации, кроме датированного исправления критического бага.
- Нет очистки заполненных строк/колонок как в классическом block puzzle.
- Нет вращения фигур.
- Нет бустеров, undo, shuffle, bomb, wild-card клеток.
- Нет скрытых ложных подсказок.
- Нет случайной генерации следующей фигуры во время попытки.
- Нет таймера.

# 10. Метрики и события

Shell логирует:

- `game_open`
- `hub_impression`
- `hub_click`
- `teaser_click`
- `help_open`
- `more_yes`
- `session_2`
- `return_d1`
- `return_d7`

Механика вызывает:

- `first_action` — первый валидный `place_shape`;
- `level_start` — при входе на уровень;
- `level_win` — успешный `cash_out` при `score >= targetScore`;
- `level_fail` — `no_space` или `quota_not_met`;
- `retry` — повтор того же уровня после fail.

Диагностический payload для `place_shape`:

- `round_index`;
- `shape_id`;
- `anchor_x`, `anchor_y`;
- `cells_covered`;
- `treasures_found`;
- `score_after`;
- `free_cells_remaining`.

Для `cash_out`:

- `score`;
- `target_score`;
- `rounds_completed`.

Дополнительно полезно логировать `continue_round` на checkpoint с текущими `score`, `free_cells_remaining` и номером следующего раунда.

`level_5_complete` отдельно не эмитится: он автоматически следует из `level_win` пятого уровня.

Онлайн-гейты как резерв:

- **Readability:** игрок понимает связь между краевыми числами и скрытыми ценными клетками без дополнительного объяснения.
- **Reach L5:** достаточная доля игроков доходит до пятого уровня.
- **D1:** возврат на следующий день.

Если kill-критерий или онлайн-гейт провален — концепт хоронится, а не чинится дополнительными системами.
