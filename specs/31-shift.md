# 1. Паспорт концепта

- Название: Сдвиг
- **Правило одной фразой:** Выбери блок и сдвинь всю его строку или колонку на одну клетку, собирая 2+ одинаковых подряд; если на выходном краю линии стоит блок, он вылетает навсегда.
- Глагол: сдвиг линии
- Давление: необратимая потеря блоков за краем
- Твист: нет
- **Целевая эмоция:** «ещё один сдвиг соберёт группу, но ради него придётся пожертвовать крайним блоком».
- **Уровни:** генерируется
- **Солвер:** нужен
- Оценка: сильный кандидат; простое управление создаёт пространственное планирование, а пустоты после матчей постепенно превращаются в ресурс для безопасных сдвигов. Главный риск — слишком свободный и затянутый endgame после появления большого количества пустот.

Дополнительно:
- Семейство: line shift / match puzzle.
- Главное отличие от cyclic shift: линия не зацикливается; с противоположного края всегда входит пустая клетка, а выходной блок может быть потерян навсегда.
- Счёт считается по количеству блоков, удалённых через match, а не по количеству групп.
- Kill-критерий: если простая greedy-стратегия «сначала любой ход с немедленным match, среди них избегать выброса блока» набирает не менее 90% результата solver на 4 из 5 уровней, концепт хоронится как слишком очевидный. Отдельный kill-сигнал — если последние 30% партии системно превращаются в длинное бесплатное перекладывание без реальных жертв и развилок.

# 2. Цель и условия

Правила уровня — текст для кнопки `?`:

Выбери любой блок. Стрелки влево и вправо двигают всю его строку ровно на одну клетку; стрелки вверх и вниз — весь его столбец. С противоположного края появляется пустая клетка. Если на выходном краю стоял блок, он вылетает и больше не возвращается. После каждого сдвига любые горизонтальные или вертикальные группы из 2+ соседних блоков одного цвета исчезают и идут в счёт. Собери как можно больше блоков до конца уровня.

- Условие ПОБЕДЫ: уровень завершается, когда на поле не осталось ни одного цвета, представленного двумя или более блоками. Все оставшиеся одиночные блоки автоматически считаются несобранными; после этого показывается результат `collected / initialBlocks`.
- Условие ПОРАЖЕНИЯ: нет. Это score-optimization puzzle: любая попытка заканчивается результатом, а качество решения определяется количеством собранных блоков.
- Runtime RNG отсутствует.
- Начальная раскладка полностью фиксирована данными уровня.
- Начальное поле не содержит уже готовых групп 2+ одинаковых блоков по горизонтали или вертикали.
- Блоки, вылетевшие за край, не могут вернуться в текущей попытке.
- Матчи удаляются только после валидного сдвига; на старте уровня автоматического удаления нет.

# 3. Правила

1. На старте движок загружает фиксированное поле 8×8 из цветных блоков и, при необходимости конкретного уровня, пустых клеток.
2. Каждый блок имеет только `colorId`; внутри одного уровня все блоки одинаковы по размеру и механическим свойствам.
3. Игрок тапает по занятой клетке и выбирает находящийся в ней блок.
4. Тап по пустой клетке ничего не меняет и не считается ходом.
5. После выбора блока UI показывает четыре направления: `left`, `right`, `up`, `down`.
6. Выбранный блок служит только указателем линии. Отдельно двигать один блок нельзя.
7. Нажатие `left` сдвигает всю строку выбранного блока ровно на одну клетку влево.
8. Нажатие `right` сдвигает всю строку выбранного блока ровно на одну клетку вправо.
9. Нажатие `up` сдвигает весь столбец выбранного блока ровно на одну клетку вверх.
10. Нажатие `down` сдвигает весь столбец выбранного блока ровно на одну клетку вниз.
11. При сдвиге перемещаются все восемь позиций линии, включая пустые клетки. Блоки не сжимаются и не перепрыгивают через пустоты.
12. С противоположного направлению сдвига края в линию всегда входит новая пустая клетка.
13. Содержимое выходной крайней клетки покидает поле.
14. Если выходная клетка была пустой, ничего не теряется.
15. Если выходная клетка содержала блок, этот блок удаляется навсегда и `ejected += 1`.
16. Один валидный сдвиг всегда увеличивает `moves` ровно на 1 независимо от того, был ли выброшен блок.
17. После завершения сдвига движок одновременно проверяет всё поле на горизонтальные и вертикальные группы одинакового `colorId` длиной 2 или больше.
18. Горизонтальная группа — непрерывная последовательность 2+ занятых соседних клеток одной строки с одинаковым `colorId`.
19. Вертикальная группа — непрерывная последовательность 2+ занятых соседних клеток одного столбца с одинаковым `colorId`.
20. Пустая клетка всегда разрывает группу.
21. Все клетки всех найденных групп помечаются на удаление одновременно.
22. Если одна клетка одновременно входит в горизонтальную и вертикальную группу, она считается один раз.
23. После определения полного множества matched-клеток все они исчезают одновременно.
24. За каждый исчезнувший matched-блок `collected += 1`.
25. После удаления блоков освободившиеся клетки остаются пустыми; гравитации, падения или автоматического сжатия нет.
26. После удаления матчей повторная автоматическая проверка не запускается: один сдвиг вызывает максимум одну волну удаления.
27. После каждого хода движок пересчитывает, сколько блоков каждого цвета осталось на поле.
28. Если хотя бы один цвет представлен двумя или более блоками, уровень продолжается.
29. Если каждый оставшийся цвет представлен максимум одним блоком, дальнейший match физически невозможен независимо от сдвигов; уровень завершается победой.
30. Оставшиеся одиночные блоки в момент завершения записываются как `stranded`, но не прибавляются к `ejected`.
31. Итоговый результат уровня: `collected`, `ejected`, `stranded`, `moves`; при этом всегда выполняется `collected + ejected + stranded = initialBlocks`.
32. После любого завершённого хода выбор блока сбрасывается. Для следующего сдвига игрок снова выбирает блок и затем направление.
33. Все последствия каждого действия полностью детерминированы текущим состоянием и данными уровня.

# 4. Состояние уровня

```ts
type Cell = {
  colorId: string | null;
};

type SelectedCell = {
  row: number;
  col: number;
};

type GameState = {
  grid: Cell[][];              // 8x8
  selected: SelectedCell | null;
  initialBlocks: number;
  collected: number;
  ejected: number;
  stranded: number;
  moves: number;
  status: 'playing' | 'won';
};
```

Инварианты:

```ts
initialBlocks === countOccupied(grid) + collected + ejected + stranded
```

Во время `playing` значение `stranded` всегда `0`. Оно заполняется только в момент финализации уровня.

# 5. Ввод

Два типа игрового ввода:

```ts
{
  type: 'select_block';
  row: number;
  col: number;
}
|
{
  type: 'shift_selected_line';
  dir: 'left' | 'right' | 'up' | 'down';
}
```

Правила валидации:

- `select_block` валиден только для занятой клетки внутри поля.
- Невалидный `select_block` не меняет state.
- `shift_selected_line` валиден только если `selected !== null` и `status === 'playing'`.
- `left/right` всегда используют `selected.row`.
- `up/down` всегда используют `selected.col`.
- После валидного `shift_selected_line` selection сбрасывается в `null`.
- `first_action` — первый валидный `shift_selected_line`, а не выбор блока.

# 6. Контент уровня

Пример `levels.json`:

```json
{
  "id": 1,
  "grid": { "w": 8, "h": 8 },
  "cells": [
    ["a","b","c","d","a","b","c","d"],
    ["b","c","d","a","b","c","d","a"],
    ["c","d","a","b","c","d","a","b"],
    ["d","a","b","c","d","a","b","c"],
    ["a","c","b","d","a","c","b","d"],
    ["c","b","d","a","c","b","d","a"],
    ["b","d","a","c","b","d","a","c"],
    ["d","a","c","b","d","a","c","b"]
  ],
  "solver": {
    "optimalCollected": 49,
    "optimalMoves": 23
  }
}
```

`solver`-поля — данные offline-валидации и не обязаны показываться игроку.

Правила генерации:

- Поле прототипа всегда 8×8.
- Начальное состояние создаётся offline и сохраняется в `levels.json`; runtime RNG запрещён.
- Стартовая раскладка не должна содержать горизонтальные или вертикальные группы 2+ одинаковых блоков.
- Генератор обязан сохранять достаточное количество near-match ситуаций, чтобы первые осмысленные сборки были достижимы за 1–3 сдвига.
- Solver ищет максимальный `collected` до терминального состояния и минимум ходов среди решений с этим результатом.
- Уровень отклоняется, если solver не находит хотя бы две развилки, в которых разные допустимые сдвиги приводят к различному конечному `collected`.
- Уровень отклоняется, если greedy-стратегия из kill-критерия стабильно достигает ≥90% optimalCollected.
- Уровень отклоняется, если оптимальное решение содержит длинный хвост из безопасных сдвигов без выбора: более 8 последовательных ходов без ejection и без альтернативы, меняющей итоговый score.

Кривая по пяти уровням:

1. **Обучение сдвигу.** 3 цвета, почти готовая группа на одной очевидной линии. Первый ход может выбросить 1 блок, но сразу собирает 3+, чтобы цена края читалась как осознанный обмен.
2. **Пустота как ресурс.** После первой сборки появляются заметные пустые зоны; игрок впервые может сделать безопасный сдвиг, когда на выходном краю линии уже пусто.
3. **Первый настоящий выбор.** Две разные линии дают немедленный match, но одна жертвует будущим полезным цветом на краю; краткосрочный лучший ход не равен лучшему итоговому score.
4. **Давление.** 4 цвета и несколько near-match зон; для сильного результата нужно заранее создавать пустой край перед важным сдвигом.
5. **Проверка концепта.** 4–5 цветов, несколько конкурирующих цепочек решений; endgame обязан содержать хотя бы одну осмысленную жертву и не превращаться в бесплатное перекладывание остатков.

# 7. Визуал

- Поле: квадратная сетка 8×8.
- Блок: простой квадрат со скруглением; цвет берётся только из `tokens.css`.
- Пустая клетка остаётся визуально видимой как слот сетки, чтобы игрок воспринимал пустоту как пространство для манёвра.
- Выбранный блок получает чёткую рамку/подъём, но не выглядит так, будто двигаться будет только он.
- После выбора UI одновременно подсвечивает его строку и столбец очень лёгкими направляющими.
- Четыре стрелки управления появляются вокруг поля или рядом с выбранным блоком, но не перекрывают клетки.
- При нажатии `left/right` визуально двигается вся строка; при `up/down` — весь столбец.
- Перед подтверждённым сдвигом выходной край линии должен быть визуально понятен: если там блок, он коротко подсвечивается как блок, который сейчас будет потерян.
- Ejection payoff: крайний блок физически уезжает за границу поля и быстро исчезает; анимация 200–300 мс.
- Match payoff: все matched-блоки делают короткий общий pulse и схлопываются/растворяются одновременно; 350–500 мс.
- После match новые пустые клетки должны быть видны сразу; никакого падения блоков.
- Если за один ход есть и ejection, и match, сначала читается движение/ejection, затем match; суммарный payoff не дольше ~1 секунды.
- HUD: `Собрано N`, `Потеряно N`, `Осталось N`.
- Счёт `Собрано` визуально важнее `Потеряно`; отдельного таймера и лимита ходов нет.

# 8. Онбординг

1. `Выбери блок.`
2. `← → двигают всю его строку на 1 клетку.`
3. `↑ ↓ двигают весь его столбец на 1 клетку.`
4. `Если на выходном краю есть блок — он потеряется.`
5. `Собери 2+ одинаковых подряд. Они исчезнут и освободят место.`
6. `Пустой край позволяет двигать линию без потери блока.`

Кнопка `?` всегда показывает короткий текст из раздела 2 и не запускает отдельный tutorial-flow.

# 9. Явно ВНЕ рамок

- Без меты, валют, коллекций, заданий, ежедневных бонусов, рекламы, IAP.
- Без runtime RNG.
- Максимум одно давление, максимум один твист; здесь давление — необратимая потеря крайних блоков, отдельного твиста нет.
- Без изменений баланса/уровней после публикации; правки только как датированный критический баг.
- Нет cyclic wrap: блок, ушедший за край, не появляется с другой стороны.
- Нет движения отдельного блока; всегда сдвигается целая строка или колонка.
- Нет диагональных сдвигов.
- Нет свободного drag линии на несколько клеток: один ход = ровно одна клетка.
- Нет максимального автоматического сдвига до упора.
- Нет гравитации.
- Нет refill/spawn новых блоков после старта уровня.
- Нет power-ups, blockers, locked cells или специальных цветов в первой версии.
- Нет combo multiplier и бонуса за длину группы; каждый собранный блок всегда стоит ровно 1.
- Нет каскадной второй волны match после удаления.
- Нет общего лимита ходов.

# 10. Метрики и события

Шелл сам логирует `game_open`, `hub_impression`, `hub_click`, `teaser_click`, `help_open`, `more_yes`, `session_2`, `return_d1`, `return_d7` и общие поля (`game_id`, `anonymous_user_id`, `session_id`, `timestamp`, `source`, `version`).

Модуль механики вызывает:

- **first_action** — первый валидный `shift_selected_line`.
- **level_start** — при входе на каждый уровень; поля: `level`, `initial_blocks`.
- **level_win** — когда каждый оставшийся цвет представлен максимум одним блоком; поля: `level`, `collected`, `ejected`, `stranded`, `moves`, `collection_rate = collected / initialBlocks`.
- **level_fail** — не используется, потому что fail-состояния нет.
- **retry** — не используется как fail-retry; ручной restart попытки можно логировать отдельным `level_restart`, если shell это поддерживает.
- **level_5_complete** — автоматически через `level_win` пятого уровня, отдельно не эмитить.

Дополнительные mechanic events для анализа концепта:

- `line_shift` — `level`, `axis: row|col`, `dir`, `ejected: 0|1`, `matched_count`, `occupied_before`, `occupied_after`.
- `match_clear` — `level`, `matched_count`, `groups_count`, `largest_group`.

Ключевые offline-показатели:

- `collection_rate` — доля стартовых блоков, собранных через match.
- `ejection_rate` — доля стартовых блоков, потерянных за краем.
- `safe_shift_rate` — доля сдвигов, где выходная клетка была пустой.
- `productive_shift_rate` — доля сдвигов, после которых собран хотя бы один блок.
- `endgame_move_share` — доля ходов после момента, когда на поле осталось ≤30% стартовых блоков; высокий показатель при низком риске подтверждает проблему затянутого endgame.

Онлайн-ворота эксперимента остаются стандартными: читаемость механики, доходимость до 5 уровня, возврат D1.

Если kill-критерий срабатывает — концепт хоронится, а не чинится дополнительными таймерами, препятствиями или power-ups.
