# 1. Паспорт концепта

- Название: Ящик приезжает
- **Правило одной фразой:** Откручивай винты под текущие ящики; каждые три хода ящик меняется, карман вмещает три.
- Глагол: извлечение
- Давление: навязанная очередь
- Твист: нет
- **Целевая эмоция:** ритм — «я вовремя подготовился к следующему ящику»
- **Уровни:** генерируется
- **Солвер:** не нужен
- Оценка: 27/30 — чит 4, мот 5, давл 4, payoff 4, произв 5, рынок 5

# 2. Цель и условия

Правила уровня — текст в кнопке «?»:

Откручивай винты. Внизу стоят два активных ящика. Каждые 3 хода левый уезжает, правый сдвигается влево, а справа приезжает следующий. Цвета следующих ящиков видны заранее. Если нужного цвета сейчас нет, винт идёт в карман на 3 места. Когда подходящий ящик приезжает, такие винты автоматически уходят из кармана.

- Условие ПОБЕДЫ: на поле не осталось винтов.
- Условие ПОРАЖЕНИЯ: игрок откручивает винт недоступного цвета, когда все 3 места кармана заняты. Попытка положить четвёртый винт = немедленный проигрыш.
- Runtime RNG нет. Порядок ящиков, цвета и расположение винтов заранее зафиксированы.

# 3. Правила

1. На старте загружаются винты, два активных ящика и фиксированная очередь следующих ящиков.
2. Счётчик смены начинается с `3`, карман пуст.
3. Игрок тапает по любому винту, который ещё находится на поле.
4. Валидный тап откручивает винт и считается одним ходом.
5. Если цвет винта совпадает с одним из активных ящиков, винт сразу улетает в него.
6. Если совпадения нет и в кармане есть место, винт занимает первый свободный слот.
7. Если совпадения нет и карман уже `3/3`, фиксируется поражение по п.2.
8. После успешного хода счётчик смены уменьшается на 1.
9. При `0` левый ящик уезжает, правый становится левым, первый из очереди приезжает справа, счётчик снова становится `3`.
10. После смены все винты из кармана, подходящие под любой активный ящик, автоматически уходят туда. Это не считается ходом.
11. Игрок не двигает ящики, не меняет очередь и не может пропустить ход.
12. Если после разрешения хода винтов на поле не осталось, фиксируется победа по п.2.

# 5. Ввод

```ts
{ type: 'tap'; targetId: string }
```

Один игровой жест — тап по винту. Тап по HUD, ящикам или карману игровым действием не считается.

# 6. Контент уровня

Пример `levels.json`:

```json
{
  "id": 1,
  "shiftEvery": 3,
  "pocketSize": 3,
  "queuePreview": 3,
  "screws": [
    { "id": "s1", "color": "c1", "x": 0.24, "y": 0.31 }
  ],
  "boxes": ["c1", "c2", "c3", "c1", "c4", "c2"]
}
```

Первые два `boxes` активны, остальные образуют очередь. Генерация выполняется до публикации и сохраняется как фиксированный контент.

Кривая по пяти уровням:

1. 3 цвета, 10 винтов. Почти все винты подходят текущим ящикам; карман нужен один раз.
2. 3 цвета, 13 винтов. Нужно заметить смену через 3 хода и один раз подготовиться к следующему ящику.
3. 4 цвета, 16 винтов. Первый настоящий выбор между винтом доступного цвета и цветом, который скоро приедет.
4. 4 цвета, 20 винтов. Карман регулярно доходит до `2/3`; неправильный порядок создаёт угрозу переполнения.
5. 5 цветов, 24 винта. Минимум три ситуации, где preview очереди должен менять порядок откручивания.

# 7. Визуал

- Поле: одна плита с крупными круглыми винтами; никаких падающих деталей и дополнительной физики.
- Внизу: два крупных активных ящика; рядом три меньших preview-ящика.
- Карман: три постоянных слота `○ ○ ○`.
- Выбрано: винт приподнимается и делает короткий оборот.
- Выполнено: винт быстро летит в подходящий ящик.
- Карман: неподходящий винт летит в свободный слот.
- Payoff: при смене старый ящик уезжает, новый въезжает, подходящие винты каскадом вылетают из кармана. Событие должно читаться примерно за секунду.
- Ошибка: при четвёртом винте карман дёргается, винту некуда встать, сразу появляется fail.
- HUD: `Осталось: N`, `Смена через: 3/2/1`, `Карман: N/3`, preview очереди.

# 8. Онбординг

1. Нажми на винт, чтобы открутить его.
2. Подходящий цвет сразу уйдёт в один из двух ящиков.
3. Неподходящий винт попадёт в карман.
4. В кармане только 3 места.
5. Каждые 3 хода приезжает новый ящик.
6. Следующие ящики видны заранее.

Кнопка `?` показывает только правило из п.2.

# 9. Явно ВНЕ рамок

- Без меты, валют, коллекций, заданий, ежедневных бонусов, рекламы, IAP.
- Без runtime RNG.
- Максимум одно давление: навязанная очередь.
- Твист отсутствует.
- Без бустеров, undo, перестановки винтов, ручного управления ящиками, пропуска хода и вместимости ящиков.
- Без изменений баланса/уровней после публикации, кроме датированного критического бага.

# 10. Метрики и события

Шелл сам логирует `game_open`, `hub_impression`, `hub_click`, `teaser_click`, `help_open`, `more_yes`, `session_2`, `return_d1`, `return_d7` и общие поля.

Механика вызывает:

- `first_action` — первый валидный тап по винту на поле.
- `level_start` — вход на уровень, поле `level`.
- `level_win` — после выполнения условия победы из п.2.
- `level_fail` — при попытке положить четвёртый винт в карман; `reason: 'pocket_overflow'`.
- `retry` — повтор того же уровня после `level_fail`.
- `level_5_complete` отдельно не эмитится.

Kill-критерий концепта: если preview очереди ящиков не заставляет менять порядок откручивания минимум в ключевых ситуациях уровня 5, концепт хоронится.

Онлайн-резерв: читаемость, доходимость до 5 уровня, возврат D1. Если критерий не сработал — концепт не чинится.
