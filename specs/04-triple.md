# 2. Цель и условия

Правила уровня — текст в кнопке «?»:

Откручивай доступные винты. Каждый винт падает в поддон на 5 мест. Когда в поддоне собираются 3 винта одного цвета, они сразу исчезают и освобождают места. Если следующий ход тоже собирает тройку, серия разгрузок продолжается. Разбери всё поле, не переполнив поддон.

- Условие ПОБЕДЫ: на поле не осталось ни одного винта после завершения всех разгрузок текущего хода.
- Условие ПОРАЖЕНИЯ: игрок откручивает винт, для которого нет свободного места в поддоне, и этот винт не образует тройку сразу при добавлении.
- Поддон имеет 5 постоянных мест. Шестой винт может войти только как временный входящий элемент: сначала проверяется, образует ли он тройку; если нет — немедленный проигрыш.
- Runtime RNG нет. Цвета, расположение, доступность винтов и порядок разблокировок заранее зафиксированы уровнем.

# 3. Правила

1. На старте уровня движок загружает поле винтов и пустой поддон на 5 мест.
2. У каждого винта есть фиксированный список `requiresRemoved`; винт доступен, если все указанные там винты уже удалены.
3. Игрок может тапнуть по любому доступному винту.
4. Тап по недоступному или уже удалённому винту ничего не меняет и не считается ходом.
5. Валидный тап удаляет винт с поля и пытается добавить его в поддон.
6. Если в поддоне меньше 5 винтов, новый винт занимает следующее свободное место.
7. Если в поддоне уже 5 винтов, новый винт считается временным шестым входящим элементом до проверки совпадения.
8. После добавления движок считает винты каждого цвета в поддоне вместе с временным входящим элементом.
9. Если цвет добавленного винта теперь встречается не менее 3 раз, удаляются ровно 3 самых ранних винта этого цвета.
10. После удаления тройки оставшиеся винты сдвигаются влево без изменения относительного порядка.
11. Если новый винт был временным шестым и тройка не образовалась, фиксируется поражение по п.2; винт визуально не занимает постоянный слот.
12. Одна разгрузка считается частью серии, если предыдущий успешный ход тоже завершился разгрузкой тройки.
13. Серия заканчивается, если успешный ход не образовал тройку, либо уровень завершился.
14. Серия из двух и более разгрузок подряд получает отдельный payoff: вторая и последующие тройки схлопываются быстрее и с нарастающим визуальным акцентом.
15. Каждый валидный тап считается одним ходом независимо от того, собрал он тройку или нет.
16. После завершения хода движок пересчитывает доступность оставшихся винтов через `requiresRemoved`.
17. Игрок не может переставлять винты внутри поддона, удалять их вручную или отменять ход.
18. Если после завершения разгрузки на поле не осталось винтов, фиксируется победа по п.2.

# 6. Контент уровня

Пример `levels.json`:

```json
{
  "id": 1,
  "traySize": 5,
  "screws": [
    { "id": "s1", "color": "c1", "x": 0.25, "y": 0.22, "requiresRemoved": [] },
    { "id": "s2", "color": "c2", "x": 0.50, "y": 0.22, "requiresRemoved": [] },
    { "id": "s3", "color": "c1", "x": 0.75, "y": 0.22, "requiresRemoved": ["s1"] }
  ]
}
```

Генератор создаёт фиксированный граф разблокировок, набор цветов и расположение винтов. После генерации solver обязан подтвердить существование хотя бы одного полного маршрута без переполнения поддона. Runtime RNG нет.

Кривая по пяти уровням:

1. 3 цвета, 9 винтов. Первые три доступных винта одного цвета дают очевидную первую разгрузку. Поддон не поднимается выше `3/5`.
2. 3 цвета, 12 винтов. Игрок один раз доходит до `4/5`, после чего правильный цвет сразу освобождает тройку. Есть очевидная серия из двух разгрузок на соседних ходах.
3. 4 цвета, 15 винтов. Первый настоящий выбор: доступны винты двух цветов, но только один порядок оставляет место под третью копию нужного цвета.
4. 4 цвета, 18 винтов. Поддон несколько раз достигает `5/5`; следующий выбор должен либо немедленно собрать тройку, либо привести к fail. Минимум одна серия из двух разгрузок подряд.
5. 5 цветов, 21 винт. Минимум три состояния требуют планировать будущие разблокировки, а не только текущий состав поддона. Минимум одна серия из трёх разгрузок подряд должна быть достижима правильной игрой.

# 7. Визуал

- Поле: одна или несколько простых пластин с крупными круглыми винтами; цвет винта берётся только из `tokens.css`.
- Недоступный винт остаётся видимым, но визуально сидит глубже и не имеет активного tap-state.
- Доступный винт слегка приподнят относительно поверхности.
- Поддон: пять постоянных круглых слотов в один ряд.
- Выбрано: винт приподнимается и делает короткий оборот.
- Выполнено без тройки: винт быстро перелетает в первый свободный слот поддона.
- Выполнено с тройкой: три одинаковых винта стягиваются друг к другу и схлопываются за один короткий переход, после чего оставшиеся винты сдвигаются влево.
- Серия: вторая и последующие разгрузки подряд идут быстрее и получают усиленный импульс; это основной payoff-момент.
- Ошибка: при попытке добавить шестой винт без немедленной тройки входящий винт ударяется о заполненный поддон, слоты коротко дёргаются, затем показывается fail.
- HUD: `Осталось: N`, `Поддон: N/5`; при серии дополнительно короткий `×2`, `×3` без отдельной шкалы или мета-награды.

# 8. Онбординг

1. Нажимай на доступные винты, чтобы откручивать их.
2. Каждый винт падает в поддон.
3. Три одинаковых винта сразу исчезают.
4. В поддоне только 5 постоянных мест.
5. Если поддон заполнен, следующий винт должен сразу собрать тройку.
6. Собирай тройки подряд, чтобы быстро освобождать поддон.

Кнопка `?` показывает только правило из п.2 и не повторяет пошаговый онбординг.

# 9. Явно ВНЕ рамок

- Без меты, валют, коллекций, заданий, ежедневных бонусов, рекламы, IAP.
- Без runtime RNG.
- Одно давление: дефицит места в поддоне.
- Один твист: серия последовательных разгрузок.
- Без ручной сортировки поддона, swap, hold-слота, бустеров, undo и пропуска хода.
- Без дополнительных размеров групп: разгружается только ровно тройка одного цвета.
- Без таймера реального времени.
- Без изменений баланса/уровней после публикации, кроме датированного критического бага.

# 10. Метрики и события

Аналитикой владеет общий shell. Механика **не вызывает PostHog напрямую** —
она сообщает о происходящем через контракт `MechanicHost`.

- Shell сам логирует `game_open`, `help_open`, `level_start`, `level_win`,
  `level_5_complete`, `rating_submit`, `comment_submit`.
- Hub отдельно логирует `hub_impression`, `hub_click`, `teaser_click`.
- D1/D7 и повторные сессии PostHog считает сам по persisted distinct_id и
  `game_open` — отдельные события для них не нужны.
- `retry` шлёт shell после fail-попапа; `level_5_complete` отдельно не
  эмитится, он выводится из `level_win` пятого уровня.

Ниже описано, **когда** наступает каждое событие. Механика при этом вызывает
только `onFirstAction()`, `onFail('<код>')` и `onComplete()` — остальное
отправляет shell.

- `first_action` — первый валидный тап по доступному винту.
- `level_start` — при входе на каждый уровень, с номером уровня.
- `level_win` — когда после завершения текущей разгрузки на поле не осталось винтов.
- `level_fail` — при попытке добавить шестой винт, который не образует тройку; `reason: 'tray_overflow'`.
- `retry` — при повторной попытке того же уровня после `level_fail`.
- `level_5_complete` отдельно не эмитится.

Kill-критерий концепта: если серия из двух и более разгрузок подряд встречается реже одного раза за уровень при корректной игре, концепт хоронится.

Онлайн-резерв: читаемость, доходимость до 5 уровня, возврат D1. Если критерий не сработал — концепт хоронится, не чинится.

# 12. Профиль реализации

Относится к фабрике, а не к игровой идее: сменится фабрика — перепишется
только этот раздел.

**Контракт.** Механика реализует `MechanicHost` из `src/shell-contract.ts` и
вызывает `onFirstAction()`, `onComplete()`, `onFail(reason)`, `onExit()`.
PostHog напрямую не трогает — см. раздел 10.

**`game.config.ts`.** `id` совпадает со `slug` из шапки, `title` — с
`title_ru`, `tagline` — короткая строка под названием, `levelCount: 5`,
`version` и `onboarding.version` поднимаются при изменении контента и правил
соответственно. Токены аналитики и ключ обратной связи копируются из
`games/tap-targets/game.config.ts`.

**`data-testid`.** Обязателен на каждом интерактивном элементе — e2e ищет
строго по ним. Существующая конвенция: `game-surface` — контейнер механики,
`mechanic-hud` — HUD с атрибутом `data-remaining`.

**Анимация.** Payoff строится из эффектов `render-kit`: `punch`,
`invalidShake`, `successFlash`, `fadeCollapse`, `cameraShake`, `moveTo`.
Если нужного нет — сказать здесь, а не изобретать свой во время сборки.
_Какие именно эффекты нужны этой игре — не записано._
