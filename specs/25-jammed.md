# 1. Паспорт концепта

- Название: Заклинило
- **Правило одной фразой:** Перетаскивай одинаковую плитку на соседнюю: они сливаются в следующую по номиналу, а новая плитка остаётся именно в выбранной клетке; слей всё поле в одну плитку.
- Глагол: слияние
- Давление: цена ошибки
- Твист: нет
- **Целевая эмоция:** ответственность — каждый merge необратимо определяет, где окажется будущая крупная плитка.
- **Уровни:** генерируется
- **Солвер:** нужен
- Оценка: 20/30 — читаемость 4, мотивация 4, давление 4, payoff 2, производимость 3, рынок 3

Дополнительно:
- Семейство: Merge
- Отличие от аналога: 2048 — плитки не ездят по полю и новые не появляются; единственное перемещение происходит через merge одной одинаковой плитки в соседнюю.
- TREND: нет
- Kill-критерий: если правильное направление merge нельзя осмысленно предсказать хотя бы на два хода вперёд и результат воспринимается как угадайка, концепт хоронится.

# 2. Цель и условия

Правила уровня — текст для кнопки `?`:

Перетащи плитку на соседнюю плитку с тем же номиналом. Они сольются в одну плитку следующего номинала, которая останется в клетке, на которую ты перетащил. Пустая клетка останется свободной. Новых плиток не появляется. Продолжай, пока на поле не останется одна плитка.

- Условие ПОБЕДЫ: на поле осталась ровно одна плитка.
- Условие ПОРАЖЕНИЯ: на поле больше одной плитки и не существует ни одной пары ортогонально соседних плиток с одинаковым номиналом.
- Диагональное соседство не считается.
- Никакого общего лимита ходов нет.
- Runtime RNG отсутствует. Начальное поле полностью задано уровнем.

# 3. Правила

1. На старте движок загружает фиксированную сетку и набор плиток с номиналами.
2. Плитки занимают по одной клетке.
3. Пустые клетки не содержат объектов и не блокируют правила merge.
4. Игрок начинает drag с одной плитки и отпускает её на ортогонально соседней клетке.
5. Валидный merge возможен только если целевая клетка занята плиткой с тем же номиналом.
6. Диагональный drag невалиден.
7. Drag на пустую клетку невалиден: свободно перемещать плитки нельзя.
8. Drag на плитку другого номинала невалиден.
9. Невалидный drag ничего не меняет и не считается ходом.
10. При валидном merge исходная плитка удаляется со своей клетки.
11. Целевая плитка заменяется одной плиткой следующего номинала.
12. Новый номинал определяется как `value * 2`.
13. Новая плитка всегда остаётся именно в целевой клетке, куда игрок перетащил исходную.
14. Исходная клетка становится пустой.
15. Merge не запускает автоматических дополнительных merge.
16. Получившаяся плитка может позже участвовать в новом merge, если рядом появится плитка того же номинала.
17. После каждого валидного merge движок сначала проверяет победу.
18. Если на поле осталась одна плитка, фиксируется `level_win`.
19. Если плиток больше одной, движок проверяет наличие хотя бы одной валидной соседней одинаковой пары.
20. Если такой пары нет, фиксируется `level_fail` с причиной `jammed`.
21. Все последствия полностью определяются текущим состоянием поля и направлением drag.

# 4. Состояние уровня

```ts
type TileState = {
  id: string;
  x: number;
  y: number;
  value: number;
};

type GameState = {
  grid: {
    w: number;
    h: number;
  };
  tiles: TileState[];
  moves: number;
  status: 'playing' | 'won' | 'failed';
};
```

Никаких скрытых состояний у плиток нет.

# 5. Ввод

Один тип игрового ввода:

```ts
{
  type: 'merge_drag';
  sourceId: string;
  targetId: string;
}
```

Renderer сам определяет target по клетке отпускания. Engine повторно валидирует соседство и равенство номиналов.

# 6. Контент уровня

Пример `levels.json`:

```json
{
  "id": 1,
  "grid": { "w": 4, "h": 4 },
  "tiles": [
    { "id": "a", "x": 0, "y": 0, "value": 2 },
    { "id": "b", "x": 1, "y": 0, "value": 2 },
    { "id": "c", "x": 1, "y": 1, "value": 2 },
    { "id": "d", "x": 2, "y": 1, "value": 2 }
  ]
}
```

Правила генерации:

- Используются только номиналы степеней двойки: `2, 4, 8, 16...`.
- Все плитки и их позиции заданы заранее.
- Новых плиток во время уровня не появляется.
- Генератор обязан прогнать solver и подтвердить хотя бы один путь к одной финальной плитке.
- Solver должен учитывать направление каждого merge, потому что оно определяет клетку результата.
- Уровень не принимается, если все валидные первые ходы ведут к победе: цена ошибки должна быть реальной.
- Уровень не принимается, если правильный выбор направления нельзя обосновать состоянием поля хотя бы на два merge вперёд.
- Runtime RNG отсутствует.

Кривая по пяти уровням:

1. **Обучение направлению.** 4 плитки `2`; очевидная последовательность. Игрок видит, что `2 → 2` и `2 ← 2` дают разные позиции итоговой `4`.
2. **Первый риск.** 6 плиток. Есть две одинаковые пары, но merge одной пары в неправильную сторону создаёт тупик.
3. **Первый настоящий выбор.** 8 плиток. Нужно заранее подготовить соседство будущих `4`; минимум один ход выглядит локально правильным, но ломает следующий merge.
4. **Давление.** 10–12 плиток нескольких номиналов. Минимум два последовательных решения, где важно выбрать не только пару, но и направление схлопывания.
5. **Проверка концепта.** 12–16 плиток. Не меньше трёх развилок; хотя бы один путь проигрывает только через 2–3 хода, но причина должна быть читаема заранее по геометрии поля.

# 7. Визуал

- Поле: простая квадратная сетка с хорошо видимыми пустыми клетками.
- Плитка: квадрат со скруглением и крупным номиналом по центру.
- Цвет номинала берётся из `tokens.css`; значение всегда дублируется числом.
- При drag исходная плитка слегка приподнимается.
- Валидная целевая одинаковая плитка подсвечивается.
- Невалидная цель даёт короткий отказ без изменения состояния.
- Merge: исходная плитка быстро втягивается в целевую, после чего целевая увеличивается на коротком `pop` и показывает новый номинал.
- Пустая после merge клетка должна стать заметна сразу — это часть планирования.
- Fail `jammed`: все оставшиеся плитки коротко дёргаются, а отсутствие доступных пар визуально считывается за ~1 секунду.
- HUD: количество оставшихся плиток и число сделанных merge. Общего лимита ходов нет.

# 8. Онбординг

1. Перетащи плитку на соседнюю такую же.
2. Две одинаковые превращаются в одну следующего номинала.
3. Новая плитка остаётся там, куда ты её перетащил.
4. На пустую клетку двигать нельзя.
5. Новых плиток не будет — работай только с тем, что уже на поле.
6. Оставь одну плитку и не разнеси будущие пары по разным частям поля.

`?` повторяет только правила, без пошагового решения текущего уровня.

# 9. Явно ВНЕ рамок

- Нет meta-прогрессии, валют, коллекций, квестов, daily bonus, рекламы и IAP.
- Нет runtime RNG.
- Давление ровно одно: цена необратимого merge.
- Твиста нет.
- После публикации баланс и уровни не меняются, кроме датированного исправления критического бага.
- Нет свободного перемещения плиток.
- Нет свайпа всей строки/колонки.
- Нет появления новых плиток после merge.
- Нет автоматических каскадов.
- Нет undo, бустеров, shuffle, bomb и wild-card плиток.
- Нет общего лимита ходов и таймера.

# 10. Метрики и события

Shell логирует:

- `game_open`
- `hub_impression`
- `hub_click`
- `teaser_click`
- `help_open`
- `more_yes`
- `session_2`
- `return_d1`
- `return_d7`

Общие поля shell: `game_id`, `level_id`, `session_id`, `timestamp`.

Механика вызывает:

- `first_action` — первый валидный `merge_drag`;
- `level_start`;
- `level_win`;
- `level_fail` с `reason: 'jammed'`;
- `retry`.

Для `merge_drag` в диагностическом payload можно хранить:

- `source_value`;
- `source_x`, `source_y`;
- `target_x`, `target_y`;
- `result_value`;
- `tiles_remaining`.

`level_5_complete` отдельно не эмитится: он автоматически следует из победы на уровне 5.

Онлайн-гейты как резерв:

- **Readability:** игрок понимает правило направления merge без дополнительного текста.
- **Reach L5:** достаточная доля игроков доходит до пятого уровня.
- **D1:** возврат на следующий день.

Если критерий провален — концепт хоронится, а не чинится дополнительными системами.
