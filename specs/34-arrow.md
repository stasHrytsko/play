# 1. Паспорт концепта

- Название: Стрелка
- **Правило одной фразой:** Каждый ход выбери одну из двух стрелок и поставь её на любой блок: стрелка задаёт или меняет его направление, после чего все блоки со стрелками одновременно сдвигаются на одну клетку, а соприкоснувшиеся блоки одного цвета исчезают.
- Глагол: программирование
- Давление: каждое новое решение одновременно сдвигает все уже запрограммированные блоки
- Твист: стрелку на блоке можно заменить новой
- **Целевая эмоция:** «я сейчас перенаправлю этот блок — и вся система наконец сойдётся».
- **Уровни:** нужен авторинг
- **Солвер:** нужен
- Оценка: сильный casual-puzzle кандидат; управление объясняется одним действием, но последствия распространяются на всё поле. Главный риск — если игрок почти всегда может исправить ошибку следующей стрелкой, решения потеряют вес.

Дополнительно:
- Семейство: grid / movement / programming puzzle.
- Основное отличие: игрок не двигает блок напрямую; он меняет направление одного блока, а затем движется вся уже запрограммированная система.
- Kill-критерий: если простая greedy-стратегия «если можно сразу схлопнуть пару — делай это, иначе ставь любую допустимую стрелку» успешно проходит 4 из 5 финальных уровней, концепт считается недостаточно глубоким и хоронится.

# 2. Цель и условия

Правила уровня — текст для кнопки `?`:

На поле стоят цветные блоки. Каждый ход тебе показывают две стрелки. Выбери одну стрелку и поставь её на любой блок — если на блоке уже была стрелка, она заменится. После этого все блоки со стрелками одновременно пытаются сдвинуться на одну клетку по своим направлениям. Если два или больше блока одного цвета после движения соприкасаются стороной, вся такая группа исчезает. Очисти поле до того, как закончатся пары стрелок.

- Условие ПОБЕДЫ: после фазы схлопывания на поле не осталось ни одного блока.
- Условие ПОРАЖЕНИЯ: использована последняя пара стрелок уровня, после последующей фазы движения и схлопывания на поле остался хотя бы один блок.
- Лимит ходов детерминирован и равен длине массива `arrowPairs` уровня.
- Runtime RNG отсутствует.
- Последовательность пар стрелок полностью задана уровнем заранее и одинакова при каждом retry.

# 3. Правила

1. На старте движок загружает фиксированное поле 8×8, набор цветных блоков и фиксированную последовательность `arrowPairs`.
2. Каждый блок занимает ровно одну клетку и имеет цвет и направление: `up`, `down`, `left`, `right` или `null`.
3. На старте часть или все блоки могут быть без стрелок; конкретное состояние задаётся уровнем.
4. На старте не должно быть ортогонально соприкасающихся групп 2+ блоков одного цвета; такие уровни невалидны.
5. В каждый ход игрок видит ровно две стрелки текущей пары `arrowPairs[turnIndex]`.
6. Игрок выбирает одну из двух стрелок.
7. После выбора стрелки игрок тапает по любому существующему блоку.
8. Выбранная стрелка становится новым направлением этого блока.
9. Если у блока уже была стрелка, старое направление немедленно заменяется новым.
10. Вторая, невыбранная стрелка текущей пары сгорает и больше не используется.
11. После назначения стрелки начинается одна общая фаза движения.
12. В начале фазы движения движок делает snapshot позиций всех блоков.
13. Каждый блок с `direction != null` пытается перейти ровно на одну ортогонально соседнюю клетку по своей стрелке.
14. Блок без стрелки не предлагает движение и остаётся на месте.
15. Если целевая клетка находится за границей поля, блок остаётся на месте.
16. Если целевая клетка была занята любым блоком в snapshot начала фазы, движущийся блок остаётся на месте, даже если тот блок сам собирался уйти.
17. Если два или больше блоков предлагают одну и ту же свободную целевую клетку, ни один из этих блоков не двигается.
18. Все остальные валидные предложения движения применяются одновременно.
19. После завершения движения движок ищет ортогонально связанные компоненты блоков одного цвета.
20. Любая компонента размера 2 или больше помечается на удаление.
21. Все помеченные компоненты удаляются одновременно.
22. Диагональное касание не считается совпадением.
23. Если один блок одновременно касается нескольких блоков того же цвета и все они связаны ортогонально, исчезает вся связанная группа целиком.
24. После удаления блоков пустые клетки остаются пустыми; гравитации нет.
25. Направления у выживших блоков сохраняются после движения и продолжают действовать на следующих ходах, пока игрок их не заменит.
26. Если после удаления блоков поле пусто, фиксируется победа немедленно; оставшиеся пары стрелок не разыгрываются.
27. Если поле не пусто и использована последняя пара стрелок, фиксируется поражение.
28. Если поле не пусто и пары ещё остались, `turnIndex` увеличивается на 1 и показывается следующая пара стрелок.
29. Любой тап по пустой клетке ничего не меняет и не тратит ход.
30. Выбор стрелки сам по себе не тратит ход; ход фиксируется только после валидного тапа по существующему блоку.
31. Игрок может сменить выбранную стрелку между двумя вариантами текущей пары до тапа по блоку.
32. После валидного тапа отмены хода нет.
33. Все результаты действия полностью детерминированы текущим состоянием и данными уровня.

# 4. Состояние уровня

```ts
type Direction = 'up' | 'down' | 'left' | 'right';

type Block = {
  id: string;
  color: string;
  x: number;
  y: number;
  direction: Direction | null;
};

type ArrowPair = [Direction, Direction];

type GameState = {
  width: 8;
  height: 8;
  blocks: Block[];
  arrowPairs: ArrowPair[];
  turnIndex: number;
  selectedArrow: Direction | null;
  removedCount: number;
  status: 'playing' | 'won' | 'failed';
};
```

Внутри одного engine-step дополнительно используется временное состояние:

```ts
type MoveProposal = {
  blockId: string;
  fromX: number;
  fromY: number;
  toX: number;
  toY: number;
  valid: boolean;
};
```

`MoveProposal` не хранится между ходами.

# 5. Ввод

Рендерер шлёт в движок два типа ввода:

```ts
{
  type: 'select_arrow';
  direction: Direction;
}
|
{
  type: 'assign_arrow';
  blockId: string;
}
```

Правила ввода:

- `select_arrow` валиден только для одного из двух направлений текущей пары.
- Повторный `select_arrow` до назначения просто меняет выбор и не двигает поле.
- `assign_arrow` валиден только если `selectedArrow != null` и `blockId` существует.
- Именно валидный `assign_arrow` считается игровым ходом и запускает полную цепочку: назначение → движение всех активных блоков → схлопывание → win/fail check.
- Невалидный ввод состояние не меняет.

# 6. Контент уровня

Пример `levels.json`:

```json
{
  "id": 1,
  "grid": { "w": 8, "h": 8 },
  "blocks": [
    { "id": "r1", "color": "red", "x": 0, "y": 1, "direction": null },
    { "id": "r2", "color": "red", "x": 4, "y": 1, "direction": null },
    { "id": "b1", "color": "blue", "x": 1, "y": 5, "direction": null },
    { "id": "b2", "color": "blue", "x": 5, "y": 4, "direction": null }
  ],
  "arrowPairs": [
    ["right", "down"],
    ["left", "up"],
    ["right", "up"],
    ["down", "left"],
    ["right", "left"]
  ]
}
```

Требования к авторингу:

- Поле прототипа всегда 8×8.
- Количество цветов на уровне: ориентир 1–4.
- Каждый цвет должен иметь минимум 2 блока.
- Начальное состояние не должно содержать уже готовых групп 2+ одного цвета.
- Последовательность пар стрелок фиксируется внутри уровня; runtime RNG запрещён.
- Solver обязан подтвердить хотя бы один путь к полному очищению до окончания `arrowPairs`.
- Solver должен учитывать точные snapshot-правила коллизий и одновременного схлопывания.
- Уровень отклоняется, если одна из двух стрелок в большинстве пар не меняет множество достижимых состояний.
- Уровень отклоняется, если последовательное переназначение одной и той же стрелки одному блоку даёт тривиальное решение.
- Уровень отклоняется, если победа требует заранее знать скрытые будущие пары: решение должно быть разумно строиться по текущей видимой паре и состоянию поля. Последовательность всё равно фиксирована для повторяемости.

Кривая по пяти уровням:

1. **Обучение.** 2 пары блоков, много пустого места, 4–5 пар стрелок. Первый match должен получаться за 1–2 понятных действия.
2. **Переназначение.** Впервые выгодно поменять стрелку уже движущемуся блоку, чтобы он не прошёл мимо пары.
3. **Первый настоящий выбор.** 3 цвета; обе стрелки текущей пары валидны, но ведут к разным будущим конфигурациям. Игрок должен учитывать движение уже запрограммированных блоков.
4. **Давление.** Меньше свободного пространства, появляются блокировки траекторий и конфликт двух движущихся блоков за одну клетку.
5. **Проверка концепта.** 3–4 цвета, несколько активных стрелок одновременно, минимум одна ситуация, где лучший ход — перенаправить старый блок вместо запуска статичного. Greedy по немедленному match не должен стабильно проходить уровень.

# 7. Визуал

- Поле: квадратная сетка 8×8.
- Блок: крупный скруглённый квадрат одного из token-цветов.
- Блок без направления: чистая цветная плитка.
- Блок с направлением: крупная контрастная стрелка по центру плитки.
- Две доступные стрелки текущего хода показываются отдельными крупными кнопками под полем.
- Выбранная стрелка получает очевидное состояние selection.
- При тапе блока новая стрелка коротко «впечатывается» в плитку, чтобы замена направления читалась до движения.
- Затем все активные блоки сдвигаются синхронной анимацией примерно 150–250 мс.
- Заблокированный блок делает короткий микро-bump в сторону своей стрелки и возвращается на место.
- Если несколько блоков конфликтуют за одну клетку, оба делают короткий встречный bump без движения.
- Группа 2+ одного цвета после контакта схлопывается/втягивается в общий центр и исчезает примерно за 250–400 мс.
- Payoff должен читаться примерно за 1 секунду: назначил стрелку → всё поле двинулось → совпавшие цвета схлопнулись.
- HUD: номер хода `N / total`, сколько блоков осталось, сколько уже схлопнуто.
- Никаких таймеров на самих стрелках.

# 8. Онбординг

1. «Каждый ход выбери одну из двух стрелок.»
2. «Тапни блок — стрелка закрепится на нём.»
3. «Если стрелка уже была, новая заменит её.»
4. «После этого все блоки со стрелками двигаются на одну клетку.»
5. «Соедини 2+ одинаковых блока стороной — они исчезнут.»
6. «Очисти поле, пока не закончились пары стрелок.»

Кнопка `?` показывает только короткие правила из раздела 2 и не запускает отдельное обучение.

# 9. Явно ВНЕ рамок

- Без меты, валют, коллекций, заданий, ежедневных бонусов, рекламы, IAP.
- Без runtime RNG.
- Максимум одно давление, максимум один твист.
- Без изменений баланса/уровней после публикации; правки только как датированный критический баг.
- Нет таймера жизни стрелки.
- Нет блокировки переназначения на 2+ хода.
- Нет свободного drag блоков.
- Нет вращения поля.
- Нет диагонального движения.
- Нет гравитации после исчезновения блоков.
- Нет бонусов за цепочки, комбо, размер группы или скорость.
- Нет возможности хранить невыбранную стрелку на следующий ход.
- Нет Undo.
- Нет runtime-генерации новых блоков.

# 10. Метрики и события

Шелл сам логирует `game_open`, `hub_impression`, `hub_click`, `teaser_click`, `help_open`, `more_yes`, `session_2`, `return_d1`, `return_d7` и общие поля.

Модуль механики вызывает:

- **first_action** — первый валидный `assign_arrow`, после которого запускается движение поля.
- **level_start** — при входе на каждый уровень, поле `level`.
- **level_win** — когда после фазы схлопывания `blocks.length === 0`.
- **level_fail** — когда закончилась последняя пара стрелок и после фазы схлопывания остались блоки; причина `arrows_exhausted`.
- **retry** — повтор той же попытки после `level_fail`.
- **level_5_complete** отдельно не эмитится: фиксируется автоматически через `level_win` пятого уровня.

Дополнительные mechanic-поля к событиям, где уместно:

```ts
{
  turn_index: number;
  blocks_remaining: number;
  active_arrows: number;
  reassigned: boolean;
  removed_this_turn: number;
}
```

Резервные онлайн-ворота эксперимента: читаемость, доходимость до 5 уровня, возврат D1.

Если kill-критерий срабатывает — концепт хоронится, а не чинится добавлением новых механик.
