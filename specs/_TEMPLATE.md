# Шаблон «Правила игры»

Обязательная структура описания механики для прототипов эксперимента 30/30. Файл на игру: `specs/NN-name.md`.

## 1. Паспорт концепта

- Название
- **Правило одной фразой** — простыми словами объяснить, как в это играть. Без слогана и абстракций: что делает игрок, что меняется и где риск. Формулировка должна быть понятна человеку, который впервые видит игру.
- Глагол
- Давление (ровно одно)
- Твист (максимум один, либо «нет»)
- **Целевая эмоция** — что именно должен почувствовать игрок (напр. «азарт на грани провала», «облегчение от порядка»)
- **Уровни:** генерируется / нужен авторинг
- **Солвер:** нужен / не нужен
- Оценка

## 2. Цель и условия

- Правила уровня — текст в кнопке «?»
- Условие ПОБЕДЫ: точное правило
- Условие ПОРАЖЕНИЯ: есть или нет
  - Если есть — точный лимит (ходы/фигуры/что угодно), без runtime-случайности
  - Скрытая информация допустима только как заранее зафиксированное состояние уровня, которое можно сузить по видимым уликам

## 3. Правила

Пронумерованный список, без «и так далее». Для любого возможного тапа/свайпа можно однозначно сказать, что случится.

1. Что происходит на старте уровня
2. Что делает игрок (один жест = один пункт)
3. Что происходит при каждом результате действия (попал / не попал / занято / уже собрано...)
4. ...
5. N. Условие завершения (ссылка на п.2)

## 4. Состояние уровня

Что движок хранит между ходами, например:

```ts
{ remaining: string[]; moves: number; selected: string | null }
```

## 5. Ввод

Что рендерер шлёт в движок, один тип на один жест:

```ts
{ type: 'tap', targetId: string } | { type: 'swipe', dir: 'up'|'down'|... }
```

## 6. Контент уровня

- Параметры одного уровня в `levels.json`
- Кривая по **пяти** уровням: 1–2 обучающие, 3 — первый настоящий выбор, 4–5 — давление

## 7. Визуал

- Формы объектов на поле (без цветов — они из `tokens.css`)
- Состояния «выполнено / выбрано / ошибка» — анимация или нет, какая; это и есть payoff-момент — должен читаться глазами за секунду
- HUD помимо «осталось: N»

## 8. Онбординг

4–6 пунктов. Кнопка «?» — подсказка правила, **не обучение**.

## 9. Явно ВНЕ рамок

Фиксированный список ограничений эксперимента — просто подтвердить, что ничего из этого нет:

- Без меты, валют, коллекций, заданий, ежедневных бонусов, рекламы, IAP
- Без runtime RNG
- Максимум одно давление, максимум один твист
- Без изменений баланса/уровней после публикации (правки — только датированный критический баг)

## 10. Метрики и события

Аналитикой владеет общий shell, а не конкретная игра.

- Shell сам логирует `game_open`, `help_open`, `level_start`,
  `level_win`, `level_5_complete`, `rating_submit`,
  `comment_submit`.
- Hub отдельно логирует `hub_impression`, `hub_click`, `teaser_click`.
- D1/D7 и повторные сессии считаются в PostHog по persisted distinct_id и
  `game_open`, отдельные custom events для них не нужны.
- Механика **не вызывает PostHog/track напрямую**.

Механика сообщает shell только то, чего shell сам увидеть не может:

- **first_action** — в спеке точно указать первое осмысленное **валидное**
  действие. Render/host вызывает `onFirstAction()`; shell сам отправляет
  `first_action` и защищается от дублей.
- **level_fail** — если поражение возможно, при точном условии поражения
  render/host вызывает `onFail('<stable_reason_code>')`; shell сам отправляет
  `level_fail` и показывает общий fail-popup.
- **retry** — механика его не вызывает. Shell отправляет `retry`, когда игрок
  нажимает повтор после fail-popup, и монтирует тот же уровень заново.
- **level_start / level_win / level_5_complete** — полностью ответственность
  shell; механика сообщает победу только через существующий `onComplete()`.

Если критическое событие нельзя однозначно привязать к правилу из разделов 2–5,
спека ещё не готова к реализации.

**Онлайн** — ворота из правил эксперимента (читаемость, доходимость до 5 уровня,
возврат D1) — резервный способ, если первые два недоступны до публикации.

Если критерий не сработал — концепт хоронится, не чинится.
