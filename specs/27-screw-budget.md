# 1. Паспорт концепта

Дополнительно:
- Отличие от Screw Jam: винты не сортируются по цветам и не отправляются в карман; главный ресурс — общий запас крутей, а решение строится вокруг выбора, какие крепления снимать, а какие оставить на детали.
- Runtime RNG отсутствует.

# 2. Цель и условия

Правила уровня — текст для кнопки `?`:

На поле лежат детали слоями. Винт можно открутить только если его не закрывает другая деталь. Каждый винт стоит 1–3 крутя. У тебя один общий запас крутей на весь уровень. Чтобы снять деталь, не обязательно выкручивать все её винты — достаточно убрать указанное число креплений. Снятая деталь исчезает и открывает нижний слой. Сними все детали, пока запас крутей не закончился.

- Условие ПОБЕДЫ: все детали сняты с поля.
- Условие ПОРАЖЕНИЯ: детали ещё остались, но среди доступных винтов нет ни одного, стоимость которого не превышает оставшийся запас крутей.
- Никакого таймера нет.
- Скрытой информации нет: стоимость каждого винта, требуемое число снятых креплений на каждой детали и оставшийся запас крутей видны заранее.
- Состояние уровня полностью детерминировано.

# 3. Правила

1. На старте движок загружает фиксированный набор деталей, их порядок по слоям, винты, стоимость каждого винта и общий запас `turnsBudget`.
2. Каждая деталь содержит `N` винтов и параметр `releaseRequired` — сколько винтов нужно удалить с этой детали, чтобы она снялась.
3. `releaseRequired` всегда меньше либо равно числу винтов на детали.
4. Каждый винт имеет стоимость `1`, `2` или `3` крутя.
5. Стоимость винта видна на самом винте до действия игрока.
6. Винт доступен только если его позицию не перекрывает ни одна ещё не снятая деталь верхнего слоя.
7. Недоступный винт нельзя выбрать.
8. Игрок тапает по доступному винту.
9. Если стоимость винта больше текущего `turnsRemaining`, тап невалиден и ничего не меняет.
10. Если винт доступен и его стоимость не превышает `turnsRemaining`, винт удаляется.
11. После удаления винта `turnsRemaining` уменьшается на его стоимость.
12. Удалённый винт больше не участвует в уровне и не возвращается.
13. После каждого валидного удаления движок считает, сколько винтов уже удалено с соответствующей детали.
14. Когда число удалённых винтов достигает `releaseRequired`, деталь немедленно снимается с поля.
15. Все оставшиеся на снятой детали винты исчезают вместе с ней без дополнительной траты крутей.
16. Снятие детали может открыть винты на деталях нижнего слоя.
17. Один ход может снять максимум одну деталь — ту, с которой был удалён выбранный винт.
18. Снятие детали не запускает автоматическое удаление винтов на других деталях.
19. После каждого хода движок сначала проверяет победу.
20. Если деталей не осталось, фиксируется `level_win` независимо от остатка крутей.
21. Если детали остались, движок пересчитывает все доступные винты.
22. Если среди них нет ни одного винта со стоимостью `<= turnsRemaining`, фиксируется `level_fail` с причиной `out_of_turns`.
23. Иначе уровень продолжается.
24. Все последствия определяются только текущим состоянием поля и выбранным винтом; runtime RNG отсутствует.

# 4. Состояние уровня

```ts
type ScrewState = {
  id: string;
  plateId: string;
  x: number;
  y: number;
  cost: 1 | 2 | 3;
  removed: boolean;
  blockedBy: string[];
};

type PlateState = {
  id: string;
  z: number;
  releaseRequired: number;
  screwIds: string[];
  removed: boolean;
};

type GameState = {
  turnsRemaining: number;
  plates: PlateState[];
  screws: ScrewState[];
  moves: number;
  status: 'playing' | 'won' | 'failed';
};
```

`blockedBy` хранит id деталей, которые геометрически закрывают конкретный винт. Винт доступен, когда все эти детали уже сняты.

# 5. Ввод

Один тип игрового ввода:

```ts
{
  type: 'unscrew';
  screwId: string;
}
```

Renderer отправляет только id выбранного винта. Engine повторно проверяет доступность винта и наличие достаточного запаса крутей.

# 6. Контент уровня

Пример `levels.json`:

```json
{
  "id": 1,
  "turnsBudget": 7,
  "plates": [
    {
      "id": "top",
      "z": 2,
      "releaseRequired": 2,
      "screwIds": ["a", "b", "c"]
    },
    {
      "id": "bottom",
      "z": 1,
      "releaseRequired": 2,
      "screwIds": ["d", "e", "f"]
    }
  ],
  "screws": [
    { "id": "a", "plateId": "top", "x": 2, "y": 1, "cost": 1, "blockedBy": [] },
    { "id": "b", "plateId": "top", "x": 4, "y": 1, "cost": 1, "blockedBy": [] },
    { "id": "c", "plateId": "top", "x": 3, "y": 2, "cost": 3, "blockedBy": [] },
    { "id": "d", "plateId": "bottom", "x": 2, "y": 3, "cost": 1, "blockedBy": ["top"] },
    { "id": "e", "plateId": "bottom", "x": 3, "y": 3, "cost": 2, "blockedBy": ["top"] },
    { "id": "f", "plateId": "bottom", "x": 4, "y": 3, "cost": 3, "blockedBy": [] }
  ]
}
```

Правила генерации:

- Каждый уровень должен иметь хотя бы одно решение в пределах `turnsBudget`.
- Solver перебирает не только порядок деталей, но и подмножество винтов, которое реально используется для освобождения каждой детали.
- Уровень не принимается, если для каждой детали оптимально всегда выбирать просто `releaseRequired` самых дешёвых винтов независимо от того, какие нижние винты они открывают.
- Минимум с уровня 3 должен существовать выбор, где более дешёвый винт сейчас ведёт к более дорогому прохождению уровня целиком.
- Минимум с уровня 4 должен существовать хотя бы один винт стоимостью `3`, который визуально доступен, но в оптимальном решении вообще не откручивается.
- Уровень не принимается, если все валидные первые действия ведут к победе.
- Уровень не принимается, если единственное решение нельзя объяснить через видимое расположение слоёв, стоимости и `releaseRequired`.
- Runtime RNG отсутствует.

Кривая по пяти уровням:

1. **Обучение экономии.** Одна деталь, 3 винта `1 / 1 / 3`, `releaseRequired = 2`. Игрок понимает, что дорогой винт можно оставить.
2. **Слои.** Две детали. Верхняя снимается двумя из трёх винтов и открывает нижнюю. Запас позволяет одну явную ошибку, но показывает цену дорогого винта.
3. **Первый настоящий выбор.** Две верхние детали перекрывают разные винты нижнего слоя. Самый дешёвый локальный выбор открывает дорогой путь; чуть более дорогой первый ход экономит общий бюджет.
4. **Давление.** 4–5 деталей, стоимости `1–3`, несколько частично доступных винтов. Один доступный винт `3` является ловушкой и не нужен в оптимальном решении.
5. **Проверка концепта.** 5–7 деталей, минимум три развилки. Игрок должен планировать, какие крепления оставить на двух разных деталях, чтобы открыть дешёвые винты ниже и уложиться в жёсткий бюджет.

# 7. Визуал

- Поле: набор плоских деталей неправильной формы, лежащих внахлёст; границы слоёв читаются без дополнительного текста.
- Винт: крупная головка с визуальным индикатором стоимости `1`, `2` или `3` — например, одно/два/три кольца или насечки. Значение также может дублироваться цифрой.
- У каждой детали рядом компактно показано `снято / нужно`, например `1/2`.
- Недоступный винт визуально приглушён или частично закрыт верхней деталью.
- Доступный винт реагирует на тап.
- При удалении винта проигрывается короткая анимация вращения: число оборотов соответствует его стоимости, после чего винт вылетает из детали.
- HUD постоянно показывает `Крути: N`.
- После снятия последнего обязательного крепления деталь слегка приподнимается и уходит с поля; оставшиеся на ней винты уезжают вместе с ней. Это основной payoff-момент.
- При открытии нижних винтов они коротко подсвечиваются.
- Невалидный тап по слишком дорогому винту даёт короткий отказ и не тратит ресурс.
- Fail: HUD с остатком крутей коротко дёргается, все доступные винты показывают стоимость выше остатка; причина проигрыша читается за ~1 секунду.

# 8. Онбординг

1. Каждый винт стоит 1–3 крутя.
2. Общий запас крутей один на весь уровень.
3. Откручивать можно только открытые винты.
4. Чтобы снять деталь, достаточно убрать указанное число её винтов.
5. Остальные винты можно оставить — они исчезнут вместе с деталью.
6. Сними все детали, не потратив запас впустую.

Кнопка `?` повторяет правило, но не подсказывает конкретное решение текущего уровня.

# 9. Явно ВНЕ рамок

- Без меты, валют, коллекций, заданий, ежедневных бонусов, рекламы и IAP.
- Без runtime RNG.
- Давление ровно одно: общий дефицит крутей.
- Твист ровно один: для снятия детали не обязательно выкручивать все её винты.
- Без изменений баланса/уровней после публикации, кроме датированного критического бага.
- Нет цветов винтов как механики.
- Нет match-3, сортировки винтов и кармана.
- Нет таймера.
- Нет физической симуляции падения деталей.
- Нет изменения стоимости винта во время уровня.
- Нет бонусных крутей, комбо, бустеров, undo и shuffle.
- Нельзя закручивать винты обратно.

# 10. Метрики и события

Аналитикой владеет общий shell. Механика **не вызывает PostHog напрямую** —
она сообщает о происходящем через контракт `MechanicHost`.

- Shell сам логирует `game_open`, `help_open`, `level_start`, `level_win`,
  `level_5_complete`, `rating_submit`, `comment_submit`.
- Hub отдельно логирует `hub_impression`, `hub_click`, `teaser_click`.
- D1/D7 и повторные сессии PostHog считает сам по persisted distinct_id и
  `game_open` — отдельные события для них не нужны.
- `retry` шлёт shell после fail-попапа; `level_5_complete` отдельно не
  эмитится, он выводится из `level_win` пятого уровня.

Ниже описано, **когда** наступает каждое событие. Механика при этом вызывает
только `onFirstAction()`, `onFail('<код>')` и `onComplete()` — остальное
отправляет shell.

- `first_action` — первый валидный тап по доступному винту, который реально удаляет его;
- `level_start` — при входе на уровень;
- `level_win` — когда снята последняя деталь;
- `level_fail` — когда деталей ещё больше нуля, но ни один доступный винт нельзя оплатить оставшимися крутьями;
- `retry` — новая попытка того же уровня после `level_fail`.

Диагностический payload для `unscrew`:

- `screw_cost`;
- `turns_before`;
- `turns_after`;
- `plate_id`;
- `plate_removed_after_action`;
- `remaining_plates`.

`level_5_complete` отдельно не эмитится: он автоматически следует из `level_win` на пятом уровне.

Онлайн-гейты как резерв:

- **Readability:** игрок без дополнительного текста понимает, что цифра/насечки на винте — это стоимость в крутьях, а `1/2` на детали — сколько креплений ещё нужно убрать.
- **Reach L5:** достаточная доля игроков доходит до пятого уровня.
- **D1:** возврат на следующий день.

Главный офлайн-критерий: greedy-бот «всегда выбирай самый дешёвый доступный винт» не должен выигрывать более 80% валидных сгенерированных уровней. Если выигрывает — концепт хоронится, а не усложняется дополнительными системами.

# 12. Профиль реализации

Относится к фабрике, а не к игровой идее: сменится фабрика — перепишется
только этот раздел.

**Контракт.** Механика реализует `MechanicHost` из `src/shell-contract.ts` и
вызывает `onFirstAction()`, `onComplete()`, `onFail(reason)`, `onExit()`.
PostHog напрямую не трогает — см. раздел 10.

**`game.config.ts`.** `id` совпадает со `slug` из шапки, `title` — с
`title_ru`, `tagline` — короткая строка под названием, `levelCount: 5`,
`version` и `onboarding.version` поднимаются при изменении контента и правил
соответственно. Токены аналитики и ключ обратной связи копируются из
`games/tap-targets/game.config.ts`.

**`data-testid`.** Обязателен на каждом интерактивном элементе — e2e ищет
строго по ним. Существующая конвенция: `game-surface` — контейнер механики,
`mechanic-hud` — HUD с атрибутом `data-remaining`.

**Анимация.** Payoff строится из эффектов `render-kit`: `punch`,
`invalidShake`, `successFlash`, `fadeCollapse`, `cameraShake`, `moveTo`.
Если нужного нет — сказать здесь, а не изобретать свой во время сборки.
_Какие именно эффекты нужны этой игре — не записано._
