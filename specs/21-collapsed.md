# 1. Паспорт концепта

- Название: Схлопнулись
- **Правило одной фразой:** Режь большие фигуры на два куска и совмещай одинаковые пары, чтобы очистить экран.
- Глагол: разделение
- Давление: цена ошибки
- Твист: нет
- **Целевая эмоция:** облегчение — «нашёл правильный разрез, и пара наконец исчезла»
- **Уровни:** генерируется
- **Солвер:** нужен
- Оценка: 23/30 — читаемость 4, мотивация 4, давление 5, payoff 5, производимость 2, рынок 3

Дополнительно:
- Семейство: Cut / Match-2
- Отличие от аналога: match создаётся не перестановкой готовых элементов, а выбором того, как разрезать исходные фигуры.
- Kill-критерий: если более чем в 80% состояний любой доступный разрез сохраняет решаемость, концепт хоронится — выбор линии должен реально влиять на возможность очистить экран.

# 2. Цель и условия

Правила уровня — текст для кнопки `?`:

На экране находятся большие фигуры. У каждой есть несколько допустимых линий разреза. Нажми на линию — фигура разделится на два куска. Затем перетащи один кусок на другой кусок **того же типа формы**: пара схлопнется и исчезнет. Разрежь все большие фигуры так, чтобы каждому получившемуся куску нашлась пара и экран полностью очистился.

- Условие ПОБЕДЫ: на поле не осталось ни больших фигур, ни несхлопнутых кусков.
- Условие ПОРАЖЕНИЯ: большие фигуры и/или куски ещё остаются, но solver текущего состояния подтверждает, что ни одной последовательностью оставшихся разрезов и матчей очистить экран уже невозможно.
- Уровень полностью детерминирован: набор фигур, варианты разрезов и типы получаемых кусков заранее заданы.
- Runtime RNG отсутствует.
- Цвет не участвует в matching. Совпадение определяется только точным `pieceType`.
- Плавное движение объектов декоративное и не меняет доступные действия, варианты разрезов или результат уровня.

# 3. Правила

1. На старте уровня движок загружает конечный набор больших фигур и для каждой — список разрешённых разрезов.
2. Каждая большая фигура имеет минимум один и максимум три разрешённых разреза.
3. Каждый разрешённый разрез заранее определяет ровно два результата: `pieceTypeA` и `pieceTypeB`.
4. Неразрезанные большие фигуры могут плавно двигаться внутри небольшого визуального радиуса вокруг своей логической позиции; это движение не влияет на механику.
5. Игрок нажимает на одну из видимых разрешённых линий разреза выбранной большой фигуры.
6. Один валидный тап по линии выполняет ровно один разрез.
7. После разреза исходная большая фигура исчезает и заменяется двумя самостоятельными кусками, указанными в выбранном варианте разреза.
8. Одну и ту же большую фигуру нельзя разрезать второй раз: после первого разреза она больше не существует как большая фигура.
9. Получившиеся куски нельзя дополнительно резать.
10. Каждый кусок имеет точный `pieceType` из словаря уровня, например `triangle`, `rectangle`, `trapezoid`, `corner`.
11. Два куска считаются одинаковыми только если их `pieceType` совпадает полностью.
12. Цвет, визуальный масштаб и декоративный поворот куска не влияют на совпадение.
13. Игрок может начать drag только с уже созданного куска.
14. Во время drag остальные объекты продолжают только декоративное движение; логическое состояние не меняется.
15. Если кусок отпущен на другой кусок с тем же `pieceType`, оба куска схлопываются и исчезают.
16. Если кусок отпущен на объект другого `pieceType`, он возвращается в исходную логическую позицию; состояние уровня не меняется.
17. Нельзя матчить кусок с большой неразрезанной фигурой.
18. Нельзя матчить больше двух кусков одним действием.
19. Порядок матчей свободный: любую уже созданную одинаковую пару можно схлопнуть в любой момент.
20. После каждого разреза и каждого успешного match движок проверяет условие победы.
21. После каждого разреза движок также проверяет решаемость текущего состояния; если выигрышной последовательности больше нет, фиксируется `level_fail`.
22. Невалидный тап или неудачный drag не меняет состояние и не считается игровым действием.
23. Новые большие фигуры во время уровня не появляются.
24. Runtime RNG отсутствует; одинаковая последовательность действий всегда даёт одинаковый результат.

# 4. Состояние уровня

```ts
type PieceType = 'triangle' | 'rectangle' | 'trapezoid' | 'corner' | string;

type CutOption = {
  id: string;
  pieceTypeA: PieceType;
  pieceTypeB: PieceType;
  line: {
    from: { x: number; y: number };
    to: { x: number; y: number };
  };
};

type SourceShape = {
  id: string;
  shapeId: string;
  cuts: CutOption[];
  anchor: { x: number; y: number };
  visualPhase: number;
  status: 'uncut' | 'cut';
};

type PieceState = {
  id: string;
  pieceType: PieceType;
  sourceId: string;
  anchor: { x: number; y: number };
  visualPhase: number;
};

type GameState = {
  sources: SourceShape[];
  pieces: PieceState[];
  cutsMade: number;
  matchesMade: number;
  status: 'playing' | 'won' | 'failed';
};
```

`visualPhase` используется только renderer-ом для плавного движения и не участвует в solver-е.

# 5. Ввод

Два типа игрового ввода:

```ts
{
  type: 'cut';
  sourceId: string;
  cutId: string;
}
```

```ts
{
  type: 'match_drag';
  fromPieceId: string;
  toPieceId: string;
}
```

- `cut` возникает после тапа по разрешённой линии разреза.
- `match_drag` возникает после drag-and-drop одного куска на другой.
- Один `cut` = один необратимый выбор разреза.
- Один успешный `match_drag` = исчезновение ровно двух одинаковых кусков.

# 6. Контент уровня

Пример `levels.json`:

```json
{
  "id": 1,
  "pieceTypes": ["triangle", "rectangle", "trapezoid", "corner"],
  "sources": [
    {
      "id": "a",
      "shapeId": "quad_01",
      "anchor": { "x": 0.28, "y": 0.30 },
      "cuts": [
        { "id": "a1", "pieceTypeA": "triangle", "pieceTypeB": "rectangle" },
        { "id": "a2", "pieceTypeA": "trapezoid", "pieceTypeB": "corner" }
      ]
    },
    {
      "id": "b",
      "shapeId": "poly_03",
      "anchor": { "x": 0.72, "y": 0.32 },
      "cuts": [
        { "id": "b1", "pieceTypeA": "triangle", "pieceTypeB": "corner" },
        { "id": "b2", "pieceTypeA": "rectangle", "pieceTypeB": "trapezoid" }
      ]
    }
  ]
}
```

Правила контента:

- В prototype-словаре используется 4–6 визуально различимых `pieceType`.
- Один уровень содержит конечный набор из 2–8 больших фигур.
- У каждой фигуры 1–3 варианта разреза.
- Каждый вариант всегда даёт ровно два куска.
- Для каждой выигрышной генерации общее количество каждого `pieceType` после выбранных правильных разрезов должно быть чётным.
- Наличие чётного количества само по себе недостаточно: generator обязан прогонять solver и подтверждать хотя бы одну полную выигрышную последовательность.
- Solver должен также подтверждать наличие хотя бы одного реального неправильного выбора на уровнях 3–5.
- Runtime RNG отсутствует.

Кривая по пяти уровням:

1. **Обучение разрезу и match-2.** Две большие фигуры, по одному варианту разреза. После двух разрезов появляются две очевидные одинаковые пары.
2. **Первый выбор линии.** Три фигуры. У одной из них два разреза, но только один создаёт пары со вторым и третьим объектом.
3. **Первый настоящий пазл.** Четыре фигуры, у двух по два варианта разреза. Один ранний соблазнительный разрез оставляет один `pieceType` без пары и делает уровень нерешаемым.
4. **Давление выбора.** Пять-шесть фигур, 4–5 типов кусков. Минимум два последовательных решения зависят от того, какие типы уже созданы на экране.
5. **Проверка концепта.** Шесть-восемь фигур, несколько альтернативных линий. Есть минимум три точки выбора, где визуально удобный разрез отличается от выигрышного. Решение требует учитывать оба куска каждого разреза, а не только один желаемый match.

# 7. Визуал

- Экран без клеточной сетки: несколько крупных геометрических объектов свободно расположены в игровом поле.
- Большие фигуры различаются силуэтом и цветом; цвет не является правилом matching.
- На каждой большой фигуре разрешённые разрезы показываются тонкими пунктирными линиями.
- При наведении/тапе по фигуре линии становятся заметнее, но никаких дополнительных меню не открывается.
- После выбора линии короткая анимация разреза разделяет фигуру на два заранее определённых куска.
- Куски получают читаемый стандартный силуэт своего `pieceType`.
- Одинаковые `pieceType` должны быть визуально очевидно одинаковыми независимо от исходной фигуры.
- Все объекты могут слегка плавать вокруг своих anchor-позиций по заранее заданной renderer-анимации.
- Декоративное движение медленное; объект не должен уходить более чем примерно на 5% ширины своего хитбокса от anchor.
- При начале взаимодействия выбранный объект визуально стабилизируется, чтобы игрок не «ловил» его пальцем.
- Успешный match: один кусок притягивается к другому, пара быстро сжимается в центр и исчезает за ~0.4–0.6 с.
- Неудачный match: перетаскиваемый кусок мягко возвращается назад без штрафа.
- Главный payoff уровня: последняя пара схлопывается, экран остаётся пустым примерно на 0.5 с перед `level_win`.
- Цвета берутся только из `tokens.css`.
- HUD: номер уровня и количество оставшихся больших фигур + кусков. Отдельного счётчика ходов нет.

# 8. Онбординг

1. Нажми на линию — большая фигура разделится на два куска.
2. Каждый разрез необратим: заранее смотри, какие два куска получишь.
3. Перетащи один кусок на такой же — оба исчезнут.
4. Совпадает форма, а не цвет.
5. Для каждого полученного куска в итоге должна существовать пара.
6. Очисти весь экран.

Кнопка `?` повторяет краткое правило уровня, но не показывает правильный разрез.

# 9. Явно ВНЕ рамок

- Нет меты, валют, коллекций, квестов, daily-бонусов, рекламы и IAP.
- Нет runtime RNG.
- Одно давление: цена необратимого выбора разреза.
- Твист отсутствует.
- Нет изменения баланса или уровней после публикации, кроме датированного критического бага.
- Нет свободного рисования произвольной линии разреза.
- Нет приблизительного распознавания геометрии.
- Нет matching по цвету.
- Нет matching трёх и более элементов — только пары.
- Нет дополнительного разрезания уже созданных кусков.
- Нет появления новых исходных фигур после старта уровня.
- Нет таймера и real-time проигрыша.
- Нет физики столкновений между плавающими объектами.
- Нет бонусов, undo, shuffle и hint, который показывает правильный разрез.

# 10. Метрики и события

Shell логирует стандартные события:

- `game_open`
- `hub_impression`
- `hub_click`
- `teaser_click`
- `help_open`
- `more_yes`
- `session_2`
- `return_d1`
- `return_d7`

Общие поля shell: `game_id`, `level_id`, `session_id`, `ts`, platform/app-version по общему контракту.

Механика вызывает:

- `first_action` — первый валидный `cut`.
- `level_start` — старт уровня.
- `cut_made` — `source_id`, `cut_id`, `piece_type_a`, `piece_type_b`, `remaining_sources`, `remaining_pieces`.
- `pair_match` — `piece_type`, `remaining_sources`, `remaining_pieces`.
- `level_win` — после исчезновения последней пары.
- `level_fail` — причина `unsolvable_after_cut`, плюс `source_id` и `cut_id`, после которых состояние стало нерешаемым.
- `retry` — рестарт после fail или ручного перезапуска.
- `level_5_complete` отдельно не эмитится; определяется автоматически по `level_win` пятого уровня.

Резервные online-gates:

- Readability: игроки понимают, что одинаковость определяется формой, а не цветом.
- Reach L5: игроки доходят до пятого уровня без массовых бросаний после первого необратимого неправильного разреза.
- D1.

Kill-критерий концепта: если более чем в 80% игровых состояний любой доступный разрез сохраняет решаемость или игрок может игнорировать второй результат разреза и всё равно стабильно выигрывать, концепт хоронится, а не чинится балансом.
