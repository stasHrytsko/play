# 1. Паспорт концепта

Поля паспорта — в шапке раздела 0.

**Почему kill-критерий именно такой.** Идея в том, что сдвиг перестаёт быть бесплатным: у каждой машины свой запас, и важен не порядок ходов, а маршрут. Если запаса хватает с избытком на большинстве уровней, счётчик на машине — украшение, а игра остаётся обычным Parking Jam. Провал по критерию означает, что дефицит ресурса не кусается: это свойство идеи, потому что при щедром запасе счётчик мёртв независимо от того, насколько запутана парковка.

# 2. Цель и условия

## Правила уровня — текст для кнопки «?»

На парковке стоят машины. На каждой видно, сколько сдвигов у неё осталось.

Свайпай машину на одну клетку вперёд или назад вдоль её направления, если клетка свободна.

Каждый успешный сдвиг тратит `1` ход именно этой машины.

Если машина доезжает до своего выезда, она покидает поле.

Если у машины осталось `0`, а она ещё на парковке, она глохнет и больше не двигается.

Выведи все машины, не заглушив ни одну раньше времени.

## Условие ПОБЕДЫ

На поле не осталось ни одной машины.

## Условие ПОРАЖЕНИЯ

Любая машина после успешного сдвига получает `movesLeft = 0`, при этом всё ещё находится на поле.

Такая машина считается заглохшей, фиксируется `level_fail`.

Других условий поражения нет.

Runtime RNG отсутствует. Стартовые позиции, направления, выезды и запас сдвигов каждой машины заранее зафиксированы уровнем.

# 3. Правила

1. На старте уровня движок загружает парковочную сетку, машины, их направления, выезды и индивидуальный запас сдвигов.
2. Каждая машина занимает фиксированное число клеток и может двигаться только вдоль своей продольной оси.
3. На каждой машине всегда видно число оставшихся сдвигов.
4. Игрок свайпает машину вдоль её оси на одну клетку.
5. Если целевая клетка занята другой машиной или находится за границей поля вне разрешённого выезда, движение не происходит и ход не тратится.
6. Если целевая клетка свободна, машина сдвигается ровно на одну клетку.
7. Каждый валидный сдвиг уменьшает `movesLeft` этой машины на `1`.
8. Сдвиги других машин не влияют на её запас.
9. Если после валидного сдвига ведущая часть машины пересекла назначенный ей выезд, машина считается выехавшей и удаляется с поля.
10. Машина может выехать только через свой заранее заданный выезд.
11. Если машина выехала тем же сдвигом, которым её запас стал `0`, поражения нет: сначала разрешается выезд, затем проверяется остаток на поле.
12. Если после валидного сдвига `movesLeft === 0` и машина всё ещё находится на поле, она глохнет.
13. Заглохшая машина визуально остаётся на месте и больше не принимает ввод.
14. В момент появления первой заглохшей машины фиксируется поражение по условию из п.2.
15. Машины не поворачиваются, не меняют длину и не перепрыгивают через другие машины.
16. Игрок не может отменять уже сделанные сдвиги.
17. Если после удаления очередной выехавшей машины на поле не осталось машин, фиксируется победа по условию из п.2.

# 4. Состояние уровня

```ts
type Dir = 'up' | 'down' | 'left' | 'right';

type CarState = {
  id: string;
  x: number;
  y: number;
  length: 2 | 3;
  axis: 'h' | 'v';
  exitId: string;
  movesLeft: number;
  status: 'active' | 'stalled';
};

type ExitState = {
  id: string;
  edge: 'top' | 'bottom' | 'left' | 'right';
  index: number;
  axis: 'h' | 'v';
};

type GameState = {
  cars: CarState[];
  exits: ExitState[];
  moves: number;
  status: 'playing' | 'won' | 'failed';
};
```

В `cars` находятся только машины, которые ещё не выехали с поля.

# 5. Ввод

```ts
{
  type: 'swipe';
  targetId: string;
  dir: 'up' | 'down' | 'left' | 'right';
}
```

Один игровой жест — свайп машины на одну клетку.

Свайп поперёк оси машины, свайп заглохшей машины и свайп в занятую клетку считаются невалидными и не тратят ресурс.

# 6. Контент уровня

## Формат уровня в `levels.json`

```json
{
  "id": 1,
  "grid": { "w": 6, "h": 6 },
  "exits": [
    { "id": "e1", "edge": "right", "index": 2, "axis": "h" },
    { "id": "e2", "edge": "bottom", "index": 4, "axis": "v" }
  ],
  "cars": [
    {
      "id": "a",
      "x": 1,
      "y": 2,
      "length": 2,
      "axis": "h",
      "exitId": "e1",
      "moves": 4
    },
    {
      "id": "b",
      "x": 4,
      "y": 1,
      "length": 2,
      "axis": "v",
      "exitId": "e2",
      "moves": 3
    }
  ]
}
```

Генератор создаёт только уровни, где существует хотя бы одна последовательность действий, выводящая все машины до исчерпания их индивидуального ресурса.

Солвер обязателен и используется офлайн при генерации и валидации. Runtime RNG нет.

Солвер должен проверять:

1. Уровень имеет решение.
2. В решении минимум у одной машины остаётся не более `1` лишнего сдвига относительно минимально необходимого маршрута.
3. На уровнях 4–5 минимум два решения на раннем ходу выглядят допустимыми, но одно из них расходует ресурс машины так, что позже уровень становится нерешаемым.
4. Kill-критерий не нарушен: нельзя выдавать большой запас почти всем машинам.

## Кривая по пяти уровням

### Уровень 1 — понять ресурс

- 3 машины.
- У каждой 3–5 сдвигов.
- Один выезд уже почти свободен.
- Ни одна машина не требует точного расчёта более чем на 2 шага вперёд.
- Одна машина доезжает до выхода с `1` оставшимся сдвигом.

Цель: понять, что число на машине уменьшается только при её собственном движении.

### Уровень 2 — понять «не двигай зря»

- 4 машины.
- Одна блокирующая машина имеет ровно необходимый запас плюс `1`.
- Есть очевидный лишний сдвиг, который выглядит безопасно, но съедает последний запас этой машины.
- Ошибка должна быть понятна после одного retry.

Цель: перестать воспринимать движение как бесплатное.

### Уровень 3 — первый настоящий выбор

- 5 машин.
- Две машины можно двигать в начале.
- Оба хода локально освобождают место.
- Только один порядок сохраняет достаточно ресурса для позднего разведения машин.
- Минимум одна машина выходит с `0` ровно на последнем разрешённом сдвиге.

Цель: первый осознанный выбор, кому тратить ход сейчас.

### Уровень 4 — давление

- 6 машин.
- Несколько машин имеют запас, близкий к минимально необходимому.
- Одну машину приходится временно отодвинуть от своего выезда, чтобы пропустить другую.
- Лишний возврат назад делает уровень нерешаемым.
- Минимум два состояния требуют сравнить запас сразу у нескольких машин.

### Уровень 5 — проверка концепта

- 7 машин.
- У большинства запас отличается от минимально необходимого пути не более чем на `1–2` сдвига.
- Минимум три развилки, где «самый очевидный свободный ход» не является безопасным по ресурсу.
- Хотя бы одна машина должна использовать последний сдвиг непосредственно для выезда.
- Без чтения чисел на машинах уровень нельзя стабильно пройти жадной стратегией.

# 7. Визуал

## Поле

- Компактная парковочная сетка.
- Машины — простые прямоугольники длиной 2 или 3 клетки.
- Цвета берутся только из `tokens.css`.
- Выезды обозначены разрывом бордюра и короткой дорожкой за пределами сетки.

## Остаток ресурса

На каждой машине крупный бейдж с числом:

`4` → `3` → `2` → `1` → `0`

Число должно читаться без открытия HUD.

## Выбрано

При начале свайпа машина слегка приподнимается и показывает допустимую ось движения.

## Успешный сдвиг

Машина коротко снапается на соседнюю клетку, а число на ней уменьшается на `1` одновременно с остановкой.

## Выезд — payoff

Если машина пересекает свой выезд:

1. она ускоряется на последнем участке;
2. полностью уходит за границу поля;
3. её бейдж ресурса исчезает вместе с машиной;
4. освободившиеся клетки сразу становятся визуально доступными.

Момент должен читаться за секунду как «ресурс потратил правильно».

## Заглохла — ошибка

Если после сдвига число стало `0`, а машина ещё на поле:

1. машина коротко дёргается;
2. появляется визуальный признак остановки;
3. бейдж остаётся `0`;
4. машина перестаёт реагировать на ввод;
5. сразу показывается поражение.

Без дополнительных всплывающих правил до fail.

## HUD

Помимо `Осталось машин: N`:

- `Ходов сделано: N`
- количество активных машин
- без общего лимита ходов

Главный ресурс читается не из HUD, а непосредственно на машинах.

# 8. Онбординг

1. Свайпай машину вдоль её направления.
2. Каждый сдвиг тратит `1` ход этой машины.
3. Остаток ходов написан прямо на машине.
4. Довези машину до её выезда.
5. Если число станет `0` раньше выезда — машина заглохнет.
6. Выведи все машины.

Кнопка `?` показывает только краткое правило из п.2 и не повторяет пошаговое обучение.

# 9. Явно ВНЕ рамок

- Без меты, валют, коллекций, заданий, ежедневных бонусов, рекламы, IAP.
- Без runtime RNG.
- Одно давление: дефицит индивидуального ресурса движения.
- Твист отсутствует.

- Без толкания нескольких машин одним свайпом.

# 10. Метрики и события

Аналитикой владеет общий shell. Механика **не вызывает PostHog напрямую** —
она сообщает о происходящем через контракт `MechanicHost`.

- Shell сам логирует `game_open`, `help_open`, `level_start`, `level_win`,
  `level_5_complete`, `rating_submit`, `comment_submit`.
- Hub отдельно логирует `hub_impression`, `hub_click`, `teaser_click`.
- D1/D7 и повторные сессии PostHog считает сам по persisted distinct_id и
  `game_open` — отдельные события для них не нужны.
- `retry` шлёт shell после fail-попапа; `level_5_complete` отдельно не
  эмитится, он выводится из `level_win` пятого уровня.

Ниже описано, **когда** наступает каждое событие. Механика при этом вызывает
только `onFirstAction()`, `onFail('<код>')` и `onComplete()` — остальное
отправляет shell.

Фрагменты `track(...)` ниже описывают **payload события**, который
отправит shell, а не вызов, который делает механика. Имена причин из
них — это коды для `onFail(reason)`.

## `first_action`

Первый валидный свайп активной машины на свободную соседнюю клетку.

Невалидный свайп, свайп поперёк оси или свайп заглохшей машины не считается `first_action`.

## `level_start`

При входе на каждый уровень:

```ts
track('level_start', { level })
```

## `level_win`

Когда после выезда очередной машины:

```ts
cars.length === 0
```

```ts
track('level_win', {
  level,
  moves
})
```

## `level_fail`

Когда после валидного сдвига машина остаётся на поле с `movesLeft === 0`:

```ts
track('level_fail', {
  level,
  moves,
  reason: 'car_stalled',
  car_id: car.id
})
```

## `retry`

При повторной попытке того же уровня после `level_fail`:

```ts
track('retry', { level })
```

## `level_5_complete`

Отдельно не эмитится. Автоматически определяется shell как `level_win` пятого уровня.

## Проверяемая гипотеза

Игрок воспринимает каждый сдвиг конкретной машины как расходуемый ресурс и из-за этого меняет порядок движений.

Kill-критерий: если у более чем 80% проверенных уровней запас ходов настолько велик, что игрок может делать лишние сдвиги без заметного риска, концепт хоронится.

Онлайн-резерв: читаемость, доходимость до 5 уровня, возврат D1. Если критерий не сработал — концепт не чинится.

# 11. Крайние случаи

- **Повторный свайп той же машины** — обычный ход: каждый валидный сдвиг тратит ещё одну единицу запаса (п.7). Невалидный — упёрлась в машину или в границу — запас не тратит (п.5).
- **Свайп мимо всего** — по пустой клетке или HUD — не ход, запас не тратится.
- **Действие невозможно** — свайп заглохшей машины игнорируется (п.13). Позиция, где ни одна машина сдвинуться не может, а заглохших ещё нет, — тупик без исхода: уровень обязан считать её проигрышной, и это проверяет солвер (`solver: required`).
- **Ходов не осталось, победа не выполнена** — исчерпанный запас — это и есть поражение: машина глохнет (п.12) и первая заглохшая фиксирует проигрыш (п.14). Исключение одно: машина выехала тем же сдвигом, которым запас стал `0` (п.11).
- **Два объекта в одной позиции** — неприменимо: машины не пересекаются и не перепрыгивают друг друга (п.5, п.15).

# 12. Профиль реализации

Относится к фабрике, а не к игровой идее: сменится фабрика — перепишется
только этот раздел.

**Контракт.** Механика реализует `MechanicHost` из `src/shell-contract.ts` и
вызывает `onFirstAction()`, `onComplete()`, `onFail(reason)`, `onExit()`.
PostHog напрямую не трогает — см. раздел 10.

**`game.config.ts`.** `id` совпадает со `slug` из шапки, `title` — с
`title_ru`, `tagline` — короткая строка под названием, `levelCount: 5`,
`version` и `onboarding.version` поднимаются при изменении контента и правил
соответственно. Токены аналитики и ключ обратной связи копируются из
`games/tap-targets/game.config.ts`.

**`data-testid`.** Обязателен на каждом интерактивном элементе — e2e ищет
строго по ним. Существующая конвенция: `game-surface` — контейнер механики,
`mechanic-hud` — HUD с атрибутом `data-remaining`.

**Анимация.** Payoff строится из эффектов `render-kit`: `punch`,
`invalidShake`, `successFlash`, `fadeCollapse`, `cameraShake`, `moveTo`.
Если нужного нет — сказать здесь, а не изобретать свой во время сборки.
_Какие именно эффекты нужны этой игре — не записано._
