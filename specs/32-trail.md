# 1. Паспорт концепта

- Название: След
- **Правило одной фразой:** Иди по клеткам, собери X/Y/Z в любом порядке и доберись до B, но каждая покинутая клетка исчезает на следующие 3 хода и может отрезать тебе путь.
- Глагол: движение
- Давление: временно исчезающий путь
- Твист: нет
- **Целевая эмоция:** «ещё шаг — и я сам себе перекрою дорогу; надо найти маршрут, который переживёт мой собственный след».
- **Уровни:** нужен авторинг
- **Солвер:** нужен
- Оценка: сильный кандидат — очень простое управление, но каждое движение одновременно продвигает игрока и временно разрушает пространство позади него.

Дополнительно:
- Семейство: route puzzle / grid navigation.
- Поле прототипа: 8×8.
- Контрольные точки: `X`, `Y`, `Z`; их можно посещать в любом порядке.
- Финальная точка: `B`; победа возможна только после посещения всех контрольных точек.
- Базовый cooldown клетки: **3 хода**.
- Kill-критерий: если на уровнях 3–5 простая стратегия «всегда идти к ближайшей непосещённой точке кратчайшим доступным путём» проходит не менее 80% тестовых раскладок без необходимости учитывать исчезающие клетки, концепт хоронится как слишком слабый.

# 2. Цель и условия

Правила уровня — текст для кнопки `?`:

Ты начинаешь в точке `A`. Перемещайся на одну клетку вверх, вниз, влево или вправо. Каждый раз, когда ты уходишь с клетки, она исчезает и остаётся недоступной следующие 3 хода, после чего возвращается. Посети `X`, `Y` и `Z` в любом порядке, затем доберись до `B`. Если после хода тебе некуда идти и цель ещё не выполнена — уровень проигран.

- Условие ПОБЕДЫ: игрок находится на клетке `B` и все обязательные контрольные точки уровня уже посещены.
- Условие ПОРАЖЕНИЯ: после завершения валидного хода у текущей позиции нет ни одной доступной ортогонально соседней клетки, а условие победы не выполнено.
- Отдельного лимита ходов нет.
- Пропускать ход нельзя.
- Runtime RNG отсутствует.
- Положение `A`, `B`, контрольных точек и начальное состояние поля полностью фиксированы уровнем.

Точное правило «исчезает на 3 хода»:

- Если игрок покинул клетку на ходе `N`, она недоступна как клетка назначения на ходах `N+1`, `N+2` и `N+3`.
- После завершения хода `N+3` клетка возвращается.
- Следовательно, впервые снова войти в неё можно на ходе `N+4`.
- Пример минимального цикла `A → B → C → D → A`: если `A` покинута на первом ходу, вернуться в неё четвёртым ходом нельзя — она станет доступна только после завершения этого хода.

# 3. Правила

1. На старте уровня движок создаёт фиксированное поле 8×8.
2. Все клетки поля изначально активны.
3. Игрок стартует на клетке `A`.
4. Уровень содержит от 1 до 3 обязательных контрольных точек; в полной версии прототипа используются `X`, `Y`, `Z`.
5. Контрольные точки можно посещать в любом порядке.
6. `B` видна с начала уровня, но не завершает уровень, пока не собраны все обязательные контрольные точки.
7. Один ход — перемещение ровно на одну клетку вверх, вниз, влево или вправо.
8. Диагональные перемещения запрещены.
9. Нельзя выходить за границы поля.
10. Нельзя войти в клетку, которая сейчас исчезла (`cooldown > 0`).
11. Невалидный ввод ничего не меняет и не считается ходом.
12. Перед применением валидного хода движок запоминает клетку, с которой уходит игрок (`origin`).
13. Игрок перемещается на выбранную соседнюю активную клетку (`destination`).
14. После перемещения у всех клеток, которые были исчезнувшими до этого хода, `cooldown` уменьшается на 1.
15. Если после уменьшения `cooldown` становится `0`, клетка сразу возвращается и снова считается доступной.
16. После уменьшения старых cooldown клетке `origin` присваивается `cooldown = 3`; она исчезает.
17. Клетка, на которой находится игрок после хода, никогда не исчезает в этот же ход.
18. Если `destination` содержит ещё не посещённую контрольную точку, она отмечается как собранная.
19. Посещённая контрольная точка остаётся собранной навсегда, даже если её клетка позже временно исчезает.
20. Если игрок приходит на `B` до сбора всех контрольных точек, ничего особенного не происходит: `B` остаётся обычной активной клеткой, через неё можно пройти дальше.
21. Когда собрана последняя обязательная контрольная точка, `B` визуально переключается из состояния `locked` в `active`.
22. Если после хода игрок находится на активной `B` и все контрольные точки собраны, фиксируется победа.
23. Если победы нет, движок проверяет четыре ортогональных соседних клетки текущей позиции.
24. Если хотя бы одна из них находится внутри поля и имеет `cooldown = 0`, игра продолжается.
25. Если ни одной такой клетки нет, фиксируется поражение `no_moves`.
26. Никакие клетки не исчезают и не возвращаются по реальному времени; только после успешных игровых ходов.
27. Все последствия каждого действия полностью детерминированы текущим состоянием.

Пример таймера одной клетки:

```text
ход 1: покинул A  → A получает cooldown 3
ход 2: A недоступна → после хода cooldown 2
ход 3: A недоступна → после хода cooldown 1
ход 4: A недоступна → после хода cooldown 0, A возвращается
ход 5: в A уже можно войти
```

# 4. Состояние уровня

```ts
type PointId = 'A' | 'B' | 'X' | 'Y' | 'Z';

type Cell = {
  x: number;
  y: number;
  cooldown: 0 | 1 | 2 | 3;
  point: PointId | null;
};

type GameState = {
  grid: Cell[][];
  player: { x: number; y: number };
  requiredPoints: Array<'X' | 'Y' | 'Z'>;
  collectedPoints: Array<'X' | 'Y' | 'Z'>;
  moves: number;
  status: 'playing' | 'won' | 'failed';
  failReason: 'no_moves' | null;
};
```

Инварианты:

- Клетка под игроком всегда имеет `cooldown = 0`.
- `collectedPoints` не содержит повторов.
- `B` не обязана быть последней впервые посещённой клеткой; она лишь должна быть текущей позицией после сбора всех required points.
- В любой момент `cooldown` зависит только от истории валидных ходов, а не от таймера устройства.

# 5. Ввод

Основной игровой ввод:

```ts
{
  type: 'move';
  dir: 'up' | 'down' | 'left' | 'right';
}
```

На мобильном `move` создаётся свайпом по полю или экранными стрелками; оба UI-варианта передают в engine один и тот же тип события.

Правила обработки:

- `move` считается `first_action`, только если направление ведёт в валидную доступную клетку и состояние уровня реально изменилось.
- Ввод в состоянии `won` или `failed` игнорируется.
- Невалидное направление не двигает игрока, не уменьшает cooldown и не увеличивает `moves`.

# 6. Контент уровня

Пример `levels.json`:

```json
{
  "id": 1,
  "grid": { "w": 8, "h": 8 },
  "cooldownMoves": 3,
  "start": [1, 6],
  "exit": [6, 1],
  "checkpoints": {
    "X": [2, 2],
    "Y": [5, 5],
    "Z": [6, 6]
  }
}
```

Ограничения контента:

- Поле прототипа всегда 8×8.
- `cooldownMoves` во всех пяти тестовых уровнях равен `3`; варианты 2 и 4 не используются как прогрессия, чтобы не смешивать проверку core-механики с изменением базового правила.
- `A`, `B` и все checkpoint-клетки различны.
- На старте ни одна клетка не исчезла.
- Runtime RNG отсутствует.
- Для каждого уровня solver обязан подтвердить существование хотя бы одного маршрута победы.
- Solver должен учитывать точный cooldown каждой клетки на каждом шаге; обычного shortest path недостаточно.
- Уровень не принимается, если greedy-агент «иди к ближайшему checkpoint/B по текущему кратчайшему пути» стабильно решает его без развилки.
- Уровень не принимается, если оптимальный маршрут требует намеренно повторять длинную безопасную петлю только ради ожидания восстановления клетки более одного раза подряд: это признак затянутого контента, а не интересного решения.

Кривая по пяти уровням:

1. **Обучение следу.** Только `X` и `B`; обе точки расположены так, чтобы игрок увидел, что назад сразу вернуться нельзя, но ловушки нет.
2. **Первый выбор маршрута.** `X`, `Y`, `B`; порядок X/Y свободный, один из очевидных коротких маршрутов создаёт неудобный след.
3. **Первый настоящий выбор.** `X`, `Y`, `Z`, `B`; ближайшая точка не обязательно выгодна первой, потому что след перекрывает удобный выход к следующей.
4. **Давление краями поля.** Checkpoints расположены ближе к краям и углам; неверный вход в зону может оставить только клетки собственного свежего следа.
5. **Проверка концепта.** Несколько правдоподобных порядков X/Y/Z, минимум две развилки, где решение зависит именно от понимания трёхходового восстановления, а не от длины пути.

# 7. Визуал

- Поле: чистая квадратная сетка 8×8.
- Игрок: один хорошо читаемый маркер/фишка поверх клетки.
- `A`: стартовый маркер, после первого хода остаётся маленькой подписью на своей клетке.
- `X`, `Y`, `Z`: крупные буквенные маркеры; после посещения становятся отмеченными/приглушёнными, но остаются различимыми.
- `B`: видна с начала; до сбора всех checkpoint имеет состояние `locked`, после последнего checkpoint — коротко активируется.
- Активная обычная клетка: нейтральная плитка.
- Исчезающая клетка: быстро проваливается/сжимается и превращается в визуальный «провал».
- На исчезнувшей клетке обязательно показывать читаемый остаток cooldown: `3`, `2`, `1` либо три уменьшающихся сегмента. Игрок не должен запоминать таймер в уме.
- При `cooldown 1 → 0` клетка возвращается короткой pop-анимацией.
- Невалидный свайп в исчезнувшую клетку: лёгкий shake/отказ без изменения состояния.
- При сборе checkpoint: короткий payoff примерно 0.5–1 сек., затем маркер остаётся в состоянии `collected`.
- При сборе последнего checkpoint: `B` явно переключается в активное состояние.
- При победе: коротко подсветить весь пройденный порядок checkpoint и `B`.
- HUD: `X/Y/Z` как три маленьких индикатора собранности, номер уровня; отдельный счётчик ходов можно показывать для тестирования, но он не является лимитом.

# 8. Онбординг

1. `Свайпни, чтобы перейти на соседнюю клетку.`
2. `Клетка позади исчезает.`
3. `Она вернётся только после 3 следующих ходов.`
4. `Собери X, Y и Z в любом порядке.`
5. `После этого доберись до B.`
6. `Если сам отрежешь себе все выходы — уровень проигран.`

Кнопка `?` показывает только краткие правила из раздела 2; отдельный tutorial overlay после первого уровня не нужен.

# 9. Явно ВНЕ рамок

- Без меты, валют, коллекций, заданий, ежедневных бонусов, рекламы, IAP.
- Без runtime RNG.
- Максимум одно давление: временно исчезающие клетки собственного пути.
- Дополнительного твиста нет.
- Без лимита ходов.
- Без кнопки `wait` / пропуска хода.
- Без диагонального движения.
- Без телепортов, ключей, переключателей, движущихся стен и специальных типов клеток в пяти тестовых уровнях.
- Cooldown не меняется между уровнями: всегда 3.
- X/Y/Z не имеют обязательного порядка.
- Без изменений баланса/уровней после публикации; правки — только датированный критический баг.

# 10. Метрики и события

Шелл сам логирует `game_open`, `hub_impression`, `hub_click`, `teaser_click`, `help_open`, `more_yes`, `session_2`, `return_d1`, `return_d7` и общие поля (`game_id`, `anonymous_user_id`, `session_id`, `timestamp`, `source`, `version`).

Модуль механики вызывает:

- `first_action` — первый **валидный** `move`, который реально переместил игрока.
- `level_start` — при входе на уровень, с `level_id`.
- `level_win` — когда игрок находится на `B` после сбора всех обязательных checkpoint.
- `level_fail` — когда после хода нет ни одной доступной соседней клетки и победа не выполнена; `reason: 'no_moves'`.
- `retry` — при повторной попытке того же уровня после `level_fail`.
- `level_5_complete` отдельно не эмитить: shell фиксирует его автоматически через `level_win` пятого уровня.

Дополнительные mechanic-поля в событиях:

```ts
{
  moves: number;
  collected_count: number;
  required_count: number;
}
```

Для `level_fail` дополнительно:

```ts
{
  player_x: number;
  player_y: number;
  blocked_neighbors: number;
}
```

Внутренний тест концепта:

- Проверить completion rate уровней 1–5.
- Сравнить solver с greedy nearest-target агентом.
- Отдельно смотреть, на каком ходе игроки впервые пытаются вернуться на исчезнувшую клетку: это главный сигнал понятности core-правила.
- Если игроки массово воспринимают cooldown как таймер в секундах, визуал считается непонятным.
- Если greedy nearest-target проходит ≥80% тестовых уровней 3–5, концепт не даёт достаточного пространства решений и хоронится.

**Онлайн-ворота:** читаемость core-правила, доходимость до 5 уровня, возврат D1.

Если kill-критерий сработал — концепт хоронится, а не чинится дополнительными механиками.
